## 2. セレクタが実際に効いているか

### 2-1. 判定方法（重要）

**近似ではなく、実際のCSSセレクタ照合を行いました。**
`lxml` + `cssselect` で公開ページのHTMLをDOMとしてパースし、
各セレクタをXPathに変換して `document.querySelectorAll()` 相当の照合をしています。

- ただし `::before` / `::after` などの擬似要素、`:hover` などの動的擬似クラスは
  **取り除いてから**照合しています（要素の存在で判定）。
- `:has()` を含む2件のセレクタは `cssselect` が未対応のため照合不能。**判定不能＝残す**扱いです。
- 対象ページ: サイトマップから **32ページ**（各テンプレート種別を網羅）
  TOP / メニュー / 会社概要 / 代表あいさつ / ブログ一覧・記事・カテゴリ・タグ / 特集（エアコン他）/
  施工事例一覧・詳細 / お問い合わせ / お客様の声 / アクセス / コンセプト / 季節 / サイトマップ /
  プライバシーポリシー / その他事業 / 各サービスページ
- `/nenmatsu` は **401（パスワード保護）** のため取得できず、照合対象外です。

## 4. 危険な記述の検出

### 4-1. 素の要素セレクタ／広範な指定

- `*`、`html`、`a`、`p`、`div` 単体への指定は **ありません**（良い点）。
- 唯一の完全グローバル指定は先頭の1件:

```css
body {
  background: radial-gradient(…), linear-gradient(180deg,#f6f1eb,#f3efe9) !important;
  color: #202223 !important;
}
```

  `!important` 付きでサイト全体の背景色・文字色を固定しています。
  **今後どのページを追加してもこの色になります。**CMSのテーマ設定は無視されます。

- それ以外はすべて `body <パーツ>[data-lib=…]` か `body .-w-<CMSクラス>` で始まっています。
  ただし後者は**パーツ指定がないため全ページに効きます**。将来ページを追加したときに
  影響が出るのは次の27ルールです:

#### SEO・アクセシビリティ上の問題

1. **`98.8%` は HTML に存在しない文字列です。**

2. **SPではH相当の見出し文言がCSS側に移っています。**

   → **スクリーンリーダーはHTMLの元テキストを読み、目で見える文字とは語順が変わります。**
   「見えるテキストと読み上げテキストが一致しない」状態で、WCAGの観点で問題になり得ます。
3. **PCのロゴ横の `ONE HITTER / HOUSE CLEANING SERVICE` もHTMLに存在しません。**
   ロゴ画像の `alt="ワンヒッター株式会社"` は生きているので致命傷ではありませんが、
   本来はHTMLに書くべき文字列です。
4. **文字化けテキストがCSS内に4箇所残っています。**
   現在は上書きで表示されていませんが、上書き側を1行消しただけで
   **サイトに文字化けが露出します。**

### 5-2. 安全性の検証（これが一番重要です）

## 6. 人間（オーナー）が判断すべきこと

優先度順に挙げます。**いずれも本レポートでは実行していません。**

### 【最優先】1. base64画像を画像ファイルに移す（−204,870 B / −76%）

現状、PCのヒーロー背景画像がCSSに直接埋め込まれているため、
**全ページのHTMLが205KB重くなっています**（画像なのでキャッシュも効かない）。

- `hero-desktop.jpg`（153,628 B / 1448×1086）として書き出し済みです。
- これをCMSの画像リソースとしてアップロードし、CSSの
  `url('data:image/jpeg;base64,……')` を `url('/_img/…')` に置換するだけで、
  **CSSは268KB → 約63KB（−76%）になります。**
- 判断が必要な点: どのリソース枠にアップロードするか、ファイル名をどうするか。

### 2. SPヒーローのPexels直リンクをどうするか

- 第三者サーバー依存であり、先方が削除・仕様変更すれば**SPの背景が消えます**。
- そもそもPCとSPで写真が違います。**同じ画像に統一すべきか**の判断が必要です。
- ライセンス上、Pexelsは直リンクではなくダウンロードして自サーバーに置くことを想定しています。

### 3. 文字化けした `content:` 4箇所（906/922/967行 と 355行）

- 現在は他のルールに上書きされて画面には出ていませんが、CSSには残っています。
- **上書き側を1行消しただけで、サイトに文字化けが露出します。**
- 判断: 正しい日本語に直すか、まるごと削除するか。
  （本来の文言は第4-4章にデコード済みで記載しています）

### 4. `content:` によるテキスト差し込みをHTMLに戻すか

SEO・アクセシビリティの観点では、以下はHTMLに書くべき文字列です。

- PC: `ONE HITTER` / `HOUSE CLEANING SERVICE`（ロゴ横）
- PC/SP: `98.8%`（実績数値）
- SP: 見出しの分割表示（`あなたに` / `徹底的に・寄り添う・ハウスクリーニング`）

特にSPは `font-size:0; color:transparent` で**HTMLの見出しを消して**CSSのテキストに
差し替えているため、目で見える文言と読み上げ文言の語順が食い違っています。
CMSの見出し欄に改行入りで入力し直せば、CSS側の細工は不要になる可能性があります。

### 5. `.swiper-slide img { opacity: 0 }` は意図どおりか

CMSに登録したメインビジュアル画像2枚（ID 42925 / 43283）が完全に透明化されています。
- 意図的（CSS背景に置き換えた）なら、**CMS側でスライダー画像を外す**のが筋です。
  今は見えないのにダウンロードされており、表示速度の無駄になっています。
- 意図的でないなら、CSS背景の方をやめてCMSの画像を出すべきです。

### 6. スライダーの矢印・ドット非表示は意図どおりか

`display:none !important` で「前へ／次へ」矢印とページネーションを消しています。
スライドが2枚あるのに操作UIが無い状態です。自動送りだけで良いかの確認が必要です。

### 7. `-w-staff` 向けコードを本当に消してよいか

サイトのHTMLにもCMSのテーマCSSにも一切存在しないクラスです。
**「これから作る予定のページ用に先に書いた」ものでないか**だけご確認ください。
予定があるなら proposed.css の該当削除を戻してください（`dropped.json` に全件記録済み）。

### 8. 中期的には「CMS側の設定でできることはCSSでやらない」方針へ

- `!important` 437箇所のうち、色・フォント・余白の多くはCMSのデザイン設定で
  指定できるはずの項目です。
- 現状は管理画面から見た目を変えてもCSSに打ち消されるため、
  **今後の更新作業のたびにこのCSSを触る必要があります**。
- 7回分の上書きレイヤーが積み重なっているのが今の状態なので、
  ヒーロー部分だけでも一度「1レイヤーに統合」しておくと将来の事故が減ります。
  （proposed.css の適用は、その第一歩として安全に行えます）
