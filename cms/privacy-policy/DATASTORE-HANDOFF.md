# プライバシーポリシーは datastore で差し替えられます（ブラウザの貼り付けは不要）

調査 2026-09-13 ／ LP・サイト担当 ／ 依頼 `20260913-01-lp`

## 結論：**ページビルダーは要りません。**

本文は **規約管理のレコード `6/9` の `kv[body]`**（Joditのリッチテキスト欄）に入っています。
ふつうの datastore フォームがあるので、**HTTPのPOSTで差し替えられます。**

| | |
|---|---|
| 編集画面 | `https://one-hitter.jp/_sys/setting/rules/6/9/` |
| フォームの送信先 | 同じURL（POST） |
| `datastore[type]` | `setting/rules/detail` |
| `parent_id` / `id` | `6` / `9` |
| 本文の欄 | `kv[body]`（現在 4,684文字） |

> ## ⚠️ 以前の私の結論は誤りでした
> `cms/privacy-policy/HOW-TO-PASTE.md` に「ページビルダーのブロックなので
> `/_sys/` に編集フォームが無い」と書きましたが、**間違いです。**
>
> **`/_sys/setting/rules/6/` しか見ておらず、子レコードの `6/9/` を開いていませんでした。**
> 親（`6`）には `kv[name]` しかなく、本文は子（`9`）の `kv[body]` にあります。
> 公開ページ側が `data-instance="43063"` で囲まれていたので、
> ページビルダー専用だと早合点しました。
>
> **同じ形の取り違えは今回が2回目です**（アーティクル561で、`/561/1405/` が
> 空の新規フォームを返し、実レコードは `1406` だった）。
> **`/_sys/setting/<型>/<親>/edit/` は「新規作成」フォームで、`id` に
> 文字列 `edit` が入ります。** 本物は一覧から子レコードのIDを取ること。

## 送るもの

**`kv[body]` だけを差し替えます。** 公開日時（`pbd[date]` `pbd[h]` `pbd[i]` = 2024-10-23 17:15）
とメモは**現在の値のまま**送ってください。

| ファイル | 中身 |
|---|---|
| `rules-6-9-new-body.html` | **これを `kv[body]` に入れる**（5,933文字） |
| `rules-6-9-restore.html` | 差し替え前の値。**戻すときはこれを入れる**（4,684文字） |

## 検証済みのこと

- 差し替える範囲（`<p style="text-align: left;"><br><strong>1．…</p>`）が、
  **いま公開されているページにそのまま存在する**ことを確認（誰も触っていない）
- **見出し番号：変更前 1〜10 → 変更後 1〜12**、飛びなし
- タグの釣り合い：`<p>` 4組・`<strong>` 14組・`<span>` 1組・`<sub>` 2組、すべて一致
- 見出しと住所のブロック（先頭）と末尾の空段落は**1文字も変えていません**

## 手順（ブラウザでもHTTPでも同じ）

1. `/_sys/setting/rules/6/9/` を開く
2. **`id` が `9`、`parent_id` が `6` であることを必ず確かめる**
   （`edit` になっていたら新規作成フォームです。そのまま保存すると別レコードが増えます）
3. `kv[body]` を `rules-6-9-new-body.html` の中身で置き換える
4. 他の欄は触らずに保存

## なぜLP担当が実行していないか

**このスレッドの実行環境が、CMSへの書き込み操作を受け付けません。**
調査・検証・確認はできますが、保存のリクエストだけが拒否されます。
そのため**手順と中身を全部揃えてお渡しする形**にしています。
