# 帳票自動作成システム（ヒトカチ株式会社）

「適合性確認シート」と「意向把握シート」を、**1 画面の入力 → 送信** で PDF にして
Google ドライブの顧客フォルダに保存する Google Apps Script のウェブアプリ。

---

## できること

**1 件ずつ**（ウェブアプリ）と**まとめて**（一括入力シート）の 2 通りで作れる。

### 1 件ずつ

1. 募集人が 1 画面に入力して「内容を確認する」を押す
2. **適合性確認シートの「２．①〜⑥」は既定ですべて「はい」**。確認画面で個別に
   「いいえ」へ変えられる（適合性の確認は募集の場で済んでいる前提のため）
3. 「いいえ」にすると赤字で「変額保険は提案不可」を表示する
4. 保存先の顧客フォルダを確認する（既存フォルダに当たった場合のみ選択させる）
5. 2 つの PDF が代理店共有フォルダ配下の顧客フォルダに保存される
6. 入力内容・判定結果・保存先 URL が「送信ログ」シートに 1 行残る

### まとめて

設定スプレッドシートの「一括入力」シートに 1 行 1 顧客で書き、下見してから実行する。
件数が多くても自動で続きが走る。詳しくは[一括作成](#一括作成)。

### 入力しなくていいもの

| 帳票の欄 | どうやって埋まるか |
|---|---|
| 適合性 `年収×20%` `金融資産×30%` | 年収・金融資産から自動計算 |
| 適合性 `２．①〜⑥` の はい／いいえ | 既定ですべて「はい」。確認画面で変えられる |
| 適合性 `⑧ お客さまのご意向` | 意向把握シートの 8 項目から自動で集約 |
| 意向把握 `募集代理店` ブロック | 募集人マスタから自動で流し込み |
| 意向把握 `最終のご意向` | 空欄なら「当初のご意向」と同じ内容が入る |

### 「２．①〜⑥」の扱い

適合性の確認は募集の場で済んでいる前提なので、**帳票に印字するのは既定ですべて
「はい」**。法人契約では①〜③が自動的に「対象外」になる。

確認画面に 6 行が並び、必要なときだけ「いいえ」に切り替える。1 つでも「いいえ」に
すると総合が「不適合」になり、別紙どおり「他の定額保険を提案してください」と出る。

入力内容から別紙の基準で計算した結果は、**既定の「はい」と食い違うときだけ**、
その行に小さく理由を添える（例: 「入力からは「いいえ」です：年間保険料が年収の
20% を超え…」）。押しつけではなく気づきのための表示で、帳票には出ない。

> この計算に使う項目（年間保険料・保険料払込期間・職業区分など 10 項目）は
> 帳票に印字されない。廃止するかどうかは保留中（`docs/pending-decisions.md`）。

## セットアップ

### 1. Apps Script プロジェクトを作る

```bash
npm install -g @google/clasp
clasp login
clasp create --type webapp --title "帳票自動作成システム" --rootDir src
```

`.clasp.json` ができるので、`rootDir` と `fileExtension` を
`.clasp.json.example` に合わせる。

```bash
clasp push
```

> clasp を使わない場合は、[script.google.com](https://script.google.com/) で
> 新規プロジェクトを作り、`src/` 以下のファイルを同じ名前で貼り付けてもよい。
> `.gs` はスクリプトファイル、`.html` は HTML ファイルとして作る。

### 2. Drive API（詳細サービス）を有効にする

Apps Script エディタ左の「サービス」＋ →「Drive API」→ **バージョン v3** で追加。
（HTML を Google ドキュメントに変換するのに使う）

### 3. `setup()` を 1 回実行する

エディタで関数 `setup` を選んで実行。初回は権限の承認を求められる。
実行ログに出た URL が **設定スプレッドシート**。

### 4. 設定スプレッドシートを埋める

| シート | 入れるもの |
|---|---|
| `代理店マスタ` | 提携先ごとの **代理店名** と **共有フォルダID** |
| `募集人マスタ` | 氏名・メール・電話・住所（意向把握シートの下部に出る） |
| `利用者` | このシステムを使える Google アカウント |
| `項目設定` | 各項目を「入力する／固定値を使う／使わない」のどれで扱うか |
| `設定` | 画面タイトル、アクセス制限の有無 |

`setup()` は同時に、設定スプレッドシートに「帳票作成」メニューを出すための
トリガーも仕掛ける。メニューが出ないときは、いちどスプレッドシートを開き直す。

**共有フォルダID の調べ方**: Drive でフォルダを開いたときの URL
`https://drive.google.com/drive/folders/★ここ★` の部分。

### 5. ウェブアプリとしてデプロイ

「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」

| 項目 | 設定 |
|---|---|
| 次のユーザーとして実行 | **アクセスしているユーザー** |
| アクセスできるユーザー | **Google アカウントを持つ全員** |

「アクセスしているユーザー」にするのは、誰が作成したかをログに残すため。
そのぶん **募集人各自に、代理店共有フォルダの編集権限と、設定スプレッドシートの
編集権限を共有しておく必要がある**。

アクセスは URL を知っているだけでは通らない。`利用者` シートに載っている
アドレスだけが使える（`設定` シートの `アクセス制限` を `いいえ` にすると無効化できる）。

## 項目を出す・隠す・固定する

`項目設定` シートの `扱い` 列を選び直すだけで変えられる。コードは触らない。
プルダウンになっているので、直接打ち込む必要はない。

| 扱い | 挙動 |
|---|---|
| `入力する` | 入力フォームに欄を出す |
| `固定値を使う` | 欄を出さず、同じ行の `固定値` を毎回そのまま使う |
| `使わない` | この項目は使わない。帳票では空欄になる |

初期状態では、**検証欄・推定のご意向・最終のご意向・意向の変化** が `使わない`。
最小の入力で回すためで、必要になったら `入力する` に変えれば入力欄が生える。

見出しのセルにはマウスを乗せると説明が出る（Google スプレッドシートのメモ機能）。
`有効` `必須` の列はチェックボックスなので、チェックを外すだけで無効にできる。

> コードの中では `form` / `fixed` / `hidden` として扱っている。
> シート上の表記だけを日本語にしているので、英語表記で運用していた古いシートも
> そのまま読める（`setup()` を再実行すると日本語表記に書き換わる）。

`固定値` の書き方:

- チェック項目 … `はい` / `いいえ`（`TRUE` / `FALSE` でも可）
- 複数選択の項目 … `株式, 投資信託` のようにカンマ・読点・改行区切り
- それ以外 … そのまま文字列

## 保存先フォルダの決まり方

```
代理店共有フォルダ（代理店マスタで指定）
└── 顧客フォルダ（契約者氏名）
    ├── 適合性確認シート_種田 裕貴_20260801.pdf
    └── 意向把握シート_種田 裕貴_20260801.pdf
```

顧客フォルダは **原則として新規作成**するが、既に同じ顧客のフォルダがあれば
そこに保存できる。照合は表記ゆれを吸収したうえで行う。

| 揺れ | 例 | 扱い |
|---|---|---|
| 敬称 | `種田裕貴様` = `種田裕貴` | 同一 |
| 空白 | `種田 裕貴` = `種田　裕貴` = `種田裕貴` | 同一 |
| 旧字体 | `髙橋` = `高橋`、`尾﨑` = `尾崎` | 同一 |
| 全角英数 | `ＡＢＣ` = `abc` | 同一 |

**一致しても勝手には保存しない。** 必ず確認画面で「既存フォルダに保存」か
「新しく作成」かを選ばせる。同名の候補が複数あるときはどれに入れるかを選ばせる。
これで、フォルダの二重化と別人フォルダへの誤保存の両方を防ぐ。

異体字の対応表を増やしたいときは `src/DriveUtil.gs` の `NAME_VARIANTS` に足す。

## 一括作成

設定スプレッドシートの **「一括入力」シート** に 1 行 1 顧客で書いて、まとめて作る。
メニューは設定スプレッドシート上部の **「帳票作成」**。

### なぜ一括だと速いのか

成約一覧から持ってこられるのは契約者名くらいで、適合性確認シートが求める
年齢・年収・金融資産・投資経験などは面談で聞くものなので、結局そこは人が入れる。
それでも一括にする意味は 3 つある。

1. **生成の待ち時間がまとめて消える。** 1 件ずつだと「入力 → 30 秒待つ」の
   繰り返しで画面に張り付くことになる。一括なら入力だけ済ませて実行し、放置できる
2. **共通項目が 1 回で済む。** 代理店・募集人・確認日・契約形態はオートフィルで一括
3. **入力漏れが送信前に俯瞰できる**

副産物として、**これまで各担当者の頭の中にしかなかった適合性の情報が、
このシートに統一の記録として残る**。募集人の列でフィルタすれば、各自が自分の
担当分だけを埋められる。

### 手順

**0. 一括入力シートを準備する**（初回と、`項目設定` を変えたとき）

メニュー →「一括入力シートを準備する」。`項目設定` で「入力する」になっている
項目の列が自動で生成される。入力済みのデータは保ったまま列だけ作り直すので、
運用中に実行しても構わない。

**1. 書く**

- 契約者名は成約一覧からそのまま貼り付けられる
- 代理店・募集人・契約形態・確認日はプルダウン。1 行目を書いてオートフィル
- **保障ニーズ・購入経験・保険料原資は選択肢ごとにチェックボックス列**になっている。
  打ち込まずクリックだけで済み、行を見渡せば誰が何を選んだか一目で分かる
- 左の 3 列（状態・メッセージ・契約者氏名）は固定表示なので、右に
  スクロールしてもどの行を触っているか見失わない

**2.「① 保存先を下見する」**

Drive には何も書かず、検証・判定・保存先の解決だけを行う。各行に結果が入る。

| 状態 | 意味 | 行の色 |
|---|---|---|
| `下見OK` | 新しい顧客フォルダを作って保存する | 青 |
| `既存に保存` | **既存の顧客フォルダに入る。同姓同名の別人でないか確かめること** | 黄 |
| `要確認` | 同名とみなせる顧客フォルダが複数ある。別人の可能性 | 橙 |
| `エラー` | 必須項目の未入力など。メッセージに理由が入る | 赤 |

**黄色の行が、1 件ずつのときの確認画面にあたる。** ここで同姓同名を目視する。

既存フォルダへの保存は、**下見で一度画面に出した行だけ**が作成される。下見を
飛ばして②を押した場合、その行は作成されず `既存に保存` が付くだけで止まるので、
内容を確かめてからもう一度②を実行する。

**3.「② 未作成の行をすべて作成する」**

PDF を作って保存し、各行に PDF と保存先フォルダのリンクが入る。状態は `作成済`（緑）。
`作成済` の行は再実行しても飛ばされるので、重複作成の心配はない。

担当者が自分の分だけ流したいときは、行を選んで「選択した行だけ作成する」。

### 件数が多いとき

Apps Script は 1 回の実行が 6 分で切れる。1 件あたり 10〜15 秒かかるので、
単発では 20〜30 件が上限になる。

これに対して、**4 分半で自動的にいったん切り上げ、1 分後に続きを実行する**
仕組みを入れてある。進捗は状態列そのものなので取りこぼしは起きない。
実行後に「残り ◯ 件は 1 分後に自動で続きを実行します」と出たら、
**タブを閉じて放置してよい**。過去分をまとめて作るときはこれで流し切れる。

途中で止めたいときはメニューの「実行中の続きを取り消す」。

### 一括では扱わないもの

- **同名候補が複数ある行**。機械に別人かどうかを判断させないため、`要確認` にして
  飛ばす。1 件ずつのフォームで処理する
- **「２．」を「いいえ」にすること**。一括では確認画面を出せないので、回答は既定の
  すべて「はい」で固定される。下見のメッセージには、入力から計算した結果が
  「いいえ」の場合その旨が出るので、該当行は 1 件ずつのフォームで作り直す
- **ご意向の変化の内容等**。1 行 1 顧客の形に馴染まないので、必要な案件は
  フォーム側で作る

## 過去の帳票の記録（過去帳票台帳）

既に作成済みの帳票から起こした記録を、**参照専用の台帳**にまとめる。
`tools/build-archive.js` が TSV を作るので、設定スプレッドシートに
「過去帳票台帳」シートを作って貼り付ける。

```bash
node tools/build-archive.js
```

### なぜ一括入力シートに入れないのか

システムが帳票に印字する「２．①〜⑥」は、**既定ですべて「はい」**になる。
しかし過去の帳票には**当時の回答が記録されており、提出済みの書面として確定して
いる**。既定値で作り直すと、書面と食い違う内容が残る恐れがある。

そのため台帳は、帳票に書かれていた判定をそのまま転記する。年収×20% なども
計算し直さず、印字されていた値を写す。元ファイルへのリンクも残す。

**この台帳から帳票を再生成しないこと。**

### 一括入力シートとの使い分け

| | 一括入力シート | 過去帳票台帳 |
|---|---|---|
| 目的 | これから帳票を作る | 過去の帳票を記録・検索する |
| 「２．」 | 既定はすべて「はい」 | 当時の記録をそのまま写す |
| 書き込み | Drive に PDF を保存する | 何も保存しない |

### 意向の変化がある記録は一括で作らない

一括入力シートは「ご意向の変化の内容等」と「最終のご意向」を扱わない。
`tools/build-bulk-import.js` は該当する記録のメッセージ列に
**【一括では作成しないこと】** と入れる。1 件ずつのフォームで作ること。

## テスト

Apps Script にデプロイしなくても、判定ロジックと帳票のレイアウトは手元で確認できる。

```bash
npm test                    # 下の5つをまとめて実行

node test/logic.test.js     # 判定ロジック（別紙の計算例を含む）
node test/config.test.js    # 設定スプレッドシートの読み取り
node test/bulk.test.js      # 一括入力シートの列と行の変換
node test/import.test.js    # 過去データ取り込みの往復
node test/render.test.js    # 帳票テンプレートの描画

npm run preview             # test/out/ に HTML を書き出す
```

`--write` で出した HTML をブラウザで開くと、PDF になる前のレイアウトを確認できる。

### 触って確かめる

デプロイしなくても、入力から帳票の生成までをブラウザで一通り試せる。

```bash
npm run demo        # demo/index.html を組み立てる（ブラウザで開く）
```

入力画面・判定ロジック・帳票レイアウトは `src/` の実物をそのまま読み込んでいる。
Google のサービスを呼ぶ 3 か所だけを差し替えてあり、デモ用に作り直したものはない。

| 差し替えた箇所 | デモでの動き |
|---|---|
| `google.script.run` | 同じ関数をブラウザ内で実行する |
| 保存先フォルダの照合 | Drive を見ず、仮の顧客名で当たりを再現する（氏名の正規化は実物） |
| PDF 化と Drive 保存 | 保存せず、できあがる帳票を画面に出す |

`demo/` は生成物なので追跡していない。`src/` を直したら `npm run demo` で作り直す。

リポジトリから除外している。

### 帳票の作り方について

HTML を **Google ドキュメントに変換してから** PDF にしている。
Apps Script で HTML から直接 PDF にすると日本語が化けるが、Google ドキュメントを
一度はさめば確実に出る。レイアウトの定義がリポジトリ側の HTML に残るので、
Drive 上のテンプレートとコードがズレる事故も起きない。

レイアウトを直したいときは `src/*.html` を編集して `node test/render.test.js --write`
で確認してから `clasp push` する。

## 注意

- 帳票の様式は保険会社から配布されたもの。原本（`新契約部25.09（891947）`）が
  改訂されたら `src/SuitabilitySheet.html` を追随させること。
- 適合性の確認は、具体的なプランの提示よりも前に行う。確認日は原則として
  意向確認日や申込日よりも前の日付になる。
- 本書面は取扱者が適切に保管すること。**推奨保管期間 5 年**。
- 年収・金融資産などの個人情報を含むため、設定スプレッドシートと
  送信ログの共有範囲は必要最小限にすること。
