# 帳票自動作成システム（ヒトカチ株式会社）

「適合性確認シート」と「意向把握シート」を、**1 画面の入力 → 送信** で PDF にして
Google ドライブの顧客フォルダに保存する Google Apps Script のウェブアプリ。

---

## できること

1. 募集人が 1 画面に入力して「内容を確認する」を押す
2. **適合性確認シートの「２．①〜⑥」は自動判定される**（入力しない）
3. 不適合なら赤字で「変額保険は提案不可」を表示する
4. 保存先の顧客フォルダを確認する（既存フォルダに当たった場合のみ選択させる）
5. 2 つの PDF が代理店共有フォルダ配下の顧客フォルダに保存される
6. 入力内容・判定結果・保存先 URL が「送信ログ」シートに 1 行残る

### 入力しなくていいもの

| 帳票の欄 | どうやって埋まるか |
|---|---|
| 適合性 `年収×20%` `金融資産×30%` | 年収・金融資産から自動計算 |
| 適合性 `２．①〜⑥` の はい／いいえ | 別紙の基準にそって自動判定 |
| 適合性 `⑧ お客さまのご意向` | 意向把握シートの 8 項目から自動で集約 |
| 意向把握 `募集代理店` ブロック | 募集人マスタから自動で流し込み |
| 意向把握 `最終のご意向` | 空欄なら「当初のご意向」と同じ内容が入る |

`年間保険料` と `保険料払込期間` の 2 項目だけ余分に聞くが、そのぶん判定 6 項目が
消えるので、入力の総数はむしろ減る。この 2 項目は判定にだけ使い、帳票には出力しない。

## セットアップ

### 1. Apps Script プロジェクトを作る

```bash
npm install -g @google/clasp
clasp login
clasp create --type webapp --title "帳票自動作成システム" --rootDir src
```

`.clasp.json` ができるので、`rootDir` と `fileExtension` を
`.clasp.json.example` に合わせる。

```bash
clasp push
```

> clasp を使わない場合は、[script.google.com](https://script.google.com/) で
> 新規プロジェクトを作り、`src/` 以下のファイルを同じ名前で貼り付けてもよい。
> `.gs` はスクリプトファイル、`.html` は HTML ファイルとして作る。

### 2. Drive API（詳細サービス）を有効にする

Apps Script エディタ左の「サービス」＋ →「Drive API」→ **バージョン v3** で追加。
（HTML を Google ドキュメントに変換するのに使う）

### 3. `setup()` を 1 回実行する

エディタで関数 `setup` を選んで実行。初回は権限の承認を求められる。
実行ログに出た URL が **設定スプレッドシート**。

### 4. 設定スプレッドシートを埋める

| シート | 入れるもの |
|---|---|
| `代理店マスタ` | 提携先ごとの **代理店名** と **共有フォルダID** |
| `募集人マスタ` | 氏名・メール・電話・住所（意向把握シートの下部に出る） |
| `利用者` | このシステムを使える Google アカウント |
| `項目設定` | 各項目を `form` / `fixed` / `hidden` のどれで扱うか |
| `設定` | 画面タイトル、アクセス制限の有無 |

**共有フォルダID の調べ方**: Drive でフォルダを開いたときの URL
`https://drive.google.com/drive/folders/★ここ★` の部分。

### 5. ウェブアプリとしてデプロイ

「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」

| 項目 | 設定 |
|---|---|
| 次のユーザーとして実行 | **アクセスしているユーザー** |
| アクセスできるユーザー | **Google アカウントを持つ全員** |

「アクセスしているユーザー」にするのは、誰が作成したかをログに残すため。
そのぶん **募集人各自に、代理店共有フォルダの編集権限と、設定スプレッドシートの
編集権限を共有しておく必要がある**。

アクセスは URL を知っているだけでは通らない。`利用者` シートに載っている
アドレスだけが使える（`設定` シートの `アクセス制限` を `false` にすると無効化できる）。

## 項目を出す・隠す・固定する

`項目設定` シートの `モード` 列だけで変えられる。コードは触らない。

| モード | 挙動 |
|---|---|
| `form` | 入力フォームに表示する |
| `fixed` | フォームに出さず、同じ行の `固定値` を使う |
| `hidden` | 使わない。帳票では空欄になる |

初期状態では、**検証欄・推定のご意向・最終のご意向・意向の変化** が `hidden`。
最小の入力で回すためで、必要になったら `form` に変えれば入力欄が生える。

`固定値` の書き方:

- チェック項目 … `TRUE` / `FALSE`
- 複数選択の項目 … `株式, 投資信託` のようにカンマ・読点・改行区切り
- それ以外 … そのまま文字列

## 保存先フォルダの決まり方

```
代理店共有フォルダ（代理店マスタで指定）
└── 顧客フォルダ（契約者氏名）
    ├── 適合性確認シート_種田 裕貴_20260801.pdf
    └── 意向把握シート_種田 裕貴_20260801.pdf
```

顧客フォルダは **原則として新規作成**するが、既に同じ顧客のフォルダがあれば
そこに保存できる。照合は表記ゆれを吸収したうえで行う。

| 揺れ | 例 | 扱い |
|---|---|---|
| 敬称 | `種田裕貴様` = `種田裕貴` | 同一 |
| 空白 | `種田 裕貴` = `種田　裕貴` = `種田裕貴` | 同一 |
| 旧字体 | `髙橋` = `高橋`、`尾﨑` = `尾崎` | 同一 |
| 全角英数 | `ＡＢＣ` = `abc` | 同一 |

**一致しても勝手には保存しない。** 必ず確認画面で「既存フォルダに保存」か
「新しく作成」かを選ばせる。同名の候補が複数あるときはどれに入れるかを選ばせる。
これで、フォルダの二重化と別人フォルダへの誤保存の両方を防ぐ。

異体字の対応表を増やしたいときは `src/DriveUtil.gs` の `NAME_VARIANTS` に足す。

## テスト

Apps Script にデプロイしなくても、判定ロジックと帳票のレイアウトは手元で確認できる。

```bash
node test/logic.test.js     # 判定ロジック（別紙の計算例を含む）
node test/render.test.js    # 帳票テンプレートの描画
node test/render.test.js --write   # test/out/ に HTML を書き出す
```

`--write` で出した HTML をブラウザで開くと、PDF になる前のレイアウトを確認できる。

## ファイル構成

| パス | 内容 |
|---|---|
| `src/Fields.gs` | **入力項目の定義（唯一のマスタ）**。項目を足すならここ |
| `src/Judge.gs` | 適合性 2.①〜⑥ の判定ロジック |
| `src/Config.gs` | 設定スプレッドシートの読み書き |
| `src/DriveUtil.gs` | 氏名の正規化とフォルダ照合 |
| `src/Render.gs` | 差し込みモデルの組み立てと HTML→PDF 変換 |
| `src/SuitabilitySheet.html` | 適合性確認シートのレイアウト |
| `src/IntentSheet.html` | 意向把握シートのレイアウト |
| `src/Generate.gs` | 生成と保存の流れ |
| `src/LogSheet.gs` | 送信ログ |
| `src/WebApp.gs` | ウェブアプリの入口・アクセス制御 |
| `src/Form.html` | 入力画面 |
| `src/Setup.gs` | 初回セットアップ |
| `docs/field-mapping.md` | 入力項目と 2 帳票の対応表 |

### 帳票の作り方について

HTML を **Google ドキュメントに変換してから** PDF にしている。
Apps Script で HTML から直接 PDF にすると日本語が化けるが、Google ドキュメントを
一度はさめば確実に出る。レイアウトの定義がリポジトリ側の HTML に残るので、
Drive 上のテンプレートとコードがズレる事故も起きない。

レイアウトを直したいときは `src/*.html` を編集して `node test/render.test.js --write`
で確認してから `clasp push` する。

## 注意

- 帳票の様式は保険会社から配布されたもの。原本（`新契約部25.09（891947）`）が
  改訂されたら `src/SuitabilitySheet.html` を追随させること。
- 適合性の確認は、具体的なプランの提示よりも前に行う。確認日は原則として
  意向確認日や申込日よりも前の日付になる。
- 本書面は取扱者が適切に保管すること。**推奨保管期間 5 年**。
- 年収・金融資産などの個人情報を含むため、設定スプレッドシートと
  送信ログの共有範囲は必要最小限にすること。
