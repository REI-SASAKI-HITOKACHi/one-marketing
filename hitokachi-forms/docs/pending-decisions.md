## 1. 判定にしか使わない入力項目を廃止するか

**状態**: 決着（2026-09-04）。既定で「使わない」にした。

適合性の「２．①〜⑥」を自動判定から「既定はすべて はい・確認画面で変更可」に
変えたことで、次の 10 項目は**帳票に印字されず、判定の参考にしか使われなく
なった**。入力を減らして一括作成を現実的にするため、既定を「使わない」にした。

| 元の判定 | 項目 | フィールドキー |
|---|---|---|
| ① | 70歳以上の場合の募集方法 | `elderlyMethod` |
| ② | 職業区分 | `occupationClass` |
| ② | 世帯主・家族等の職業を確認した（チェック） | `householdConfirmed` |
| ③ | 年間保険料 | `annualPremium` |
| ③ | 保険料払込期間 | `payYears` |
| ④ | 投資経験がないため十分に説明した（チェック） | `experienceExplained` |
| ⑤ | ア．原資が満期金・解約返戻金ではない（チェック） | `sourceNotMaturity` |
| ⑤ | （満期金等の場合）不利益事項を説明した（チェック） | `sourceMaturityExplained` |
| ⑤ | イ．元本割れを許容できる余裕資金（チェック） | `sourceSpare` |
| ⑤ | ウ．借入金を前提としていない（チェック） | `sourceNotLoan` |

入力項目は 33 → 23 に減った。**コードを触らず、設定スプレッドシートの
「項目設定」で「入力する」に戻せる**。戻せば確認画面の参考判定も復活する。

### 参考判定はどうなるか

「使わない」にした項目を根拠にしている判定は、入力から確かめようがないので
参考判定を出さない（`Judge.gs` の `JUDGE_INPUTS` が対応表）。これをやらないと、
入力を減らした瞬間に「入力からは いいえ です」がほぼ全件に出てしまう。

入力が残っている判定（⑥のリスク選好とご意向）の参考判定は、これまでどおり出る。

### 引き換えに失うもの

過去 98 件の適合性確認シートを調べたところ、記録された判定に**「いいえ」は
1 件もなかった**。一方で、⑥保険料原資が「解約返戻金」なのに 2.⑥ア
「解約返戻金ではない」が「はい」になっている記録が 11 件あった。
**この種の食い違いは、今後は自動では検出できない。**
気になるようなら `sourceNotMaturity` だけ「入力する」に戻せば、⑤の参考判定が復活する。

## 2. 確認画面の「入力からは いいえ です」の注記を残すか

**状態**: 決着（上記 1 とセット）。残した。

既定はすべて「はい」だが、入力内容から計算した結果が「いいえ」になる場合に、
確認画面の該当行へ小さく理由を出している。押しつけではなく、気づきのための表示。

上記 1 で入力を減らしたので、注記が出るのは⑥だけになった。
注記そのものを消したい場合は `src/Form.html` の `renderConfirm` から
`advice` の描画を外す。
