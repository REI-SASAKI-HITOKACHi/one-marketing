## 9/19 にやったこと

### ⚠「マスタのTZが America/Los_Angeles」の原因を特定しました

**実データで割れました。推測ではありません。**同じ1件の見積を、2つのシートが16時間ちがう時刻で記録していました。

| どこ | `EST-20260507-0001` |
|---|---|
| 操作ログ（**マスタSS**） | `2026/05/07 **2:00:23**` |
| 見積データ（**テンプレートSS**） | `2026/05/07 **18:00:21**` |

JST 18:00 = LA 02:00（PDT）。ぴったり16時間。

- **マスタSS = LA** → **ずれているのは操作ログの時刻だけ**
- **テンプレートSS = Asia/Tokyo（正常）** → **見積・請求のデータも、PDFの日付も正しい**
- **採番は影響なし**。`generateDocumentId_` は `APP.TZ = 'Asia/Tokyo'` 決め打ちの `formatDate_` を通る

→ `adminSetMasterTimezone()` の実行を推奨（ログが正しくなるだけ／既存ログの見た目は変わらない／新形式の見積0件のいまが一番安い）。**実行はブラウザ担当の手。CMO中継で依頼中。**

### `run-all.sh` の Windows 誤検知を直しました（`297bfba`）

ブラウザ担当の手元で 12・13 が落ちた件。**コードではなくテスト側の環境依存**でした。
`python3` 決め打ち → `python3` / `python` / `py -3` を順に探す。`md5sum` → **改行をLFに揃えてから sha256** を取る `tools/hash-files.js`。
**テストスクリプトだけの変更。貼るコードは変わっていないので v6 の貼り直しは不要です。**
