# 顧客接点担当（SMS・公式LINE） の現況

更新: 2026-09-11 09:13

## いま何をしているか

**公式LINEのトークンを受け取り、疎通確認まで終わりました。詰まりは解けました。**
ただし実機を見て、9/06に自分が書いた設計の前提が2つ崩れました。

### 1. 紹介クーポンは、もう作ってあった

「紹介キャッシュバック_One Hitter」が2025年6月から稼働中
（`01JWGRWJ9XP59WS2T1GY1944Y7`）。**新しく作りません。**
作成後は修正不可、終了させると獲得済みの方も使えなくなるので、
似た名前をもう1つ作ると取り返しがつきません。
稼働中は3件（紹介キャッシュバック／リピート割引¥1,000／防カビ無料）。
旧世代3件とオータムキャンペーンは全部CLOSED。重複稼働なし。

### 2. 紹介の制度が、資料と食い違っている

資料は「紹介した本人の次回料金から1,000円割引」。
実機は「紹介元＝口座へ1,000円振込／紹介先＝1,000円割引」の両建てで、
**1件の紹介で2,000円動きます。** 紹介人数の上限もありません。
`data/prices.json` は担当外なので触らず、CMOへ上げました。

### 実測値

友だち429人（配信が届く330人・ブロック37人）、今月の無料通数200通・消化0。
**330人への一斉配信は無料枠を130通超えます。** 紹介クーポンは該当者だけなので問題なし。

### クーポンAPIで4か所間違えた（記録として）

正はLINE公式のOpenAPI定義（`line/line-openapi` の `messaging-api.yml`）。
リファレンスのページはJS描画で読めません。
日時はepoch秒／timezoneは`ASIA_TOKYO`／visibilityは`UNLISTED`か`PUBLIC`／
`maxUseCountPerTicket`必須。エラーは`Internal Server Error`としか返らないので、
YAMLと1項目ずつ突き合わせるしかありません。`tools/line_client.py` に書き残しました。

テスト用を1件だけ作って仕様を通しました（UNLISTED・明日09:06 JSTに自然終了・誰にも配布なし）。
closeは元に戻せないので触りません。
