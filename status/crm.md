# 顧客接点担当（SMS・公式LINE） の現況

更新: 2026-09-11 11:06

## いま何をしているか

**名乗りの照合を、SMSと公式LINEの両方に組み込みました。**（`claude/crm-sms-line` の `af218df`）
依頼 `20260911-01-crm` は完了にしました。

`tools/meigi_check.py` を作り、`derive-soushin-keitou.py` の `meigi_hyou()` を使って
**宛先と本文の両方**を見ます。宛先が合っていても本文に相手方のURLが1本混ざれば事故なので、
片方だけにしていません。

| 組み込んだ場所 | 挙動 |
|---|---|
| `sms_build.py --check` | テンプレートの本文を照合＋台帳が読めるかを確認 |
| `sms_build.py --csv ...` | **1行ずつ照合。台帳が読めないと終了コード2で止まる** |
| `line_client.py push` | お客様あては `--tel` か `--name` が必須。台帳＝本舗なら送らない |

**効き目：実データで送信可 60名 → 54名。6名が「台帳＝本舗／文面＝自社」で弾かれました。**
弾かれた6名は全員、最新施工が2023年でした。古い施工しか無い方ほど列と実態がずれています。

9/10 に僕が「本舗19名、確認する側に倒したい」と出した論点が事故になりました。
**列を信じた設計にしていたのは、こちらの落ち度でもあります。**

あわせて、ドキュメントの使用例に実在のお客様の氏名が入っていたので架空の名前に差し替えました。

## CMOへ伝えた気づき（そちらの判断で）

- `derive-soushin-keitou.py` は **import した時点で認証が走る**ので、認証の無い環境では
  import で落ちます。こちらは包んで「落とさず可否を返す」形にしました
- 控えの寿命が12時間なので、**同じ日に2回動かすと台帳の読み直しが走りません。**
  送信直前は `--saidoku` を付けたほうが安全です
