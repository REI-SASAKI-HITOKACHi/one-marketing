# 検討メモ：作業報告書の型を見積アプリに載せられるか（2026-10-29）

依頼：urakata の提案 #3「作業報告書の型（作業前の状態・写真4枚以上・試運転・次回の目安）」。条件：**和真さんの入力を増やさない**。

## 結論（先に）
**載せられる。ただし「写真」以外の3項目は、和真さんの入力ゼロでできる。写真だけが、入力（アップロード）を増やすか、載せない（リンクだけ）かの選択になる。**
推奨：**第1段階として、写真は載せずに「報告書PDF」だけ自動で作る**（約1日＋レビュー）。写真は、現状の送り方（LINE等）を教えてもらってから決める。

## 今のアプリの状態
- 作るのは **見積書と請求書だけ**（帳票スプレッドシートの雛形に差し込み → PDF → Gmail下書き）。作業報告書は無い。
- **写真を扱う仕組みは無い**（アップロード欄も保存先も無い）。
- 請求書の様式は固定（オーナー指示 9/18）。報告書は**別の書類**として足せば、請求書・見積書には触れない。通常見積の金額も変わらない。

## 4項目ごとの載せ方
| 項目 | 載せ方 | 和真さんの入力 |
|---|---|---|
| **試運転** | メニューごとの決まり文（例：エアコン「試運転を行い、冷暖房の動作を確認しました」）を**自動で入れる**。やっていないときだけ外す（既定＝入れる） | **ゼロ**（外すときだけ1タップ） |
| **次回の目安** | メニューマスタに「次回の目安」の列を足し（例：エアコン＝1〜2年、洗濯機＝1年）、**施工日＋目安**から自動で書く。文言と年数は CMO／オーナーが決める | **ゼロ** |
| **作業前の状態** | **3択をタップ**（通常／汚れ多め／要相談）。既定＝通常で、触らなければ「通常」と書く。自由記述は任意（空欄可） | **ゼロ〜1タップ** |
| **写真4枚以上** | 下の「写真の選択肢」 | 選択肢による |

## 写真の選択肢（ここだけ決める）
| 案 | 中身 | 入力 | 工数・リスク |
|---|---|---|---|
| **A（推奨）：報告書に載せず、置き場のリンクだけ** | 見積ごとに Drive フォルダを自動で作り、報告書に「写真はこちら」のリンクを載せる。和真さんはスマホの写真を**共有 → そのフォルダ**に入れる（いまLINEに送っているなら、送り先が変わるだけ）。PDF作成時に**枚数を数えて、4枚未満なら警告**（止めない） | 送り先が変わる（新しい作業は増やさない形にできる） | 小。Drive のフォルダ共有の設定（お客様の自宅写真なので、閲覧は関係者だけ）が要る |
| B：アプリの画面から写真をアップロードして、PDFに貼る | 画面に写真欄を足す | **増える**（毎回4枚以上選ぶ） | 大。GAS は大きな画像の送信に弱く（1枚数MB×4枚）、スマホの通信で落ちやすい。PDFへの貼り込みも要作成。**今回は勧めない** |
| C：写真は載せない | 3項目だけの報告書 | ゼロ | 最小。「写真4枚以上」は守れない |

## 作り方・工数（第1段階：写真なし／A の枚数チェック付き）
1. 帳票スプレッドシートに「作業報告書」の雛形タブを足す（既存の差し込みセル定義と同じ方式）
2. 請求書の作成画面から**報告書PDFもいっしょに作る**（同じデータ＝施工日・メニュー・お客様名を再利用。新しい入力欄は「作業前の状態」の3択だけ）
3. メニューマスタに「次回の目安」「試運転の文言」の列を足す（列名で読む。列番号は固定しない）
4. テスト＋独立レビュー。**約1日**。写真の枚数チェックを付けるなら +0.5日
- 出す先：Gmail は**下書きのみ**（即送信しない）。PDF・下書きを止める条件は付けない。

## 決めてほしいこと（私からの質問は3つ）
1. **写真を、いまどうやって集めているか**（LINEに送る／Googleフォト／お客様に見せる分だけ撮る…）。A か C かが決まる
2. **「次回の目安」と「試運転」の文面**と、メニューごとの年数（CMO／オーナー）
3. **報告書をお客様に渡すか**（請求書と同封／要望があったときだけ）。渡すなら見た目の確認が要る
