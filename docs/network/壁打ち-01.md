# 壁打ち 01：構想 v1 の穴と、埋め方の案（2026-09-21）

- 対象：`docs/network/構想整理.md` v1
- 書き方：**穴 → なぜ穴か → 埋め方の案 → 決めるのは誰か**。番号は構想整理の章に対応させる（K-2-3 は 2-3 への指摘）
- 私の立場：反対ではない。構想の骨（対等・透明・権利はうち）は筋が通っている。**骨を守るために、肉の付け方で事故になる箇所を先に潰す**
- 確度：法律は「確認が要る」と書く。断定はしない。断定調で書いてあるものは、社内の既知の数字（CMOセーブデータ）か構想そのものの論理矛盾だけ

## A. 思想レベルの穴（先に決めないと下が全部ぶれる）

### K-2-3 ／ K-6-6-d 「完全に透明」と「裏でコントロール」は同時に成り立たない

- **穴**：2-4 で「完全な透明化」を売りにしながら、6-6-d で「足切りの操作はオーナーが裏で」としている。相手は同業者で、勘が鋭い。裏で動かしているのが1回でも見えたら「結局、本舗と同じで上がいる」になり、1-2-b（対等）の看板が折れる。**この構想の資産は信用そのもの**なので、ここが一番高い崖
- **埋め方**：コントロールを**やめる**のではなく、**表に出す**。「除外基準」を最初から明文化して全員が見られる場所に置く。例：
  - 3か月で元請け評価が平均○以下、または再訪問（やり直し）が○件で「受注停止」
  - 停止・復帰は自動判定。判定ログは本人が見られる
  - 運営（ワンヒッター）が手で介入する権限は「緊急停止」1つだけ、と規約に書く。介入したら理由を全員に通知
- **相手にはこう見える**：「うちは権利を持つが、権限は限定して公開している」。これは石田君のような影響力のある人にとって、参加の安心材料になる
- **決めるのは**：オーナー。運営の権限リストを決める（案は B-1 に）

### K-2-3 「権利はうち」を、参加者に納得してもらう理屈がまだ無い

- **穴**：「システムの権利はワンヒッターに帰属」は、参加者から見れば「ルール変更・利用料・データの持ち出し」を一方的にされる不安。対等と言いながら権利は片側、を飲んでもらう説明が構想の中にまだ無い
- **埋め方**：権利と権限を分ける
  - **権利**（うちが持つ）：システムの所有・開発・運営主体・ブランド商標
  - **権限**（投票で決める）：手数料率・利用料の額・除外基準の数値・単価ガイドの更新
  - **保証**（規約で約束）：自分の取引データは自分でいつでもエクスポートできる／利用料の値上げは○か月前告知／退会自由
  - 「うちが持つのは**ハンドルを握る責任**で、**進む方向はみんなで決める**」という言い方が使える
- **決めるのは**：オーナー（プレゼンの核になるので早めに）

### K-1-1 ／ K-1-2 ／ K-1-3 三つの狙いは時間軸が違う。ひとつの箱に入れるとデモがぼやける

- **穴**：1-1（今すぐ・自社の外注）、1-2（中期・組合ブランドで集客）、1-3（将来・全国）は求める機能が違う。9/26 に全部を見せようとすると散る
- **埋め方**：段階を名前で切る
  - **第1段（〜2026年内）「協力店の受発注板」**：この地域、知り合い、案件を出す・受ける・金額が見える。1-1 だけ
  - **第2段（会員が○社を超えたら）「組合ブランド」**：バッジ・共通の名乗り・集客ページ。1-2
  - **第3段「全国」**：政令指定都市。1-3
  - デモと資料は第1段だけを厚く、第2・第3は「絵」1枚ずつ
- **決めるのは**：オーナー。私の推しは上記

## B. 仕組みの穴

### B-1（K-3-4 ／ K-3-5 ／ K-4-2）「投票で単価を決める」「最低単価は自分で決める」「率か固定か」は、いま3つが噛み合っていない

- **穴**：
  - 3-4 で「単価の上げ下げを投票」、3-5 で「最低単価は各自で決める」。**何を投票で決めるのか**が二重になっている
  - 稼働回数＝票数だと、**票を持つのは受け手（施工側）ばかり**になる。発注側の意見が入らない。施工側が単価を上げる方に投票し続ける構造になる
  - **同業者が集まって受注単価を投票で決めるのは、外から見ると価格協定に見える**（独占禁止法の「不当な取引制限」）。元請けと下請けの1対1の値決めは問題にならないが、参加者全員で単価を決めるのは形が違う。ここは 5-3 のリーガルチェックの論点に**必ず**入れる
- **埋め方（私の推し＝「率は決めない。金額を全部見せる」）**：
  1. 発注者は案件を出すとき、**お客様への請求額**と**施工者に払う額**の両方を書く。システムが差額と割合を自動で表示する（2-4 の透明性はこれで担保）
  2. 施工者は自分の**最低受け額**を登録しておく（3-5）。それ未満の案件は自分には表示されない、または「下限未満」と出る
  3. **投票で決めるのは価格ではなく運営ルール**：システム利用料の額、除外基準の数値、運営の権限、「相場の目安表」を出すか出さないか
  4. 「相場の目安」は**投票で決めるのではなく、実績の中央値を自動表示**する（先月このシステムで成立したエアコンノーマルの施工額の中央値：○円）。これなら価格協定でなく情報開示
  5. 票の重み：稼働回数（受けた数）**と発注回数の合計**にする。発注側も票を持つ
- **決めるのは**：オーナー。4-2 の「率か固定か」はこの案だと**どちらでもない**（率を決めない）になる

### B-2（K-4-1 ／ K-4-3-d）ワンヒッターの取り分が2種類あって、混ざるとロイヤリティに見える

- **穴**：「うちに2,000円以上バックが入る」（4-3-d）は、うちが**元請けとして**取る差額。一方 4-1 の利用料はうちが**運営者として**取る額。参加者から見ると両方「ワンヒッターに流れる金」で、ここが不透明だと 2-2（ロイヤリティ無し）を疑われる
- **埋め方**：
  - 元請けの差額は**誰が元請けでも同じルール**（誰でも自分が元請けなら差額を取れる）。うちだけ特別ではないことを見せる
  - 運営の取り分は**利用料だけ**、取引額に比例する手数料は取らない、と規約に書く。取るなら「サーバー実費」の明示
  - 4-3-d の「初期はテストでいい」は、**テスト期間の終わりを先に決める**（例：2026年内、または成立20件まで）。終わりが無いテストは既得権に見える
- **決めるのは**：オーナー

### B-3（K-2-4 ／ K-3-3）「登録者全員に見積を開示」は、金額は良いが個人情報は出せない

- **穴**：見積には氏名・住所・電話が付いている。全員に見せると個人情報保護法上の第三者提供になる。また同じ地域の同業者に自分の顧客リストが見える状態は、参加をためらう最大の理由になる
- **埋め方**：開示の3層
  - **全員**：金額・メニュー・地域（区市まで）・日程・成立したか
  - **受け手候補**：上に加えて作業条件（駐車・台数・階数）
  - **成立した相手だけ**：氏名・住所・電話・連絡事項
  - 規約に「システム上の顧客情報は当該案件の施工にのみ使う。自社の営業に使わない」を入れる（B-5 とセット）
- **決めるのは**：オーナー（原則はこれで良いはず。細部は私が設計）

### B-4（K-3-2）カレンダー連動は「誰も更新しない」で死ぬ

- **穴**：同業者が別のカレンダーを毎日更新することは期待できない。空き情報が古いと「空いてると出てたのに断られた」で信用が落ちる
- **埋め方**：
  - 入力は**「受けられる日を丸するだけ」**の最小形。時間帯は午前・午後・終日の3択
  - Googleカレンダーを使っている人は読み取り連携（任意）
  - 更新が○日止まったら一覧から薄く表示（古い情報を新しく見せない）
  - **案件側から探す**を主にする：案件を出すと、条件に合う人に通知が飛び、**先に手を挙げた人が受ける**。これなら空き表を常に埋めなくても回る
- **決めるのは**：私（設計）。オーナーは「手挙げ方式でよいか」だけ

### B-5（K-3-6）現場での「名乗り」と「顧客の引き抜き」

- **穴**：下請けが現場で自社の名刺を渡せば、元請けは次回を失う。バッジ・首かけカードは「誰の現場か」を示す道具のはずだが、構想ではまだ「識別」としか書かれていない
- **埋め方**：
  - **現場では元請けの名前で名乗る**。首かけカードに「○○（元請け）協力店」と表示。自社名刺は渡さない
  - 次回の依頼がお客様から施工者に直接来たら、**元請けに戻す**か**紹介料を払う**（既にある「事業者→顧客 紹介手数料 原則12%」を流用できる）
  - 違反は除外基準（A の K-6-6-d）に入れる
- **決めるのは**：オーナー（紹介料の扱い）

### B-6（K-3 全体）事故と責任の取り決めが無い

- **穴**：エアコン洗浄の基板故障、水漏れ、床の傷。誰が謝り、誰が払うか。ここが決まっていないと、最初の事故で網が壊れる
- **埋め方**：
  - 参加条件に**賠償責任保険の加入**を入れる（証券番号をシステムに登録）
  - 一次対応は元請け（お客様の窓口）、費用は施工者、保険で賄う。規約に明記
  - やり直し訪問は施工者の負担。これを B-1 の除外基準の指標（再訪問回数）に使う
- **決めるのは**：オーナー（保険を必須条件にするか）

### B-7（K-5 全体）法律で確認が要る点は、競業禁止だけではない

- **穴**：5 章は本舗の競業禁止だけを見ている。他にも確認が要る
  1. **本舗の契約書そのもの**：「下請けなら競業でない」は契約の条文次第。石田君も本舗加盟店なので、**石田君自身がこの網に参加できるか**がまず問題。本舗の顧客・見積・ノウハウを網に持ち込むのは別の条項に当たる可能性
  2. **価格協定**（B-1）
  3. **下請けの代金支払ルール**：2026年1月から下請法が改正・改称されている（「中小受託取引適正化法」と呼ばれる）。資本金・従業員数の規模で適用が決まるので、小規模同士なら対象外の場合が多いが、支払期日の明記など**適用の有無を確認**
  4. **インボイス**：施工者が免税事業者（登録番号なし）だと、元請けは仕入税額控除が満額取れない。経過措置は 2026年9月末で80%→50%に下がる（2029年9月まで）。**5,000円の施工費は、相手が免税事業者だと元請けの実質負担が変わる**。参加登録時に登録番号の有無を持たせ、金額表示にも反映
  5. **個人情報**（B-3）
  6. **反社チェック・古物などは不要**だが、参加規約と利用規約は必要。ひな型は私が起こせる
- **埋め方**：リーガルチェックの「質問票」を私が作る。オーナーは誰に見せるかを決める（顧問がいなければ、まず日本政策金融公庫や商工会議所の無料相談でも一次回答は取れる）
- **決めるのは**：オーナー（誰に聞くか）

### B-8（K-6-4）「アンパンマンプロジェクト」は競合ではなく前身として使える。ただし不透明さを引き継がない

- **穴**：既にあるグループLINEが「声かけはできるが不透明」なら、それがまさに今回の構想が解く問題。ただしそのグループの主宰者から見れば、**自分の場を横取りされる**と感じる可能性がある
- **埋め方**：石田君に、そのグループの主宰者との関係を先に聞く。取り込むなら「LINEでの声かけはこれまで通り、金額と成立の記録だけシステムで」と、置き換えではなく**記録の追加**として入る
- **決めるのは**：オーナー（9/26 に石田君へ聞く項目に入れる）

### B-9（K-7 ／ K-1-3）「この地域の知り合い」で成り立つ信用は、地方に運べない

- **穴**：第1段は顔見知りで回る。地方は誰も知らない。除外基準（A）と保険（B-6）と評価の見える化が、**顔の代わり**になっていないと地方には広げられない
- **埋め方**：第1段のうちに、「知らない人でも受け入れられる条件」（保険・登録番号・元請け評価○件以上）を作って運用実績を持つ。地方の最初の会員は**既存会員の紹介制**にする
- **決めるのは**：いまは決めなくてよい（第3段）

### B-10（K-1-1）冷たいスタート問題は、実は解けている。ただし「うちが最大の発注者」であることを隠さない

- **穴ではなく確認**：受発注の網は「案件が無いと人が来ない、人が居ないと案件を出せない」で止まりやすい。この構想は**最初の発注者がうち**（大型案件の外注）なので出だしは回る。CMOセーブデータの数字では、うちの稼働率はピーク65%・通常20〜50%で、**制約は需要側**。つまり第1段の初期は「うちが出す」より「**うちが受ける**」側にも回れる
- **注意**：運営者＝最大の発注者、は利益相反に見える。「うちの案件もみんなと同じルールで出す。優先権は無い」を規約に書く
- **決めるのは**：オーナー（同意だけ）

## C. 9/26 に向けての穴（段取り）

### C-1 5日しかない。デモの範囲を今日切る

- デモに**要る**：会員一覧 ／ 案件を出す（請求額・施工額・差額%が見える） ／ 手を挙げる ／ 成立 ／ 成立後だけ顧客情報が見える ／ 相場の中央値表示（ダミーデータ）
- デモに**要らない**：投票・カレンダー連携・バッジ・地方・利用料の決済
- 技術：この会社の既存の作り（Netlify の静的ページ＋Google Apps Script のAPI＋スプレッドシート）で組める。予約フォームと同じ構成なので、**運用中のものと同じ壊れ方しかしない**。本番用は会員が増えた時点で作り直す前提で、デモはこの構成で行く

### C-2 石田君向けの資料は「うちの構想」ではなく「石田君の得」で書く

- 石田君の立場：先輩・本舗加盟店主・影響力がある・声が大きい
- 石田君の得：①受け切れない案件を捨てずに済む ②手が空いた日に受けられる ③本舗の看板を汚さずに（名乗りルール）自社を回せる ④ルールを一緒に決める側に立てる（初期メンバーの権限）
- 石田君の不安：①本舗との競業 ②自分の顧客が見られる ③ワンヒッターの下に付く形にならないか
- 資料はこの3つの不安に**先に答える**構成にする。A と B-3 と B-5 がそのまま答えになる

### C-3 「デモを見せてからルール決め」の順は正しい。ただし**ルールの叩き台は持って行く**

- 白紙で「どうしますか」と聞くと、声の大きい人の案がそのまま通る。叩き台があれば、直す形で対等に決められる
- 叩き台＝この文書の A と B の「埋め方」。9/26 までに1枚にまとめる
