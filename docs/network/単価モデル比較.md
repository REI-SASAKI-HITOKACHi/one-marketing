- 作成：2026-09-21（壁打ち B-1 / 構想整理 3-4・3-5・4-2 の続き）
- 金額の出典：`data/prices.json`（税込）。所要時間も同ファイル。移動は60分/件（CMOセーブデータの稼働率計算と同じ前提）
- 比較対象の手数料：マッチングPF 35%（`docs/流入経路の分析.md` 実測）／くらしのマーケット 20%（`docs/ポータル露出調査.md`）／おそうじ本舗ロイヤリティ 27.6%／事業者紹介料 原則12%（CMOセーブデータ）

## 0. 言葉の定義

| 用語 | 意味 |
|---|---|
| **請求額** | お客様が払う税込額 |
| **元請け手取り** | 請求額から、外部の手数料（マッチングPFの35%など）を引いた額。**率はここに掛ける**（請求額に掛けると、PF案件で元請けが赤字になる。表1⑥） |
| **率モデル** | 施工者の受取＝元請け手取り × X%。Xは網で1つ |
| **固定モデル（季節変動型）** | 施工者の受取＝メニューごとの定額。通常／繁忙（5〜7月・12月）／閑散（1〜2月）で額を変える |
| **固定A** | 5,000円一律（MTGで出た「最低もらえてよい金額」をそのまま定額にした場合） |
| **固定B** | 60%相当から丸めた季節変動型。エアコン通常 6,500／繁忙 8,500／閑散 5,500 |
| **ハイブリッド（提示型）** | 率も固定も網では決めない。発注者が案件ごとに施工額を提示し、システムが率を自動表示。施工者は自分の最低受け額を登録（3-5） |

## 1. メリット・デメリット

### 1-1. 率モデル

| 観点 | メリット | デメリット |
|---|---|---|
| 透明性 | 「請求額の何%」が一目で分かる。構想 2-4 の「この何%だからいくら」と同じ言葉 | 率を成立させるには**請求額を必ず見せる**必要がある（構想はそのつもりなので問題なし） |
| 季節・割引への追従 | 繁忙期加算・閑散期割引・複数台割引に**自動で追従**。ルール表が要らない | 閑散期は施工者の受取も下がる（表1③）。ただし閑散期は施工者も暇なので市場の理屈には合う |
| オプション売り | 現場で防カビ（3,630円）を売れば施工者の受取も増える（表1④）。**クロスセルの動機が施工者側に生まれる**。CMOセーブデータの「エアコンのみ621名 × 差5万円＝約3,100万円の潜在」に直結 | 現場で無理な売り込みが起きる可能性。評価とクレーム基準で抑える |
| 大型・法人・空室 | 値引きの大きい案件でも比率は同じなので**計算が1本**で済む | 値引きが深い案件は施工者の受取が薄くなる。3-5 の最低受け額で自衛できる |
| 低価格チャネル | くらし相場7,000円の案件でも元請けは赤字にならない（表1⑦） | 施工者の受取は3,360円（60%）。受けるかは施工者が決める＝**最低受け額とセットでないと成り立たない** |
| 地方展開 | 地方の相場が違っても率は共通で使える | — |
| 公平感 | 元請けが高く売れば施工者も増える。「一緒に売る」関係 | 同じ作業で受取が違う（元請けの売り方次第）。「同じエアコンなのに」と感じる人はいる |
| 計算 | 単純。1つの数字 | 「率60%」の妥当性を全員に説明する必要がある |
| 法務 | — | **競争関係にある元請け同士が「下請け価格は請求額の○%」を共同で決める形**。価格協定と見られないかリーガルチェックが必須（壁打ち B-7） |

### 1-2. 固定モデル（季節変動型）

| 観点 | メリット | デメリット |
|---|---|---|
| 透明性 | 「エアコン1台＝○円」と即答できる。**現場の人には一番分かりやすい** | 請求額を見せなくても成立するので、**「完全な透明化」を選ばなくても済んでしまう**。構想 2-4 と噛み合いにくい |
| 季節 | 繁忙／閑散の額を先に決めれば、施工者は月ごとの見通しが立つ | **表を維持する手間**。メニュー数（12本）×季節（3）×オプション。価格改定のたびに投票が要る |
| オプション売り | — | 施工者が現場で防カビを売っても受取は変わらない（表1④で施工者は6,500のまま、元請けの取り分が55%に跳ねる）。**売る動機が施工者に無い** |
| 大型・法人・空室 | — | 法人は台数割引が深い（業務用は1台5,000円引きなど）。定額のままだと**元請けが赤字**、法人向けの別表を作ると表が増える |
| 低価格チャネル | — | くらし相場7,000円で固定B 6,500だと**元請けが900円の赤字**（表1⑦）。低価格で売る元請けは網を使えない、または請求額を偽る動機が出る |
| 地方展開 | — | 地方の相場に合わせた別表が要る |
| 公平感 | 同じ作業なら誰でも同じ受取。「対等」と相性がよい | 元請けが高く売った分は全部元請けのもの。水まわり3点だと元請け60%（表1⑤）。**施工者から見ると「元請けが取りすぎ」に見える案件が出る** |
| 計算 | 案件ごとの計算は不要 | 表の管理と改定の投票が重い |
| 法務 | — | **同業者が集まって施工単価の表を共同で決める形**。率よりも価格協定に見えやすい（「単価表」そのもの）。リーガルチェック必須 |

### 1-3. 一覧

| | 率 | 固定（季節変動） | ハイブリッド（提示型） |
|---|---|---|---|
| 透明性（2-4）との相性 | ◎ 請求額を見せることが前提 | △ 見せなくても成立 | ◎ 請求額・施工額・率を全部表示 |
| 季節・割引への追従 | ◎ 自動 | △ 表の維持 | ◎ 発注者が案件ごとに判断 |
| 施工者がオプションを売る動機 | ◎ | × | ○ 発注者が「オプションは施工者に○%」と書けば◎ |
| 法人・空室・大型 | ○ | × 別表 | ◎ |
| 低価格チャネルの元請け | ○ 赤字にならない | × 赤字 | ◎ |
| 地方 | ◎ | × 別表 | ◎ |
| 現場の分かりやすさ | ○ | ◎ | ○ 額はその場で見える |
| 「対等」の見え方 | ○ | ◎ 同一作業＝同一額 | ○ 相場の中央値を並べて見せれば◎ |
| 運営の手間 | 小 | 大 | 小（表示だけ） |
| 価格協定のリスク | 中（率の共同決定） | 高（単価表の共同決定） | **低**（値決めは1対1。網は表示のみ） |
| 投票で決めること | 率 | 単価表 | 運営ルールだけ |

### 2-1. 表から読めること

1. **固定A（5,000一律）は、元請けの取り分が54%になる。** マッチングPF（35%）より多く取る形になり、施工者から見て「くらしより悪い」になる。MTGで「うちに2,000円以上バックが入る」と言っていたのは、この差（5,780円 − PF相当の3,773円 ≒ 2,000円）と一致する
2. **率60%と固定B（6,500）は、エアコン通常月ではほぼ同じ**（施工者 6,468 vs 6,500）。違いが出るのは、オプション（④）・複数点（⑤）・低価格チャネル（⑦）・繁忙期（②）
3. **固定は「売れた案件ほど元請けが取りすぎに見える」**（⑤で60%、⑥で63%）。**率は「安く売った案件ほど施工者が薄い」**（⑦で3,360円）。どちらも極端な案件で不満が出るが、率の側は 3-5（最低受け額）で施工者が自衛できる。固定の側は元請けに自衛手段がない（赤字案件は出せない＝網に流れない）
4. **施工者の時給換算は、率60%でエアコン1台 3,234円／h、水まわり3点 4,508円／h。** 固定Bはオプションと複数点で伸びない（3,000円/h止まり）。**施工者にとっては率の方が「稼げる案件を選ぶ」余地が大きい**
5. **マッチングPF経由の案件は、率を「請求額」に掛けると元請けが赤字になる**（27,250×60%＝16,350 ＞ 手取り17,712 − ほぼ残らない）。率は必ず**元請け手取り**に掛ける。これはシステムの入力項目（外部手数料）に効く
6. **繁忙期加算（+3,300）は率なら自動で施工者に1,980円乗る（60%）。** 固定は表の改定が要る

### 2-2. 率をいくつにするか（率を採る場合の目安）

| 率（施工者取り分） | 元請けの取り分 | 位置づけ |
|---|---|---|
| 70% | 30% | 本舗ロイヤリティ（27.6%）と同水準。施工者に厚い。「本舗と同じ取り分で、上下なし」と言える |
| 60% | 40% | PF（35%）よりは元請けが取る。元請けの集客コスト（CPA上限9,500円＝約35%）を賄える最低線 |
| 50% | 50% | 折半。分かりやすいが、施工者の時給が2,695円/h（エアコン1台）まで落ちる |

元請けが負う仕事（集客・見積・電話・決済・事故の一次対応・再訪の手配）の対価として **30〜40%** が、既存の仲介（本舗 27.6%・PF 35%）と並べたときに説明できる帯。

## 3. 私の推し：**ハイブリッド（提示型）＋既定値60%**

- 網としては率も固定も**決めない**。発注者が案件ごとに「請求額」「外部手数料」「施工額」を入力し、システムが**施工者の取り分率**を自動表示する
- 入力欄の**既定値は手取りの60%**（発注者が変えられる）。これで日常の操作は率モデルと同じ手間。ただし拘束はしない
- 施工者は**最低受け額**（メニューごと、または時給ベース）を登録。下限未満の案件は薄く表示
- 成立実績から**メニューごとの施工額の中央値と率の中央値**を全員に表示。「みんないくらで出しているか」が見えるので、取りすぎる元請けは自然に選ばれなくなる。**投票で決めなくても相場が形成される**
- 投票は運営ルール（利用料・除外基準・既定値の見直し）にだけ使う
- **なぜ**：率の長所（追従・動機・地方）を持ちながら、価格協定のリスクが最も低く、固定の長所（現場の分かりやすさ）は「額がその場で表示される」ことで代替できる
- **弱点**：発注者が案件ごとに金額を決める手間。既定値で埋めるので実質は1クリック。もう1つは「既定値60%」自体が事実上の基準になること。法務にはこれも聞く

### 石田君への言い方（案）

> 「うちが率を決めるんじゃなくて、出す人が案件ごとに書く。何%かは全部見える。相場の中央値も出る。だから取りすぎる人は選ばれない。ルールで縛るんじゃなくて、見えることで整う」

---

## 4. 決めてほしいこと

- **4-1. モデル**：ハイブリッド（提示型）でよいか。率モデルを採るなら率はいくつか。固定を採るなら固定Bの表を起点にするか
- **4-2. 既定値**：60%でよいか（70%にすると本舗と同水準の取り分で「本舗と同じで上下なし」と言いやすい。60%は元請けの集客コストを賄う最低線）
- **4-3. 率の母数**：「元請け手取り（外部手数料を引いた後）」でよいか
- **4-4. オプションの扱い**：オプション（防カビ等）は本体と同じ率でよいか。現場で売った分は施工者に厚く（例：80%）してクロスセルを促すか
