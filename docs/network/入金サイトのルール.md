# 入金サイトのルール（論点と叩き台）

- 作成：2026-09-22
- 前提（確定している事実）
  - **うちの**お客様の支払いは作業完了後その場（現金かカード）。**これはうちの決済の話で、協力店の前提にはしない。** 協力店が現場で受けられる手段は店ごとに違う（現金だけの店が多いはず）。ルールは「決済手段に依存しない形」で書く
  - 施工額の既定値は**施工者75%**（仮置き、9/26まで）。受け手は自分の**最低受け額**を登録
  - 現場では**元請けの名前で名乗る**（壁打ち01 B-5）
  - 下請け相場の支払条件は「**月末締め翌月末払い**」が多数。速いところで「月末締め翌月15日・20日」（ジョーシン）、「日払い・数日以内」もある（`取り分の横並び比較.md` 1-3）
  - ポータル（くらし等）では**施工者がその場で全額受け取り**、手数料は翌月以降に払う。つまり施工者から見た競合の入金サイトは「**即日**」

---

## ★ 決定（2026-09-22 オーナー）

- **想定する利用シーンは大型案件が大半。** だから基本の流れは「**元請けがお客様から領収 → 下請けに支払う**」。下請けが現場で集金するケースは少数側
- 元請けはその案件の入金情報を**開示**し、**領収後は極力短いスパンで支払う。原則「着金後5日」**
- 以下の1章・2章の「推し」（施工者が集金する案A、翌月10日払い）は**この決定で上書き**。残す価値のある部分（領収書の名義、後日振込案件の扱い、相殺、実費）は8章で組み直す

## 1. 集金の流れ（決定前の検討。記録として残す）（ここが一番の分かれ道）

**現場にいるのは施工者。お客様はその場で払う。** だから「誰の財布に最初に入るか」で、お金の向きが逆になる。

| 案 | 流れ | 施工者の入金 | 元請けの入金 | 事故のとき |
|---|---|---|---|---|
| **A. 集金した人が相手の分を払う** | 施工者が現場で全額受け取る（現金。カード等は施工者が自分で持っている手段があれば）→ 元請けの取り分（25%）を後日払う | **即日** | 翌月 | 施工者が払わないと、元請けは25%を失う。露出は小さい |
| B. 元請けが集金して施工者に払う | お客様は元請けに払う（事前振込・元請けの決済リンク等）。現場の現金は施工者が預かって元請けへ送金 → 元請けが施工額（75%）を後日払う | 翌月 | 即日 | 元請けが払わないと、施工者は75%を失う。露出が大きい。**現金客は「預かって送金」が毎回発生** |
| C. 網（運営）が集金して分配 | お客様は運営に払う → 運営が両者に分配 | 翌月 | 翌月 | 運営に資金が滞留。**収納代行・資金移動業の規制と決済手数料が運営に乗る。** 初期は無理 |

**推し：A。** 理由は3つ。
1. 施工者の入金が即日で、**ポータルと同じ**。「くらしより入金が遅い」と言われない
2. 現金客をそのまま扱える。施工者が決済端末を持っていなくても成り立つ（**持っていない店を標準にする**）
3. 未払いの露出が元請けの25%だけ。元請け側は比較的体力のある側（うちを含む）が多く、待てる。**「元請けが待つ」は対等の見せ方として効く**

Aの補足ルール（これが無いと事故る）
- **領収書は元請けの名前で出す。** 施工者は現場で元請け名の領収書を渡す（システムが元請け名入りのPDF／控えを出す）。お客様から見た契約相手は元請け
- 現場でカード等を受けるかどうかは**施工者が自分の手段で決める**。持っていなければ現金のみ。お客様がカード払いを希望する案件は、元請けが出すときに「元請けが集金（事前決済・後日振込）」を選ぶ。その案件だけ向きが逆になる
- **誰がいくら集金したかを、施工完了の入力と同時にシステムに記録する**（現金／カード／未収）。ここが精算の元データ
- 法人・空室など**後日振込の案件は例外**：お客様が元請けに振り込む → 元請けが施工者に払う。締め・支払日は下と同じ。**お客様の入金を待ってから払う、はしない**（施工者は元請けの与信で受けている）

## 2. 締めと支払日

| 案 | 施工者から見て | 元請けから見て | 備考 |
|---|---|---|---|
| 月末締め・翌月末払い | 業界並み。遅い | 楽 | 下請け慣行そのまま。「本舗と同じ」と言われる材料になる |
| **月末締め・翌月10日払い** | 速い。差別化になる | 10日以内に精算 | 案Aなら元請けが受け取る側なので、施工者にとっては「受け取りは即日、払うのは翌月10日」 |
| 週締め・翌週払い | 最速 | 事務が毎週 | 件数が増えると回らない。運営がやるなら自動化が要る |
| 案件ごと即日精算 | 最速 | 毎回振込 | 振込手数料が毎回。相殺できない |

**推し：月末締め・翌月10日払い。** 案Aなら、施工者は現場で即日受け取り、元請けへの25%は翌月10日まででよい。元請けが施工者に払う案件（法人の後日振込・元請けが事前に集金した案件）も同じ翌月10日。**ルールが1本で済む。**

法律の確認点：下請法は2026年1月から改称・改正されている（中小受託取引適正化法）。適用は資本金・従業員数の規模で決まり、小規模同士は対象外のことが多いが、適用される場合は「受領から60日以内の支払期日」が要る。**月末締め翌月10日は余裕で収まる。** 適用の有無は5章のリーガルチェックで確認（壁打ち01 B-7）

## 3. 相殺（ネッティング）

会員は**出す側にも受ける側にもなる**。同じ2社の間で「AがBに払う分」と「BがAに払う分」が両方出る。

- **月次で、2社ごとに相殺して差額1本にする。** システムが精算書（明細つき）を両者に出す
- 振込手数料は**払う側**が負担（差額を払う側）
- 精算書は**適格請求書**の要件を満たす形にする（登録番号・税率・税額）。免税事業者の会員は登録番号なしの精算書になる。元請けは会員情報でそれを事前に見られる

## 4. 決済手数料・実費

| 項目 | 負担 | 理由 |
|---|---|---|
| カード等の決済手数料（集金した人の手段で発生した分） | **「外部手数料」として手取りから引く**（ポータル手数料と同じ欄） | 誰が集金しても割合は同じになる。集金した人の持ち出しにしない。現金なら発生しない |
| 材料・消耗品 | 施工者 | 施工額に含む（壁打ち01 B-6 と同じ整理） |
| 駐車場代・高速代 | **お客様に請求できる分は請求額に入れ、入れられない分は施工者** | 元請けが見積時に「駐車場あり／なし」を書く。無い場合は施工額に上乗せするか、施工者が最低受け額で断る |
| 当日キャンセル（お客様都合） | お客様からキャンセル料を取れたら、**施工者に全額** | 動いたのは施工者。元請けは取らない |
| 当日キャンセル（元請け都合） | 元請けが施工者に**定額**（例：3,000円）を払う | 施工者の空き日を潰した対価 |
| 当日キャンセル（施工者都合） | 施工者が元請けに**定額**（例：3,000円）＋受注停止基準の指標に入れる | お客様への迷惑は元請けがかぶる |

## 5. 未払いのとき

- 支払期日（翌月10日）を**7日過ぎたら自動で「受注・発注ともに停止」**。払えば自動で復帰。運営の手は入らない（壁打ち A-1 の方針どおり）
- 停止と復帰は本人と相手に通知。**全員には通知しない**（金の話は当事者だけ）
- 2回目以降の遅延は、除外基準（ルール5）の指標に入れる
- 遅延損害金は取らない（少額で、取り立ての事務のほうが高い）

## 6. デモに入れるもの（9/26）

- 施工完了の入力に「**誰が集金したか**（施工者／元請け／後日振込）と方法（現金／それ以外）」を足す
- 「自分」に**今月の精算見込み**（相手ごとの差額）を出す
- ルール画面に「入金サイト」の節を足す

## ★ 決定 その2（2026-09-22 オーナー）

1. **入金期日は、下請けを募集するときの必須開示項目。** 下請けは入金スケジュールまで確認したうえで受注できる仕組みにする
2. **下請けが領収する案件は、出すときにその印（チェック）を付ける。** 受ける側の確認事項に「領収後5日以内に元請け分を支払う」を入れる
3. **請求書の自動作成・保存を機能にする。** 事前の条件どおりに、施工日以降に出力可能。当事者どちらもPDFでダウンロードできる。保存期間は60日程度

デモへの反映（2026-09-22 実装済み）
- 出す：「お客様からの集金（元請けが領収／下請けが現場で領収）」「お客様からの入金予定日（必須）」「下請けへの支払予定日（＋5日、自動）」
- 案件カード：入金予定・支払予定を全員に表示
- 手を挙げる：確認ダイアログ。入金スケジュール（または領収後5日以内の支払）と、現場の名乗りに同意しないと手を挙げられない
- 完了した案件：当事者だけに「請求書（PDF保存）」ボタン。成立条件から自動作成（適格請求書の項目。免税事業者は登録番号なし）。保存期限＝施工日＋60日を表示

注意（法律）：電子で受け取った請求書は、受け取った側が**電子帳簿保存法の電子取引データ保存**として自分で保存する義務がある（保存期間は原則7年）。システムの60日保存は「取りに来る猶予」であって、各社の帳簿保存の代わりにはならない。請求書の脚注にその旨を入れてある

## ★ 決定 その3（2026-09-22 オーナー）：案件の完了は「双方のクローズ」

**元請けが着金を入力する仕組みは採らない。** 代わりに：

1. **支払予定日**（元請け領収なら入金予定日＋5日、下請け領収なら施工日＋5日）に、**双方の登録アドレスへURL付きの通知**を送る。「施工代金を支払い／入金を確認のうえ、本案件をクローズしてください」
2. **元請け**は「下請けに発注代金を支払った」「お客様からクレームは発生していない」等にチェックし、「本案件をクローズする」を押す
3. **下請け**は「受注代金の入金を確認した」「クレーム・やり直しは発生していない」等にチェックし、同じボタンを押す
4. **双方が押した時点で案件完了**（相場・票の重み・評価に反映）
5. どちらかが未押下の間は、**毎日**対応依頼メールを送る

チェック項目の叩き台（別途精査。デモに入れてある）

| 立場 | 元請けが領収した案件 | 下請けが現場で領収した案件 |
|---|---|---|
| 元請け | 下請けに発注代金を支払った／お客様からクレームは発生していない／下請けの現場対応に問題はなかった＋評価★ | 下請けから元請け分の入金を確認した／お客様からクレームは発生していない／下請けの現場対応に問題はなかった＋評価★ |
| 下請け | 受注代金の入金を確認した／クレーム・やり直しは発生していない／元請けの対応（情報・連絡）に問題はなかった | 元請けに元請け分を支払った／クレーム・やり直しは発生していない／元請けの対応（情報・連絡）に問題はなかった |

これで 8-1（着金の記録）・8-2（歯止め）・8-8（完了の定義）は解消。

## ★ 決定 その5（2026-09-25 オーナー）：5営業日・実費精算・オプション同率

- 支払サイトは**着金後5営業日以内**（土日祝を含めない）。暦日5日から変更。連休が挟まると払えない、という同業者の指摘を受けて
- **駐車場代・交通費は実費精算。** お客様に請求できる分は請求額に載せる。法人は請求書に含める。現場で施工者がその場で精算してもよい
- **オプションは本体と同じ取り分率**（4章の「決めてほしいこと 4-4」の答え）
- 「網としての最低単価を一律に決めるか」は**意見募集**として他の事業者にも聞く

## ★ 決定 その4（2026-09-22 オーナー）：与信の置き場所と支払遅延の見える化

- **原則：お客様の入金が遅れても、元請けは支払予定日に下請けへ払う**（下請けは元請けの与信で受けている）
- **例外：案件が大きいなどで元請けが支払困難なときは、「申し送り」として下請けへ通知できる**（新しい支払予定日と理由）
- **ただし入金が遅れた場合はカウントし、下請け募集時の事業者情報に「過去に何件の支払遅れがあったか」を全員に見せる**

デモへの反映（実装済み）
- 成立後、元請けに「支払が遅れる場合の申し送り」ボタン。新しい日付と理由を入れると下請けに通知され、案件カードの支払予定が「旧→新」で表示される
- 遅延の数え方：**元請けの申し送り**、または**下請けがクローズ時に「入金は支払予定日どおりだった」を外した**案件を1件と数える（元請けが黙って遅らせても下請け側から記録できる）
- 案件カードの「出した人」の横と、会員一覧に「支払遅延 ○件」を表示

これで入金サイトの論点は閉じた。残りは実務の既定値（振込手数料は払う側、相殺なし、キャンセル料の定額、下請けが複数のときは人ごと）で、異論が出たら戻す。

## 8. 決定後に残る論点（2026-09-22。上の決定で 8-1〜8-5・8-8・8-12 は解消）

基本形：**元請けが領収 → 着金後5日以内に下請けへ支払う。** そのうえで決めるもの。

| # | 論点 | 推し |
|---|---|---|
| 8-1 | 「着金」を誰がどう記録するか | 元請けが着金日をシステムに入力（自己申告）。入力した瞬間に支払期日（＋5日）が確定し、下請けに通知 |
| 8-2 | 元請けが着金を入力しないときの歯止め | 施工完了から**30日**で着金確認の催促を自動通知。**60日**で「着金とみなす」→ 支払期日が自動確定（下請法の60日に合わせる） |
| 8-3 | お客様が払わない・遅れるとき | 下請けは元請けの与信で受けている。**施工完了から60日で必ず払う**（8-2と同じ線）。お客様の未払いは元請けのリスク |
| 8-4 | 出すときに開示する入金情報 | 請求額・入金方法（現地／振込）・**入金予定日**・支払予定日（＝入金予定＋5日）。下請けは受ける前に「いつ金が入るか」を見て決める |
| 8-5 | 少数側（下請けが現場で現金を受ける案件） | 対称にする：下請けが全額受け取り、**施工完了後5日以内**に元請け分を払う。案件を出すときに「集金：現地（下請け）」と指定 |
| 8-6 | 大型案件で入金が分かれるとき（前金・中間・完工） | 着金の都度、**按分して5日以内**。按分率は施工額÷請求額で固定 |
| 8-7 | 下請けの持ち出しが大きいとき（人工・材料） | 元請けが任意で**前払い**を設定できる（案件に「前払い○円」）。義務にはしない |
| 8-8 | 施工完了の定義（支払の起点） | 下請けが完了報告 → 元請けが承認。**承認しないまま3日で自動承認** |
| 8-9 | やり直し・不備があるとき | 争いのある分だけ保留、残りは期日どおり払う。運営は仲裁しない（当事者で解決、決着したら入力） |
| 8-10 | 支払方法と手数料 | 銀行振込。振込手数料は払う側。カード等の決済手数料が発生した場合は「外部手数料」として手取りから引く |
| 8-11 | 相殺 | **しない**。案件ごとに払う（大型案件が主なら件数は少なく、相殺の利点が小さい。分かりやすさ優先） |
| 8-12 | 請求書 | システムが下請け名義の請求書（適格請求書の要件）を自動生成。免税事業者は登録番号なし |
| 8-13 | 支払遅延 | 期日＋7日で元請けの**発注を自動停止**、入金で自動復帰。通知は当事者だけ |
| 8-14 | キャンセル料 | お客様都合：取れた分は下請けに全額／元請け都合・下請け都合：定額3,000円（叩き台） |
| 8-15 | 下請けが複数のとき | 元請けが人ごとに施工額を書く。支払も人ごと |
