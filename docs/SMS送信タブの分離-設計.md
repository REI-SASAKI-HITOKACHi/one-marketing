# 1. 結論：**分離より先に、リンクを消すほうが要ります**

**依頼は「別スプシへ分離」でしたが、警告の原因は「タブがそこにあること」ではなく「リンクがあること」です。**
**別スプシへ移しても、リンクごと移れば警告も一緒に移ります。**

```
やること①  D列のリンクを外す        → 警告が消える。今すぐ効く
やること②  タブを別スプシへ移す      → 台帳が軽くなる。①とは別の目的
```

**①だけで、Drive の警告は消える見込みです。②は急ぎません。**

# 2. やること①：D列を「リンク無しの文字列」にする

## 手順（3つ）

```
1. 控えを git に取る

   → data/sheets/backup/ に落ちる。★コミットまでして初めて控え

3. 検算：ハイパーリンクが 0件になったことを読み直して確かめる
```

## ★ 送信済みの記録は消えません

**消すのは D列だけです。** 送った事実は `送信済み` 列に、本文は `送信する本文` 列（F）に残ります。
**「誰に何を送ったか」は F列で完全に追えます。**

| 列 | どうなる |
|---|---|
| D `▶SMSを開く` | **空になる**（リンクも文字も） |
| E `送信済み` | **触らない**（送信済み／返信あり／不通・エラー／対象外） |
| F `送信する本文` | **触らない**（送った本文そのもの。記録として残す） |
| G `返信メモ`・Z `返信内容（本文）`・AA `返信の分類` | **触らない** |

## ⚠️ 消すと、和真さんはスマホから送れなくなります

**D列は「タップすると宛先と本文が入ったSMS画面が開く」導線でした。**
**無くすと、F列の本文を手でコピーして、宛先も手で入れることになります。**

**だから、消してよいのは「手送りをやめてKDDIに移す」と決まってからです。**
CMO から「手送りは KDDI 開通まで一時停止」と聞いているので、**その前提なら今すぐ消せます。**
**もし手送りを再開するなら、消す前に代わりの導線が要ります**（下の③）。

# 4. やること③：タブを別スプシへ移す（急がない）

**①が済めば警告は消えるので、これは「台帳を軽くする」ためだけの作業です。**

## 移すもの／残すもの

| | 移す先 |
|---|---|
| `冬季見込み客_2026`・`お詫びSMS_20260912` | **新スプシ「SMS送信_2026」**（和真さん専用） |

## 名乗りの照合は、動かしても効き続けます

**`meigi_hyou()` が読むのは各年の `◯月_売上/顧客` だけ**（`derive-soushin-keitou.py` の `BOOKS`）。
**送信用の2タブは1行も読んでいません。** だから**2タブをどこへ移しても照合は動きます。**

**逆に、送信ツール側は2タブを読むので、スプシIDを差し替える必要があります。**

| ツール | 直すところ |
|---|---|
| `tools/sms-honpo-3tsu.py` | `SS` を新スプシIDに |
| `tools/sms-jisha-batch.py` | 同上 |
| `tools/meigi-fuitchi-hold.py` | 同上 |
| `tools/henshin-bunrui.py`・`henshin-iro.py` | 同上 |
| `tools/rakuraccoon-jogai.py` | **`SS`（送信リスト）と `BOOKS`（台帳）が別になる**。ここは分けて書く |
| `tools/build-sms-list.py`（cmo） | 読むのは台帳、書くのは新スプシ。**入口と出口が別スプシになる** |

> ### 🔴 いちばん危ないのはここです
> **いまはどのツールも `SS` 1つで済んでいます。** 分けると、**片方だけ直し忘れた
> ツールが、古いタブを読み書きし続けます。** 気づけません。
>
> **`SS` をツールごとに直すのではなく、1か所（例：`tools/sheets_ids.py`）に定数を置いて、
> 全ツールがそこを見る形にしてから移してください。** そうすれば直し忘れが起きません。

## 成果の記録を台帳へ戻す

**`送信済み`・`返信メモ`・`返信内容（本文）`・`返信の分類` は、移すと台帳から見えなくなります。**

**戻す必要はありません。** 理由：

- **`顧客管理台帳` は `◯月_売上/顧客` から作る派生データ**です。手で足すと再生成で消えます
  （`docs/crm-savedata.md` 2026-09-15）
- **成果（受注）は月次タブに入ります。** SMSから来たかどうかは `予約_Web` 側に持たせる、と
  `20260913-03-crm` で決まりました（案A）
- **返信の記録は、送信リスト側にあるのが自然です。** 台帳は「施工の記録」で、「連絡の記録」ではありません

**ただし1つだけ、台帳側に欲しいものがあります。**

| | |
|---|---|
| **配信停止の申し出** | **これは台帳側に無いと危ない。** 送信リストを作り直すたびに、
その人がまた候補に入ってきます。2026-09-21 に1名（転居・案内不要）が出ました |

**→ `顧客管理台帳` ではなく、月次タブでもなく、`電話番号_未登録` と同じ並びの
新タブ `配信停止_2026`（電話番号・氏名・申し出日・出どころ）を台帳本体に置くことを薦めます。**
**送信リストを作るツールは、毎回ここを読んで除外する。** これなら再生成で消えません。
