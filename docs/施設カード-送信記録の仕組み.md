# 施設カード：送信記録の仕組み（Google フォーム経由）

オーナー指示（2026-09-14）：「スプシへの記録だけど、Googleフォームを活用して記録はアクセスなしでできる仕組みを構築した上でCMOへ連携しておいて」

## なぜ変えたか

9/14 08:22、第1波の直前に売上スプシの読み取りが上限に達した（`Read requests per minute per user` 60/分）。
施設カードの送信は1件ごとに「送信ログに追記」「進捗タブを更新」でスプシを触るため、他のスレッド（crm・quotation 等）と枠を取り合う。
送信の最中に枠が尽きると、**送った事実が記録されない**のがいちばん困る。

## いまの形

```
送信ツール（shisetsu-outreach.py）
   └→ Google フォームに HTTPS で1回 POST（認証なし・API の枠を使わない）
          └→ フォームに回答が溜まる
                 └→ sync-sendlog.py が、溜まった分をまとめてスプシ「施設カード_送信ログ」に書く
```

- **送信の経路に認証情報が要らない。** サービスアカウントの鍵も、API の枠も使わない
- 枠切れ・トークン失効で送信が止まらない。スプシへの反映が遅れるだけで、記録そのものは失われない
- **人が手で入れる分も同じフォームから入れられる**（電話・訪問・Instagram DM。ブラウザ担当やオーナーが使う）

おかしな行が入ったら、送信者の列が「ワンヒッター株式会社 佐々木」でないもので分かる。

### 使い方

```
python3 tools/sync-sendlog.py          # 溜まった回答をスプシへ（1日1回／送信の区切りごと）
python3 tools/sync-sendlog.py --dry    # 何件あるか見るだけ
```

送信ツールは `~/.config/one-hitter/sendlog-form.json` があればフォームに投げる。無ければ今までどおり Sheets API に書く（どちらでも動く）。

## 作り直すとき

サービスアカウントは Drive のストレージ枠を持たないので、**フォームそのものは作れない**（`403 storageQuotaExceeded`／Forms API は 500）。
空のフォームだけオーナーのアカウントで作り、あとはツールで組み立てる。

1. オーナーのアカウントでフォームを作る（この環境なら Drive の連携から `mimeType=application/vnd.google-apps.form` で作れる）
2. サービスアカウント `claude-sheets@one-hitter-sheets.iam.gserviceaccount.com` を**編集者**で共有
3. `python3 tools/make-sendlog-form.py create <フォームID>` … 設問13個を作り、entry ID を保存
4. Drive で「リンクを知っている全員（閲覧者）」にし、Forms API の `setPublishSettings` で公開する
5. `python3 tools/make-sendlog-form.py test` … 1件テスト投稿（`結果=テスト` の行は sync がスプシに書かない）

Google Forms API は 2026-09-14 に web-inflow が有効化した（サービスアカウントの cloud-platform スコープで Service Usage API を叩けた。GCP の画面を触っていない）。

## 進捗タブの更新について

ステージ・接触日・次回アクションの更新は、いまも Sheets API で書いている（行を特定して1セルずつ直すので、フォームには向かない）。
ただし読み取りは送信の開始時に1回だけにして、429 と失効に再試行を入れ、それでも書けなかった分は `dist/outreach/sheets-fallback.jsonl` に残すようにした（2026-09-14）。
