# 無料経路（HP・SNS・ブログ・GBP）の数え方：毎週やること（2026-10-21 計測担当）

オーナー指示（10/21）原文：「ありがとう。無料経路(hp.sns)を強化する必要があるね。CMOへ連携して強化させて。」
目標（planning 案・CMO 採用）：2026年12月 月1〜2件 → 2027年1〜3月 月3件 → 4月以降 月6件。いま無料経路の受注は0件。

## 1. 毎週やること（計測担当の持ち場）
| 曜日 | やること | 量 | 誰が流す | 出るもの |
|---|---|---|---|---|
| **月曜** | `tools/funnel-keiro.py` で前週（月〜日）の経路別4段 | 1回 | **CMO の環境**（GA4 の鍵） → 結果を掲示板へ。私が読んで1行の見立てを付ける | 経路ごとの LP表示・予約ページ到達・入力開始・申込・**受注**、**無料経路の計** |
| **月曜** | `tools/search-console.py` で HP の検索語句（前の28日） | 1回 | CMO の環境 → lp・web-inflow へ | 表示の多い語・クリック率の低い語（HP の見出しや記事の直し所） |
| **月曜** | GBP の突き合わせ（下の3） | 1回 | browser が GBP の数字を読む → 私が GA4 と並べる | GBP のクリックと、実際にサイトに着いた数のずれ |

コマンド（毎週同じ。日付だけ変える）
```
python3 tools/funnel-keiro.py --start <前週の月曜> --end <前週の日曜> --yoyaku <予約_Web.csv> --save funnel-<日付>.json
python3 tools/search-console.py --site <Search Console の登録の形> --start <28日前> --end <前日> --by query --limit 50
python3 tools/search-console.py --site <同じ> --start <28日前> --end <前日> --by page --limit 30
```

## 2. 経路の分け方（funnel-keiro・10/21 更新）
| 経路 | src | 無料経路に入るか |
|---|---|:--:|
| HP | `hp*` | ○ |
| Instagram | `ig*`（`ig_ad` を除く） | ○ |
| Facebook | `fb*`（`fb_ad` を除く） | ○ |
| ブログ | `blog*` | ○ |
| GBP | `gbp*`（`gbp_book` 予約ボタンを含む） | ○ |
| 広告／広告（カビLP） | `gads_*` | × |
| SNS広告 | `ig_ad`・`fb_ad` | ×（お金を使う経路なので分ける） |
| SMS | `sms*` | ×（既存のお客様への連絡） |
| 直接・その他 | それ以外 | × |

- 受注は、予約_Web の「状態（の区分）」に「受注」を含む行で数える
- **数えられないもの（漏れ）**：HP の問い合わせフォームから来た申込（GA4 にも予約_Web にも入らない。完了ページの表示は申込の数ではない、と 10/15 に確定）。HP のフォーム経由は、台帳の「流入経路＝HP」で月に1回数えて、表の下に足す
- HP → 予約ページのリンクに `?src=hp…` が付いていないと「直接・その他」に落ちる。**付いているかは未確認**（公式サイトは CMS で、lp・CMO の持ち物）。付いていなければ足してもらう

## 3. 「GBP から人が来ていない」の確かめ方
GBP からサイトへの入口は2つあり、着地先が違う。
| GBP のボタン | 着地 | GBP の数字（browser が読む） | 当社側の数字 |
|---|---|---|---|
| ウェブサイト | 公式サイト（one-hitter.jp）。`utm_source=gbp&utm_medium=profile`（10/3 CMO） | GBP の「ウェブサイトのクリック数」（週） | GA4 公式サイトのストリームで、セッションの参照元＝`gbp` の数 |
| 予約 | 予約ページ `?src=gbp_book`（10/3 CMO） | GBP の「予約」のクリック数（出れば） | funnel-keiro の GBP の行の「予約ページ到達」 |
- GBP のクリックの数に比べて当社側が極端に少なければ、リンク先かパラメータが落ちている
- 両方とも少なければ、**GBP を見た人がそもそも押していない**（ボタンの前の写真・クチコミ・投稿の問題 → web-inflow の持ち場）
- 10/16 に、GBP から予約ページに来た11人が入力を始めていない件を見た。1度も触れていない人か人以外の可能性がある（20261016-01）。同じ表で続けて見る

## 4. 12月に月1〜2件へ届くか（計測からの見立て）
- 広告の実績では、**予約ページに着いた人の約4人に1人が申込**（10/11〜18：予約ページ到達13・申込3）。無料経路でも同じ率と置くと、**月1〜2件には、無料経路から予約ページに月4〜8人**着けばよい
- 10/1〜15 の GBP → 予約ページは11人（ただし入力0）。**人数は足りている可能性があり、問題は「着いてから」**かもしれない。毎週の表で、無料経路の「予約ページ到達」と「入力開始」を並べて見れば、どちらが足りないか分かる
- この見立ては、広告の率をそのまま当てたもの（推定）。無料経路の人は比べている段階の人が多く、率は低い可能性がある
