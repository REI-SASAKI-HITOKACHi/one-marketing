# GA4 キーイベントの定義（2026-09-27 作り直し）

作成 2026-09-27 ／ 計測担当 ／ 依頼 `20260925-01-measurement`（CMO）
道具 `tools/ga4-admin-setup.py`（検算 `tools/test-ga4-admin-setup.py`）

**GA4 の「キーイベント」は、レポートで「成果」として数えるものの指定です。**
**Google広告の成果は、ここを経由しません**（LPから `AW-18450975194` へ直接撃っている。
`docs/広告-コンバージョン計測.md`）。**キーイベントを変えても、広告の数字は変わりません。**

---

## 新しい定義

| イベント | 何を数えるか | どこで出るか |
|---|---|---|
| **`generate_lead`** | **申込**（受理されたもの） | LPのサンクスページ／**予約フォームの完了画面** |
| `phone_click` | 電話ボタンが押された | LP4本・アンケート・予約フォーム |
| `line_click` | LINEボタンが押された | LP4本（アンケートのLINEは `refer_share` で別物） |
| `booking_start` | 予約フォームの入力を始めた | 予約フォーム |
| `teltap` | 公式サイトの電話タップ | 公式サイト（リアライズ製。そのまま残す） |

> ### ⚠️ `booking_start` は**申込ではありません**
>
> 入力欄に触っただけで1件になります。**関心の強さの目安**として足しました（CMO判断）。
> **`generate_lead` と足し算すると水増しになります。** 分けて読んでください。

## キーイベントにしてはいけないもの

| イベント | 理由 |
|---|---|
| **`form_submit`** | **送信ボタンを押した時点。`generate_lead` と二重に数えます。** 二度押しで2件になります（9/15 のテストで実際に 4件対2件） |
| `booking_submit` | 同じ理由。予約フォームの「送信を押した」で、完了画面の `generate_lead` と二重 |
| `survey_complete` / `refer_share` | アンケートの回答・紹介。**既存のお客様の行動で、新規の成果ではありません** |
| `click` | 公式サイトの電話リンクは**1回のタップで `click` と `teltap` の2つを撃つ**ので、両方にすると1タップが2件 |

> **9/25 の依頼文には「LPの `form_submit` もキーイベントに」とありましたが、入れていません。**
> 9/27 の起こし（CMO）の一覧でも外れていたので、そちらに合わせました。

## 変更の手順（CMOの環境で）

```
python3 tools/ga4-admin-setup.py --dry-run     # 下見。何も変えない
python3 tools/ga4-admin-setup.py               # 変更する
```

**本番の実行では、GA4を触る前に「変更前の一覧」を `docs/ga4-キーイベント-変更前-<日付>.md` に書き出します。**
**元に戻すときは、そこにある名前を画面でキーイベントに付け直せば戻ります。**

**順番も道具が守ります。** 先に4件を足し、**そのあと** `form_complete` を外します。
先に外すと、その間キーイベントが減った状態でレポートが集計されるためです。

## ① スパムを除けるか → **GA4では除けません**

**GA4には、行動（滞在時間・直行・PC）で取り込み時に弾く機能がありません。**
使えるデータフィルタは「内部トラフィック（IPで指定）」と「開発者トラフィック」の2つだけで、
**スパムは当社のIPから来ないので、どちらにも当たりません。**
**過去のデータを後から消すこともできません。**

**効く手は2つです。**

| | |
|---|---|
| **キーイベントから外す**（今回やること） | **スパムが「成果」として数えられなくなります。** セッションとしては残ります |
| **フォームにスパム対策を入れる** | 根本対策。**公式サイトはリアライズ製なので、lp 経由でリアライズへ**（入力欄を1つ隠す「ハニーポット」なら、お客様の手間は増えません） |

## ② 予約フォームの「申込完了」は取れているか → **取れています。名前が `generate_lead` です**

**予約フォームの完了画面で撃っているのは `generate_lead` です**（`page_kind=booking`）。
**`booking_complete` のような別の名前は作っていません。** だから見当たらなかったのだと思います。

| | 実測 |
|---|---|
| 仕組み | 完了画面（`#done`）が出た瞬間に `generate_lead` を1回 |
| 本番での確認 | 9/15・9/18・9/21 に `tools/measure-production.py` で「予約フォーム：完了画面で発火」PASS |
| GA4での実績 | **9/20 に `yoyaku.onehitter.jp` から1件**（和真さんの動作確認。9/22 CMO実測） |

**lp と組んで入れる必要はありません。** `generate_lead` をキーイベントにすれば、予約フォームの完了も一緒に数えられます。

**LPの申込と分けて見たいときは、ホスト名で分けてください**（`lp.onehitter.jp` と `yoyaku.onehitter.jp`）。

## ③ 直近30日を新しい定義で数え直す

**GA4のレポートは、キーイベントを変えても過去には遡りません。**
**そこで、イベントの件数そのものを数えます**（イベントは変更前から届いているので、遡って数えられます）。

```
python3 tools/ga4-event-shirabe.py --event generate_lead --by sessionDefaultChannelGroup --days 30
python3 tools/ga4-event-shirabe.py --event phone_click   --by sessionDefaultChannelGroup --days 30
python3 tools/ga4-event-shirabe.py --event line_click    --by sessionDefaultChannelGroup --days 30
python3 tools/ga4-event-shirabe.py --event booking_start --by sessionDefaultChannelGroup --days 30
python3 tools/ga4-event-shirabe.py --event teltap        --by sessionDefaultChannelGroup --days 30
```

**この5本で「チャネル × キーイベント」の表になります**（ホスト名も一緒に出るので、LP・予約・公式サイトも分かれます）。
