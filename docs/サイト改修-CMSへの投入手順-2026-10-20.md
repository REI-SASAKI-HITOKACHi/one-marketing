## 🔴 決めていただきたいこと：動いているものを静止させてよいか

私が作った17枚は、**1枚のHTMLとして完結した静的なページ**です。
一方、いまのサイトは**メニュー・施工事例・お客様の声・ブログが、CMSのデータから自動で出ています**。

私の案をそのまま入れると、**この4つが自動で更新されなくなります。**
たとえばブログを書いても、トップの一覧に出てきません。メニューの料金を直しても、トップに反映されません。

やり方は2つあります。

### A案：私の案をそのまま入れる（静的にする）

- ⭕ 見た目は案のとおりになる。作業が速い
- ❌ **メニュー・施工事例・お客様の声・ブログの自動更新が止まる。**
  記事を足すたびに、トップページも手で直すことになる
- ❌ `/constructed/` `/voice/` `/blog/` は一覧ページそのものなので、影響がもっと大きい

### B案：CMSの部品はそのまま使い、見た目だけ新しくする

- ⭕ **自動更新はそのまま。** 記事を足せば今までどおり出る
- ⭕ 元に戻すのも楽（CSSを外すだけ）
- ❌ CMSが出すHTMLのクラス名に合わせてCSSを書き直す必要がある。**作業は増える**
- ❌ CMSの出すHTMLの形に縛られるので、案と完全に同じにはできない箇所が出る

### 私の見立て

**B案を軸に、部品が無いところ（ヒーロー・数字の帯・コンセプト・最後のCTA）だけA案で足す**のが、
いちばん損が少ないと思います。自動更新を止めるのは、あとから効いてくる損が大きいので。

**どちらで進めるか決めていただければ、そのまま作業に入ります。**

## どこに何を入れたか

| | |
|---|---|
| 入れた場所 | **レイアウト `base`（ID 25）の「CSS/JS/画像」の末尾** |
| 入れたもの | `cms/site/cms-skin.css` の中身（7,024字）を、下の印で挟んで追記 |
| 印 | `/* ===== OH-SKIN START 2026-10-20 … ===== */` 〜 `/* ===== OH-SKIN END ===== */` |
| 元に戻すには | **印の間を消すだけ。** 既存のCSS（フォーム周り）は1文字も触っていません |
| 控え | `cms/_backup-20261020/layout25-css-before.css`（追記前の7,210字そのまま） |

### なぜ `base`（25）なのか

レイアウトは `base`(25) を根にして枝分かれしています。

```
base (25)
 ├ TOP用 (152)        … トップ
 └ 下層共通 (155)
     ├ 通常下層ページ (42)  … コンセプト・特徴・法人 など
     ├ 施工事例 (111)
     ├ お客様の声 (129)
     └ メニュー共通 (99) → (102)
```

公開ページのCSSは `/_css/$/page/<ページ>/layout/<レイアウト>/lib/1507,…/` という1本にまとめて配信されます。
**先頭の `1507` が `base` のCSS**で、**どのページにも必ず入っています。**
つまり `base` に入れれば、1か所で全ページに効きます。

### 🔴 「ファイル管理＋外部CSS/JS」ではダメでした（実測）

最初はマニュアルどおり、ファイル管理に `cms-skin.css` を置いて
レイアウトの「外部CSS/JS」から読む形にしました。**これは効きません。**

CMSのファイル管理から配信されるファイルは **`Content-Type: application/octet-stream`** で返ります。
ブラウザは標準モードのページで、CSSでないMIMEのスタイルシートを**適用しません**。
同一オリジン（one-hitter.jp 自身）から読んでも同じでした。実測：

- `<link>` は DOM にあり、`document.styleSheets` にも並ぶ
- しかし `cssRules` は読めず、`--oh-red` も効かない（＝1行も適用されていない）

**ファイル管理に置いた `cms-skin.css` は、中身の控えとして残してあります。
これを「外部CSS/JS」からリンクしても効きません。** 直すならレイアウトのCSS欄です。
