# SMSの結果通知を、どこで受けて、どこに書くか

- 作成：2026-09-17／担当：顧客接点担当（`crm`）／きっかけ：`20260913-02-crm`（CMO 2026-09-17）
- **別紙「SMS結果通知先設定申込書（APIプラン）」が本体と一緒に出ているかが未確認**、という指摘を受けて書いた

---

## 0. 先に、いちばん大事な問い

> ### **別紙に「通知先」として何を書いたのか。**

**申込書を出したかどうかより、こちらのほうが先です。**
結果通知は**当社が用意した宛先（URL かメールアドレス）へ KDDI が送ってくる**もののはずです。
**宛先が決まっていなければ、別紙を出しても受け取れません。**

`docs/KDDI申込-記入内容.md` には、別紙について
「**デモと並行して進める**」（188行目）としか書かれておらず、**通知先の記録がありません。**

**確かめること（この順）**

1. **別紙を提出したか**
2. **提出したなら、通知先に何を書いたか**（URL／メールアドレス）
3. **その宛先を、いま誰が受け取れる状態にしてあるか**

> ⚠️ **URLを書いたなら、受け口のプログラムが要ります。**
> LINE の webhook と違い、**KDDIの結果通知に署名検証があるかどうかも未確認です。**
> メールアドレスなら、`info@one-hitter.her.jp` で受けて手で取り込む形になります。

## 1. なぜ要るのか（お金の話は小さい。台帳の話が大きい）

**CMO は「毎回お金が消えます」と書きましたが、金額としては小さいです。正直に置きます。**

| | |
|---|---:|
| 手送り74名での不通率（実測） | **4.1%**（3／74） |
| 本舗396名に当てはめると | 約16件 |
| 3通×11円なので、1回あたり | **約 ¥528** |

**¥528 は、止める理由にはなりません。**

### 本当の価値は、**台帳の電話番号を直せること**

**本舗396名の番号は、一度もSMSを送ったことがありません。**（すべて11桁の携帯番号。090が252件・080が127件・070が17件）
**どれが生きているかを、当社は一度も確かめていません。**

結果通知が無いと、こうなります。

- **どの番号が死んでいるか分からない。** 次のSMSも、電話も、同じ番号にかけ続ける
- **153名の電話番号を埋める作業（`電話番号_未登録` タブ）と混ざる。**
  「番号が無い人」と「番号はあるが死んでいる人」を分けられない
- 週次の「不達」の数字が、**和真さんが手で気づいたぶんしか出ない**

**結果通知は、台帳をきれいにする唯一の自動的な手段です。** そこが価値です。

## 2. 受け取ったら、どこに書くか

**顧客管理台帳には書きません。** 台帳は `◯月_売上/顧客` から作る派生データなので、
手で足すと再生成で消えます（`docs/crm-savedata.md` 2026-09-15）。

### 新しいタブ `SMS結果_2026`（生データを、届いた形のまま貯める）

| 列 | 中身 |
|---|---|
| 受信日時 | 通知が届いた日時 |
| 送信ID | KDDI が返す送信の識別子 |
| 宛先電話番号 | **文字列のまま。数値にしない**（先頭の0が消える） |
| 結果 | 送達／不達 |
| 理由コード・理由 | KDDIの仕様どおりに（**項目名は仕様書を見てから決める。いまは推測で埋めない**） |
| 送信日時 | 送った時刻 |
| 通数 | 分割後の通数（**課金の実績と突き合わせるため**） |

**生データはいじりません。** ここを正として、下の2つへ反映します。

### 反映その1 … `冬季見込み客_2026`

| 結果 | すること |
|---|---|
| 送達 | `送信済み` 列を「送信済み」に |
| **不達** | `送信済み` 列を「**不通・エラー**」に、`送らない理由` に **`SMS不達（理由コード）YYYY-MM-DD`** を書き足す |

**`送らない理由` は書き足しです。もとの理由は消しません**（`tools/meigi-fuitchi-hold.py` と同じ考え方）。

### 反映その2 … `電話番号_未登録` タブの隣に「死んでいる番号」を分ける

**「番号が無い人」と「番号はあるが届かない人」は、やることが違います。**

| | やること |
|---|---|
| 番号が無い（153名） | 和真さんがスマホの連絡先から埋める |
| **番号はあるが不達** | **番号が変わっている。** 電話でかけ直すか、公式LINE・郵送に切り替える |

**混ぜると、どちらも進みません。** 列で分けます。

## 3. 通数の実績は、必ず突き合わせること

**結果通知には「分割後の通数」が入るはずです。**（項目名は仕様書を見てから）

こちらの見込みは **396名・1,188通・¥13,068**（全員3通）。
**請求と合わない場合、70文字の数え方がこちらの想定と違います。**

> 例：**絵文字や機種依存文字が混ざると1通の上限が変わる仕組み**を持つサービスがあります。
> KDDIがそうかは**未確認**ですが、**1回目の請求で必ず突き合わせれば分かります。**
> いまの文面に絵文字は入っていません。
