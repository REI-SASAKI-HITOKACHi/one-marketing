# A/Bテスト計画：エアコンLP ファーストビュー（案A vs 案B）

作成日: 2026-09-06 / 対象: `lp/aircon/`（パターンA）と `lp/aircon-b/`（パターンB）

公開先は `/aircon/` と `/aircon-b/`。ビルドは両方とも `tools/build-site.py` の `PAGES` に登録済みで、
`python3 tools/build-site.py netlify`（または `php`）で同時に書き出される。

## 何を変えて、何を変えていないか

**変えたのはヒーロー（`<div class="hero">` の中）だけ。** それ以外は1文字も違わない
（`diff lp/aircon/index.html lp/aircon-b/index.html` がヒーロー内の差分しか出さないことで担保している）。

| | パターンA（現行） | パターンB（対抗案） |
|---|---|---|
| 型 | 問題提起型 | 結論提示型 |
| 見出し | フィルターを掃除してもカビ臭い。原因は、内部のカビです。 | エアコン分解洗浄、1台 10,780円／60分。最短即日でうかがいます。 |
| サブコピー | 4行（分解して洗う→60分→最短即日→追加請求なし） | 2行（熱交換器と送風ファンを取り外して洗浄／お見積り以上の追加請求なし） |
| 価格の位置 | 見出し・サブコピーの後 | 見出しの直後（サブコピーより前） |
| 主CTA | かんたん5項目でWEB予約する | この内容でWEB予約する |
| LINE CTA | LINEで無料クーポンを受け取る | LINEで予約する｜防カビコート無料 |

**変えていないもの（AとBで完全に同一）**

- ヒーロー写真、エリア表記のバッジ、価格表示の中身（ノーマル10,780円／60分、お掃除機能付き17,380円／120分）、
  LINE特典の一行（`.perk`）、実績の3枠（98.6%／0円／60分）とその注釈
- Check以降の全セクション（症状チェック、Before/After、作業内容、料金表、シミュレーター、FAQ、フォーム、フッター）
- CSS（トークン定義を含めて完全に同一。配色は今回のテスト対象ではない）、追従バー、フォームの項目
- ページのメタ情報のうち構造（title / description / OG は文言のみパターンBの内容に合わせた）

## 仮説

エアコンクリーニングは、検索・広告クリックの時点で「そろそろ洗浄が必要だ」と自覚している人が多い。
その層に対しては、症状を思い出させる手順（A）を挟まず、**「いくらで・どれくらいの時間で・いつ来て・
何をしてくれるか」を先に出したほうが、判断が早く終わる**のではないか。

Bはこの仮説に立ち、見出しに価格と所要時間を置き、価格ブロックを見出しの直後に上げ、
サブコピーを2行に削って、CTAまでの距離を縮めている。

反対に、Aが勝つ可能性も十分ある。必要性を自覚していない層（広告のディスプレイ面など）が多ければ、
価格を先に出しても「今の自分の話」だと認識されず、症状を提示するAのほうが刺さる。
**どちらが正しいかは事前には決められないので測る**、というのがこのテストの主旨。

## 測定する指標

主指標（LPのCV）は3つの合計。ASPの成果地点は作業完了ベースだが、LP側で観測できるのはここまで。

| 指標 | 取り方 |
|---|---|
| フォーム送信 | サンクスページ（`/<dir>/thanks.html`）到達、またはPHP送信の完了 |
| LINE遷移 | ヒーローと追従バーの `lin.ee` リンクのクリック |
| 電話タップ | `tel:` リンクのタップ＋コールトラッキングの着信数（`docs/tracking-setup.md` の方式Aで、LPごとに別番号を発番すれば A/B の切り分けができる） |

補助指標（勝敗の判定には使わないが、原因の解釈に使う）

- ヒーロー内CTAのクリック率（ページ下部のCTAではなく、FVで決めた人の割合）
- 料金表・シミュレーターへの到達率、平均スクロール深度
- 直帰率、滞在時間

**注意：3つを合計した「CV」で勝敗を決めること。** LINE遷移だけ、電話だけで見ると、
導線の入れ替わり（フォームからLINEへ移っただけ）を改善と誤読する。

## 正直に書いておくこと：この設計では要素を分離できない

Bでは**見出し・サブコピー・CTA文言・価格ブロックの位置を同時に変えている**。
したがってBが勝っても負けても、**「見出しが効いたのか、CTAの文言が効いたのか、価格を上に出したのが
効いたのか」は、このテストからは分からない。**

これは承知のうえでの設計で、段取りは次の通り。

1. **第1段：概念の比較。** 「問題提起型（A）」と「結論提示型（B）」のどちらの筋がいいかだけを見る。
   要素を1つずつ変えるテストは、1本あたり必要な標本が同じだけ要るので、
   先に大きな差が出そうな概念の勝敗を決めたほうが、総トラフィックが少なくて済む。
2. **第2段：勝った側での要素検証。** 勝ったパターンを新しい基準にして、
   要素を1つだけ変えた対抗案を作る（例：見出しはBのまま、CTA文言だけAに戻す）。
   ここで初めて「どれが効いたか」が言える。

第1段の結果を「見出しの勝ち」と書かないこと。言えるのは「概念Bの勝ち」までです。

## 必要なサンプルサイズ

**現時点では未算出。** 確定した数字を出すには、次の2つが要ります（どちらも未確認）。

- **ベースラインのCVR**（現行LPの、上の3指標を合計したCV率）。まだ公開していないため実測値がない。
- **検出したい差の大きさ**（何%の改善なら乗り換える価値があるか）。

参考として、有意水準5%（両側）・検出力80%・両群同数で計算した**1群あたりの必要セッション数**を置いておきます。
実測のベースラインが出た時点で、この表から読むのが早い。

| ベースラインCVR＼検出したい改善（相対） | +20% | +30% | +50% |
|---|---|---|---|
| 2%（2.0%→2.4／2.6／3.0%） | 21,109 | 9,798 | 3,826 |
| 3%（3.0%→3.6／3.9／4.5%） | 13,914 | 6,455 | 2,518 |
| 5%（5.0%→6.0／6.5／7.5%） | 8,158 | 3,780 | 1,471 |
| 8%（8.0%→9.6／10.4／12.0%） | 4,921 | 2,276 | 882 |

読み方の目安。仮にベースライン3%・相対+30%（3.0%→3.9%）を見たいなら、
**1群 6,455セッション＝合計およそ13,000セッション**が要る。
1日100セッションなら65日、1日300セッションなら22日。
現実的に回せる期間と広告出稿量から逆算して、無理なら「+50%以上の差しか見ない」に目標を緩めるか、
主指標をCV（率の低い指標）ではなくヒーローCTAクリック（率の高い指標）に置き換えて
第1段のふるいだけを速く回す、という選択になる。

## 運用の約束ごと

- **期間中に両方のLPを触らない。** 料金改定など、どうしても直す必要が出たら、
  AとBに同じ修正を同時に入れて、その日をログに残す。
- **曜日をまたいで回す。** 最低でも2週間（平日・土日を2周）。途中で覗いて勝敗を決めない。
- **配分は50:50、割り当ては訪問者単位で固定。** リロードのたびに入れ替わると、同じ人が両方を見てしまう。
- 繁忙期（5〜7月・12月）は加算があり客層も動くので、可能なら端境期（4月・8〜11月）に回す。
  またぐ場合は、期間の切れ目でデータを分けて確認する。
