## 何が起きるか

```
和真さんがスマホで入力 → 送信（即時）
   ↓ 毎時のルーティン（42分）
   ├─ ◯月_売上/顧客 タブに1行 追加
   └─ 和真さんのカレンダーに施工の予定を作成
```

**入力は1回だけ。** これまで「カレンダーに予定を入れる」「台帳に書く」の2回だったものが1回になります。

## 決めたこと（2026-09-19 オーナー回答）

| 論点 | 決定 | 理由 |
|---|---|---|
| 反映の速さ | **毎時でよい** | 予約フォームと同じ経路。すでに動いているので今日出せる。オーナーの手が要らない |
| カレンダー | **フォームが予定を作る** | 和真さんの入力が1回で済む。タイトルも自動で規則どおりになるので T035（顧客名を外す）も根本解決 |
| 入力の時期 | **受注が決まった時点** | 議題1の論点そのもの。早く入るほど、打ち手が効いたかを早く判定できる |

## 入力する項目（原則、選ぶだけ）

| | 入れ方 |
|---|---|
| どちらの受注か | ボタン（ワンヒッター／おそうじ本舗） |
| どこからの受注か | ボタン（早期予約／リピート／業務提携／知人紹介／定期便／Web／その他） |
| 提携先・紹介元 | 業務提携・知人紹介を選んだときだけ出る |
| 施工日・開始時刻 | 日付と時刻のピッカー |
| メニュー | 台数を入れるだけ。**本メニュー12種＋オプション16種** |
| 金額 | **自動計算。**値引きしたときだけ手で上書き |
| お名前 | 必須 |
| 住所・電話・郵便番号 | 任意 |
| 現場のメモ | 任意。カレンダーの説明欄に入る |

**必須はこの5つだけです**：どちらの受注か／どこからか／施工日／メニュー／お名前。

### 金額の計算

- 料金は **`data/prices.json`（パンフレットPDFが正）から生成**しています。**手で書き写していません**
- **箇所が2つ以上あるときは「同時施工」の値段**になります
- **繁忙期加算**（5・6・7・12月／1案件 3,300円）を自動で足します
  ※ 2026-09-19 オーナー決定「1案件あたり＋3,300円を上限に」のとおり、箇所ごとには足しません
- 所要時間は、1種目増えるごとに30分ひきます（最大60分まで。2026-09-04 のMTG決定）

### カレンダーの予定

- **タイトル：「地域（区/市） / 施工種類」**。2026-09-04 のMTG決定の形
- **顧客名と金額はタイトルに入れません**（カレンダーを共有したときに外へ出るため）。説明欄に入れます
- 住所は場所欄。終了時刻は所要時間から自動

## 道具

| ファイル | 役目 |
|---|---|
| `tools/build-juchu.py` | フォームを組み立てる（料金は `data/prices.json` から） |
| `tools/deploy-juchu.py` | 社内ホストへ配信。**SMSツールごと、まるごと送る** |
| `tools/juchu-inbox.py` | 届いたものをスプシへ入れ、カレンダーの材料を出す |
| `data/juchu-torikomi.json` | 取り込み済みの送信ID（**タブを増やさないため、ここに持つ**） |
| `data/calendar/juchu-todo.json` | カレンダーに作る予定。毎時のルーティンで作る |

### ⚠️ 配信するときの注意（2026-09-19 に実際に壊しました）

**社内ホストは「まるごと」配信すること。** Netlify は「送ったファイルが全部」なので、
受注フォームだけ送ると、同居しているSMSツール（`s.html`・`qr/`・`robots.txt`）が消えます。
**実際に消して404にしました。** `tools/deploy-juchu.py` は両方を必ず送る作りにし、
`s.html` が見つからなければ中止するようにしてあります。
