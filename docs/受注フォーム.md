# 受注フォーム（和真さんのスマホ用）

オーナー決定（2026-09-19・`MTGシート` 第3回 3-4 議題1）

> **受注フォームアプリを作成する。**
> 売上記録に必要な項目を原則選択式で入力可能なフォームを作成し、
> **スプシとカレンダーの双方に自動反映**させる仕様にする。
> **和真の操作工数をなるべく減らす**設計にする。
> 期限：本日／担当：マーケ部長

## 何が起きるか

```
和真さんがスマホで入力 → 送信（即時）
   ↓ 毎時のルーティン（42分）
   ├─ ◯月_売上/顧客 タブに1行 追加
   └─ 和真さんのカレンダーに施工の予定を作成
```

**入力は1回だけ。** これまで「カレンダーに予定を入れる」「台帳に書く」の2回だったものが1回になります。

## 決めたこと（2026-09-19 オーナー回答）

| 論点 | 決定 | 理由 |
|---|---|---|
| 反映の速さ | **毎時でよい** | 予約フォームと同じ経路。すでに動いているので今日出せる。オーナーの手が要らない |
| カレンダー | **フォームが予定を作る** | 和真さんの入力が1回で済む。タイトルも自動で規則どおりになるので T035（顧客名を外す）も根本解決 |
| 入力の時期 | **受注が決まった時点** | 議題1の論点そのもの。早く入るほど、打ち手が効いたかを早く判定できる |

## 入力する項目（原則、選ぶだけ）

| | 入れ方 |
|---|---|
| どちらの受注か | ボタン（ワンヒッター／おそうじ本舗） |
| どこからの受注か | ボタン。**売上シート D列の19個をそのまま**（`data/ryunyu-keiro.json`） |
| 提携先・紹介元 | 業務提携／紹介／入札案件／スケジュールマッチング／楽ラクーン のときだけ出る。**台帳から作ったプルダウン**（表記ゆれ防止）＋「新しい先を入れる」 |
| 施工日・開始時刻・**終了時刻** | 日付と時刻のピッカー。終了は所要から自動で入り、手で直せる |
| **その日の既存の予定** | 施工日を入れると出る。時間が重なると赤で警告（ダブルブッキング防止） |
| メニュー | **大きい ＋ − ボタン**で数量。直接入力も残してある |
| 金額 | **自動計算。**ワンヒッターと本舗で別の料金表。値引きしたときだけ手で上書き |
| **ヒアリング** | チェックボックス。エアコン・家電のときだけ出る項目がある |
| お名前 | 必須 |
| 住所・電話 | 任意。**郵便番号の欄は無い**（住所から自動で入る） |
| 現場のメモ | 任意。カレンダーの説明欄に入る |

**必須はこの5つだけです**：どちらの受注か／どこからか／施工日／メニュー／お名前。

### 金額の計算

**上の「どちらの受注か」で料金表が切り替わります。** 料金は生成元から入れており、**手で書き写していません**。

| | ワンヒッター | おそうじ本舗 |
|---|---|---|
| 料金の出どころ | `data/prices.json`（パンフレットPDFが正） | `data/prices-honpo.json`（**本部の公式サイト**が正） |
| メニュー | 本メニュー12種＋オプション16種 | 本メニュー15種＋オプション38種 |
| まとめ引き | **箇所が2つ以上で「同時施工」価格** | **壁掛けエアコン2台以上で1台あたり2,200円引き**（本部のまとめ割）<br>追い焚き配管は、浴室も一緒のときだけ同時施工価格 |
| キャンペーン | — | チェックを入れると壁掛けエアコンが本部のキャンペーン価格に |
| 繁忙期加算 | 5・6・7・12月／**1案件 3,300円** | **付けない。**本部は「土日祝の割増なし・汚れ具合による追加なし」 |

- 繁忙期加算は 2026-09-19 オーナー決定「1案件あたり＋3,300円を上限に」のとおり、箇所ごとには足しません
- 所要時間は、1種目増えるごとに30分ひきます（最大60分まで。2026-09-04 のMTG決定）
- **本舗のセット価格**（水まわり3点 55,000円など）は期間限定のものが混ざるため入れていません。
  セットで受けたときは「実際の金額」へ手で入れてください

### 提携先・紹介元はプルダウン（2026-09-19 オーナー指示）

> 提携先はプルダウン選択へ（表記ゆれ防止）。新規入力欄もほしい

- 選択肢の**正は『【毎月更新】リピート/業務提携』タブの B列「企業名」**。手で書き写しません
- 並び順は『提携先_休眠度』タブの**最終発注が新しい順**（よく出る先が上に来ます）。いま19件
- 一覧に無い先は「**＋ 新しい先を入れる（一覧に無い）**」を選ぶと入力欄が出ます
- 新しい名前で届くと `tools/juchu-inbox.py` が🔴で知らせます。
  **台帳のB列に足してから** `build-teikei-list.py` → `build-juchu.py` → `deploy-juchu.py`

### ⚠️ 本舗の料金が変わったとき（2026-09-19 オーナー指示）

> 本舗はキャンペーンごとに料金が変わっていくから料金の変更が生じた際にはLINEで和真が君へ知らせるよ。
> 知らせがあった時にはその時々の最新情報を確認して料金設定へ反映させるように都度対応してね。

**和真さんからLINEで知らせが来たら、その場で次をやること**（オーナーの確認は要りません）。

1. **本部の公式サイトで、いまの料金を自分で確認する**（和真さんの伝言だけで直さない。出所は下記URL）
2. `data/prices-honpo.json` を直す。**`取得日` も今日の日付に更新する**
3. `python3 tools/build-juchu.py` → `python3 tools/deploy-juchu.py`
4. 和真さんにLINEで「反映しました」と返す。変えた項目と金額を書く
5. 変更履歴をコミットに残す（何が何円から何円になったか）

キャンペーン価格は**フォームのチェックボックス**（「本部のキャンペーン価格で受けた」）で
切り替える作りなので、正規価格とキャンペーン価格の**両方**を入れてください。
`build-juchu.py` は流すたびに `取得日` を表示します。古ければそこで気づけます。

### ヒアリング（2026-09-19 オーナー指示）

チェックを入れた項目は「✓」、入れなかった項目は「未確認：」として、
台帳の備考欄とカレンダーの説明欄の両方に入ります。

| 項目 | 出る条件 |
|---|---|
| 駐車場が確保できる | いつも |
| 電気・水道をお借りする許可を得た | いつも |
| エアコンの下にある物の移動を依頼した | **エアコン**を選んだとき |
| パーツの洗い場として浴室をお借りする承諾を得た | **エアコン**を選んだとき |
| 保証年数を確認した（9年まで／洗濯機は7年まで） | **家電**（エアコン・洗濯機・冷蔵庫・食洗機・乾燥機・空気清浄機）を選んだとき |

### 郵便番号（欄を無くしました）

オーナー指示「郵便番号欄は不要。住所入力からスプシへ郵便番号を自動反映させてほしい」。

- 引くのは**取り込みのとき（サーバ側）**です。`tools/yubin.py`
- 索引 `data/postal-index.json`（東京都・千葉県・神奈川県／18,150件・約850KB）は
  **端末へ送りません**。送ると和真さんのスマホが毎回850KB読むことになります
- 精度は**町域まで**。同じタブに人が入れた「郵便番号＋住所」があれば、そちらを優先します
- 索引の作り直しは `python3 tools/build-postal-index.py`（出所：HeartRails Geo API。
  日本郵便の KEN_ALL はこの環境から落とせませんでした）

### 既存の予定（ダブルブッキング防止）

- 施工日を入れると、**その日に入っている予定**が出ます
- 開始〜終了が重なると、赤い警告が出ます（止めはしません。確かめてもらうため）
- 元は `data/calendar/watanabe-events.json`（毎時のルーティンが取っているもの）。
  **氏名・住所・金額は入っていません**。時刻と件名だけです
- フォームが読むのは `lp/juchu/yotei.json`（約1.4KB）。**描画のあとで読む**ので、起動は待ちません
- ★**毎時のルーティンで `build-juchu.py` → `deploy-juchu.py` を流すと、予定が最新になります**

### カレンダーの予定

- **タイトル：「地域（区/市） / 施工種類」**。2026-09-04 のMTG決定の形
- **顧客名と金額はタイトルに入れません**（カレンダーを共有したときに外へ出るため）。説明欄に入れます
- 住所は場所欄。終了時刻は**フォームで入れた値**（空なら所要時間から自動）
- ヒアリングの結果も説明欄に入ります

### ⚠️ 配信するときの注意（2026-09-19 に実際に壊しました）

**社内ホストは「まるごと」配信すること。** Netlify は「送ったファイルが全部」なので、
受注フォームだけ送ると、同居しているSMSツール（`s.html`・`qr/`・`robots.txt`）が消えます。
**実際に消して404にしました。** `tools/deploy-juchu.py` は両方を必ず送る作りにし、
`s.html` が見つからなければ中止するようにしてあります。
