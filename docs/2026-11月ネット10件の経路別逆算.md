## 数え方の規則（2026-10-18 決定・planning）

**問い：公式LINE 経由の Web予約（`src=line`。例：10/17 申込・10/18 施工の 久木元様）をネットに数えるか → 数える。**

| | 規則 |
|---|---|
| ① ネット経由（主の指標） | **予約ページ・LP のフォーム・HP のフォームから申し込んだ受注**。入口（src）が広告・地図検索・HP・**公式LINE のリッチメニュー・SMS のリンク**のどれでも数える |
| ② 数えないもの | 公式LINE の**トーク**・SMS への**返信**・**電話**で頼まれた受注（Web の申込を通っていない） |
| ③ うち新規（副指標） | 申し込んだ時点で**顧客管理台帳にいない人**（電話番号で照合）。入口は問わない。久木元様・長田様は新規 |
| ④ 月次タブの流入経路の書き方 | 予約ページ経由は **src の経路で書く**：`gads_*`→「広告」／`line`→「LINE」／`sms*`→「SMS」／`gbp*`→「地図検索」。**「LINE」「SMS」は予約ページ経由の予約にだけ使う**（トーク・電話・返信の依頼は「リピート」「早期予約」など）。こうすると月次タブの流入経路だけで機械的に数えられる |
| ⑤ 例外 | 10/3 の長田様（広告→LP→公式LINE→予約ページ）は、オーナー判断（10/3）どおり「広告」のまま。二重に数えない |

- **理由**：公式LINE の友だちは既存客だけではない（長田様・久木元様は新規）。リッチメニューは予約ページへのリンクで、申込は Web で完結している。オーナー目標の言い方「WEB受注」にも合う（CMO 10/15 決定の「既存客の予約ページ経由も含む」と同じ線）
- **反映**：`tools/chakuchi-shuukei.py` の NET に「LINE」「SMS」を足した（着地集計の「ネット経由」がこの規則で出る）。`tools/net11-tsuiseki.py` も同じ
- **この規則で 10月を数え直すと**：10/18 09:54 の着地で **10月のネット経由は 4件 → 5件**（広告4＋LINE 1＝久木元様 ¥9,702）。11月は0件のまま。白川様（Google広告・/aircon-e/・10/20）は受注フォームの後に「広告」で1件増える

## いちばん効く1点

**広告の「LP表示 → 予約ページ表示」**（5% → 直し後 8%）。
- 8%が続けば広告は月7件。**15%まで上がれば月12件前後**で、広告だけで新規10件に届く（measurement の逆算）。
- /aircon/ は C対E のテスト中なので触らない。**水まわりLP・年末LPの主ボタンの文言と位置を lp が直す**（CMO 指示済み）。
- **GBP は来ている人（14日で11人）が全員入力せずに離れている。** 着地を直すだけで1件取れる見込み。
