# 広告LPの「申込の入口」直し案（2026-10-09・依頼 20261008-05-lp）

画面：`docs/img/LP-入口の直し案-前後.jpg`（上段＝今の本番、下段＝直し案。左から aircon・mizumawari・aircon-c・mizumawari-b、390px幅の最初の画面）

## 何が起きているか（measurement 判定表 10/9）
| ページ | 閲覧 | フォーム入力開始 | 開始率 |
|---|--:|--:|--:|
| /aircon/ | 49 | 1 | 2% |
| /aircon-c/ | 34 | 2 | 6% |
| /mizumawari/ | 68 | 2 | 3% |
| /mizumawari-b/ | 14 | 0 | 0% |
| 予約ページ | 4 | — | 申込1 |

- LPを見た人の 94〜100% が、LP内のフォームに手を付けずに離れている
- 水まわりは 76人中 50%まで読んだのが8人（10/1 GA4）。**入口は「最初の画面」と「画面下の固定バー」にないと届かない**
- 申込5件のうち2件は予約ページ（LINE→予約ページ、予約ページ直接）。予約ページは空き日・料金・入力が1か所で済む

## 直し方（CMOの3案のうち ①＋③ を採る）
**主な入口を「予約ページ（空いている日と料金が見られるカレンダー）」にし、LP内フォームは2つ目の道として下に残す。**
ボタンの数は増やさず、行き先と文言だけを変える（ファーストビューの高さ・見た目は変えない）。

| 場所 | 今 | 直し案 |
|---|---|---|
| ヘッダーの「WEB予約」 | LP内フォームへ | **予約ページへ** |
| 最初の画面の主ボタン | aircon「かんたん5項目でWEB予約する」／mizumawari「箇所を選んで、料金を見る」／学習版「よくある頼み方と金額を見る」 | **「空いている日を見て予約する」**（mizumawari は「空いている日と料金を見る」）→予約ページ。学習版の「よくある頼み方と金額を見る」はその下の文字リンクに |
| 画面下の固定バーの右ボタン | 「WEB予約する（入力5項目）」／「料金を見る」 | **「空き日を見る」**→予約ページ（スマホで常に出ている＝③） |
| 料金計算の下（今の版） | 「この内容で予約に進む」→フォーム | **2択**：「空いている日を見て予約する」（予約ページ）／「この内容でフォームから申し込む」（学習版は 10/1 から2択） |
| LP内フォーム | — | そのまま残す（電話番号だけ送って日程は連絡で、という人の道） |

- 今の版2本はヒーローが長く、主ボタンは最初の画面の外（1245px・1289px）。**固定バーの「空き日を見る」が最初の画面の入口になる。** 学習版2本は主ボタンが最初の画面の中（697px・726px）
- **②（LP内フォームを3項目に）は今回は採らない。** 主な入口を予約ページにするので、フォームを2画面に作り直す手間に見合わない。予約ページの入力項目のほうを見直すほうが効く（予約ページは lp の持ち物。次の段で）

## 数え方（版ごとに比べられる）
- 予約ページへのクリック：`cta_click`（link_target=yoyaku、link_position=header / hero / sticky / estimate / form）。今の版にも同じ計測を足した
- どのLPから来たか：予約ページへのリンクに `lp=<ページ名>`（b03a1288）。予約_Web にも残る
- 見る数字：**LP閲覧 → 予約ページへのクリック率 → 予約ページの申込**（LP内フォームの入力開始率と並べる）
- ⚠ 予約ページの「ボタンの場所」は GA4 のカスタムディメンション link_position の登録が要る（measurement）
