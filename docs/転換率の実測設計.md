# 申込から受注までの転換率を、どう測るか

- 2026-09-19 CMO。広告が動き出す前に、測る形だけ決めておく
- **いま測れません。母数がゼロだからです。**そのことを先に書きます

## 0. 🔴 まず、いちばん大事な事実

**`予約_Web` タブの申込は、2026-09-19 現在で 0件です。**

Webの予約フォームは公開されていて、Netlify の受け口も新旧そろっていますが、
**これまで1件も通っていません。** 毎時のルーティンでも `未取り込み: 0件` が続いています。

**つまり：**

1. **転換率は、まだ1度も測られたことがありません**（分母が無い）
2. **申込から売上までの経路は、実物で1回も通っていません**（配管はあるが水が流れていない）
3. **最初の1件が、経路そのものの試験になります**

## 1. 配管はできています（crm が作った列）

`予約_Web` の列。**★の6列が、申込と台帳を結ぶために足されたもの**です。

```
受信日時／状態／お名前／お電話番号／ご住所／ご希望日／ご希望時刻／ご希望の内容／
所要(分)／概算金額／ご要望／流入元／カレンダー登録／NetlifyのID／src／cid／
★台帳の顧客ID／★台帳の名義／★台帳の最終施工日／★照合の手がかり／★属性／★売上行への参照
```

- **`src` と `cid`** … 広告の出どころ（`gads_aircon` 等）とクリックID
- **`★売上行への参照`** … ここが埋まれば、**申込1件が売上1行に結びつきます**
- 状態の初期値は **`未確認`**（`tools/booking-inbox.py`）

**足りないものは、いまのところ見当たりません。**問題は「作りが足りない」ではなく「通っていない」ことです。

## 2. 測る段（ファネル）

| # | 段 | どこで分かるか | いま取れるか |
|---|---|---|---|
| 1 | **広告の表示・クリック** | Google 広告 | ○ |
| 2 | **着地ページの到達** | GA4（`?src=` → `traffic_src`） | **計測担当が確認中** |
| 3 | **申込**（フォーム送信） | `予約_Web` の1行 ＋ GA4 のキーイベント | ○ |
| 4 | **電話がつながった** | `状態` を `未確認` から進める | **運用が未定** |
| 5 | **日程確定** | `カレンダー登録` が `登録済` | ○ |
| 6 | **施工完了** | 月次タブ（施工日付ベース） | ○ |
| 7 | **入金** | 月次タブ | ○ |

**転換率は、この段のあいだの比です。**いちばん知りたいのは **3→7（申込→入金）**。

## 3. ⚠ 11/1 の増額判断に、穴があります

planning の 11/1 の表は **CPA（コンバージョン1件あたりの費用）** で線を引いています。

| 10月の実績（月5万） | CPA | 判断 |
|---|--:|---|
| 6件以上 | ≤ ¥8,333 | 段1へ |
| 4〜5件 | ¥10,000〜12,500 | 据え置き |
| 3件以下 | ≥ ¥16,667 | 止めて設計に戻す |

**この表の「件」は、コンバージョン＝申込です。受注ではありません。**

**申込がすべて受注になるなら、CPA と CPO（受注1件あたり）は同じです。ですが同じではありません。**
電話でエリア外が分かる、日程が合わない、金額で折り合わない ―― **必ず落ちます。**

> **申込→受注が 60% なら、CPA ¥8,333 の実態は CPO ¥13,889 です。**
> **限界利益 32,362円 に対しては、それでもまだ安全側**ですが、**表の意味が変わります。**

**いま、この率は誰も知りません。** 実績がゼロだからです。

### 置き方（CMO・2026-09-19）

**11/1 の表は「CV件数」のまま使います。作り直しません。**
理由：**限界利益 32,362円 に対して CPA ¥8,333 は4倍近い余裕**があり、
**転換率が5割でも判断はひっくり返りません。**

**ただし、表に但し書きを付けます。**

> この表の「件」は**申込**であって受注ではない。**申込→受注の率は 2026-09-19 時点で未実測。**
> 実測が出たら、**CPO で引き直す。**

## 4. 最初の1件で、何を確かめるか

**最初の申込は、数字ではなく試験です。**下が全部通って、はじめて「経路がある」と言えます。

| 確かめること | 通っていない場合に起きること |
|---|---|
| Netlify の受け口に入るか | **申込が消える** |
| `booking-inbox.py` が拾うか | 気づかないまま溜まる |
| `予約_Web` に1行増えるか | 台帳に残らない |
| **`src` と `cid` が入るか** | **どの広告から来たか永久に分からない**（母の日と同じ） |
| 和真さんのカレンダーに【仮】が入るか | 二重予約 |
| GA4 のキーイベントが立つか | 広告の最適化が効かない |
| Google 広告にコンバージョンが返るか | 同上 |

**「申込が来たら喜ぶ」ではなく、「来たらこの7つを見る」を決めておきます。**
