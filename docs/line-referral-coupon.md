### ⚠️ ここが効いてきます

**友だち330人に一斉配信すると、月200通の無料枠を130通ぶん超えます。**

- 通数は「送った**人数**」で数える。330人に1回で330通
- コミュニケーションプラン（現行）は月200通まで無料
- 超えるならライトプラン（月5,500円・税込／5,000通）への変更が要る＝**お金を使う話**

**紹介クーポンは「該当する人だけ」に送るので、月に数通〜数十通で収まります。問題ありません。**
効いてくるのは「友だち全員へのお知らせ」をやりたくなったときです。そのときは費用の判断が要ります。

## 2.5 🚨 公式LINEも、送る前に名義を照合します（2026-09-11 追加）

**公式LINEはワンヒッター名義です。本舗のお客様には出しません。**

2026-09-11、本舗名義のお客様3名にワンヒッターのSMSが届く事故がありました。
同じことがLINEでも起きうるので、`tools/line_client.py push` に照合を入れました。

```bash
# お客様あて … --tel か --name が必須。台帳の最新の施工名義と照合する
python3 tools/line_client.py push --to <userId> --name "山田　太郎" \
  --coupon 01JWGRWJ9XP59WS2T1GY1944Y7 --confirm SEND

# 社内（嶺・和真・CMO）あて … 照合を省く。★お客様には使わない
python3 tools/line_client.py push --to <userId> --internal --text "..." --confirm SEND
```

止まり方を実際に確かめました。

| 状況 | 結果 |
|---|---|
| `--tel` も `--name` も無い | **送らない**（「名義の照合に使います」と出て終了） |
| 台帳＝本舗のお客様 | **送らない**（「公式LINEはワンヒッター名義です」と出て終了） |
| 台帳＝自社のお客様 | 通る（`名義の照合: OK（台帳=自社（最新施工 2026-01-11））`） |
| 台帳が読めない | **送らない** |

本文の中身も見ます。ワンヒッター名義の本文に「おそうじ本舗」や本舗の受付番号が
混ざっていれば止まります。照合は `tools/meigi_check.py`（SMSと同じものを使っています）。

## 3. 本当の難所は、クーポンではなく「誰の紹介か」

クーポンは既にあります。**足りていないのは受付の運用です。**
`docs/cmo-savedata.md` の判断待ちにある
「1,000円割引の制度はあるが、誰の紹介かを記録する運用が未整備」が、そのまま残っています。

技術的な制約が1つあります。**LINEのユーザーIDは、台帳の顧客IDと繋がりません。**
（ユーザーIDはプロバイダーごとに違う値が振られる）

なので紹介の起点を **「ご予約の受付」** に置きます。今日から回せます。

```
① 新規のお客様がご予約
   → 受付（和真さん）が必ず1つ聞く
     「どちらでお知りになりましたか？ どなたかのご紹介でしたらお名前を伺えますか」
        ↓
② 顧客管理台帳の流入経路に「紹介」＋紹介者名を書く
        ↓
③ 施工が完了した時点で、紹介者へクーポンを送る（couponId は上の表のもの）
        ↓
④ キャッシュバックは口座振込なので、振込先の確認が要る
```

### なぜ「施工が完了した時点」なのか

予約の時点で配ると、キャンセルされたときにクーポンだけが残ります。
**終了させると獲得済みの方も使えなくなる**ので、あとから取り消すとお客様との関係を壊します。

### 送り方

```bash
. ~/.config/one-hitter/line.env
python3 tools/line_client.py push --to <紹介者のLINEユーザーID> \
  --text "ご紹介ありがとうございました。" \
  --coupon 01JWGRWJ9XP59WS2T1GY1944Y7 --confirm SEND
```

`--confirm SEND` が無いと送りません。
**お客様への配信は「外に出す」ので、対象と文面が固まったらCMOへ依頼を出します。**

## 4. 詰まっているところ

| | 内容 |
|---|---|
| **紹介者のLINEユーザーID** | 台帳と繋がらない。受付で名前を聞き、LINEのトーク上で本人に名乗ってもらう運用が要る |
| **口座情報** | キャッシュバックは振込。振込先をどこで受け取り、どこに保管するか未整備。**LINEのトークで受け取ると個人情報がwebhook経路に乗る**（署名検証が無いので流さないこと） |
| **制度の食い違い** | §2のとおり。オーナー確認待ち |
| Webhook | `docs/line-api-setup.md` §3-3 のとおり、オンにすると既存のあいさつ・自動応答の挙動が変わる可能性がある。**当面オフのまま、配信だけで運用する** |

## 5. APIの仕様（つまずいたところを残す）

公式リファレンスのページはJavaScriptで描画されて読めません。
**LINE公式のOpenAPI定義を見てください。**

```
https://raw.githubusercontent.com/line/line-openapi/main/messaging-api.yml
```

9/06 の下書きは4か所間違えていて、HTTP 400 を返されました。

| | 間違い | 正しい |
|---|---|---|
| 日時 | ミリ秒 | **epoch秒** |
| timezone | `Asia/Tokyo` | **`ASIA_TOKYO`** |
| visibility | `PRIVATE` | **`UNLISTED` か `PUBLIC` の2つだけ** |
| maxUseCountPerTicket | 書いていなかった | **必須**（最大1／無制限は -1） |

**エラーは `{"message":"Internal Server Error"}` としか返りません。** どこが悪いか教えてくれないので、
YAMLと1項目ずつ突き合わせるしかありません。推測でプロパティ名を足さないこと。
