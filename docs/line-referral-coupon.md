## 1. 制度のおさらい（2つを混同しないこと）

| 誰の紹介か | 金額 | 誰が得をするか |
|---|---|---|
| **消費者 → 消費者** | **一律1,000円** | 紹介した本人の次回料金から割引 |
| 事業者 → 顧客 | 5〜15%（原則12%） | 紹介手数料として事業者へ支払う |

**LINEのクーポンで扱うのは上だけです。**
下は事業者との精算なので、クーポンではなく請求で処理します。
（レジェンド様・タカラサービス様・エコハウス様は手数料不要）

根拠は `data/prices.json` の `紹介`。

> ⚠️ スプレッドシートの「見積ルール」タブには
> 「紹介料 1-2月:5%／その他:10%」という**古い記載が残っています。**
> 実際に運用しているのは上の表です。修正はCMOスレッドのTODO（判断待ち項目）に入っています。

## 2. いちばんの難所 ——「誰の紹介か」をどう掴むか

`docs/cmo-savedata.md` の判断待ちに
「1,000円割引の制度はあるが、誰の紹介かを記録する運用が未整備」とあります。**ここが本丸です。**

技術的な制約が1つあります。**LINEのユーザーIDは、こちらの台帳の顧客IDとは繋がりません。**
（ユーザーIDはプロバイダーごとに違う値が振られるため、`docs/line-api-setup.md` §で「要設計」とされている点）

なので、**紹介の起点を「ご予約の受付」に置きます。** LINE側で紹介者を当てにいくのではなく、
受付で聞いたことをLINEに繋ぎます。これなら今日からでも回せます。

### 運用フロー（v1・Webhookなしで回る）

```
① 新規のお客様がご予約 → 受付（渡辺さん）が必ず1つ聞く
   「どちらでお知りになりましたか？ どなたかのご紹介でしたらお名前を伺えますか」
        ↓
② スプレッドシート「顧客管理台帳」の流入経路に「紹介」＋紹介者名を書く
        ↓
③ 施工が完了した時点で、紹介者へ1,000円クーポンを送る（CMO側／自動）
        ↓
④ 紹介者が次回ご予約 → クーポン画面を提示 → 1,000円割引
```

**③だけがこちらの仕事です。** ①②は今の受付作業に一言足すだけで済みます。

### なぜ「施工が完了した時点」なのか

予約の時点で配ると、キャンセルされたときにクーポンだけが残ります。
**作成したクーポンは修正できず、終了させると獲得済みの人も使えなくなります**（公式の仕様）。
配ったあとに取り消すのはお客様との関係を壊すので、完了してから配ります。

### v2（Webhookを有効にしたあと）

- 友だち追加のあいさつで「ご紹介で1,000円割引」を案内する
- 「紹介」と送ると自動でご案内を返す（応答メッセージは**通数にカウントされません**）
- 紹介者のLINEユーザーIDを、初回のやり取りで台帳の顧客IDに紐づけておく

> ただし `docs/line-api-setup.md` §3-3 のとおり、**Webhookをオンにすると既存のあいさつ・
> 自動応答の挙動が変わる可能性があり、公式に明記がありません。**
> なので **v1は「配信だけ」で走らせ、Webhookは後回しにします。** これは調査担当の判断を踏襲しています。

## 3. クーポンの中身

`data/line-coupon-referral.json` に置いてあります。

| 項目 | 値 | 理由 |
|---|---|---|
| 割引 | 固定1,000円 | `data/prices.json` の `紹介.消費者から消費者` |
| 期間 | 2026-11-01 〜 2027-01-01 | 年末商戦をまたぐ。**1〜2月は早期予約割引15%があるので、そちらと併用させない** |
| 併用 | 不可（説明文に明記） | 早期予約15%と1,000円を重ねると、閑散期の単価が落ちすぎる |
| 公開範囲 | 紹介者だけに配る | 全員に配るものではない |

### 作る手順（★作成後は修正できません）

```bash
# 1. 中身を見る（トークン不要・作成しない）
python3 tools/line_client.py coupon-create --file data/line-coupon-referral.json --dry-run

# 2. 作る
python3 tools/line_client.py coupon-create --file data/line-coupon-referral.json --confirm CREATE

# 3. couponId を控えて、一覧で確認
python3 tools/line_client.py coupon-list
```

> **最初の1件は必ずテスト用（短期間）で作り、オーナーの端末で表示を確認してから本番を作ります。**
> リクエストの一部のプロパティ名は公式リファレンスがJavaScript描画で読めず、未確認のままです。
> **エラーが返ってきたら、その本文を読んで直します。推測でプロパティを足しません。**

### 配る

```bash
python3 tools/line_client.py push --to <紹介者のLINEユーザーID> \
  --text "ご紹介ありがとうございました。次回1,000円割引のクーポンをお送りします。" \
  --coupon <couponId> --confirm SEND
```

`--confirm SEND` が無いと送りません。

## 4. 費用

**コミュニケーションプラン（現行）は月200通まで無料。** Messaging APIの利用料はありません。

- 通数は「送った**人数**」で数える。友だち100人へ1回配信すれば100通
- **応答メッセージ（相手の発言への返信）はカウントされない**
- 紹介クーポンは「該当する人だけ」に送るので、**月に数通〜数十通**で収まる

つまり **紹介クーポンの運用は、追加費用ゼロで始められます。**
月200通を超えそうになったらライトプラン（月5,500円・税込／5,000通）ですが、
その判断が要るのは冬季の一斉配信をLINEでやる場合だけです。

`python3 tools/line_client.py quota` で今月の残りが見られます。

## 5. SMSとLINEの関係（コストの話）

| | 1通あたり | 備考 |
|---|---:|---|
| SMS（KDDI Message Cast） | 9.35円〜 | 到達課金。70文字ごとに課金通数が増える |
| **LINE** | **0円** | 月200通まで。それ以上は約1.1円/通 |

**SMSは「LINEに引き込むための入口」です。**
冬季SMSの第2便（`data/sms-templates.json` の L1）は、まさにこれを狙っています。

93名にSMSを送るのに約2,100円。そのうち10名がLINEの友だちになれば、
**その10名への以後の配信は永久に無料**になります。友だち数を増やすことが、そのまま原価の削減になります。
