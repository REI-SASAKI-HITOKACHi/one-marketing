## 3. 紹介の受付運用（2026-09-11 CMO回答で確定）

### 制度はこれです

| 紹介元 | 内容 |
|---|---|
| **消費者 → 消費者** | **紹介した本人の次回料金から一律1,000円割引。** 公式LINEでクーポンを配る |
| 事業者 → 顧客 | 紹介手数料 5〜15%（原則12%）。レジェンド様・タカラサービス様・エコハウス様は不要 |

**キャッシュバック（口座振込）ではありません。** 振込先を受け取る仕組みは要りません。
`data/prices.json` の `紹介.消費者から消費者 = 定額1,000円` と一致します。

### 🚨 ただし、稼働中のクーポンがこの制度と違います

`01JWGRWJ9XP59WS2T1GY1944Y7`「紹介キャッシュバック_One Hitter」は **`reward.type = cashBack`** で、
説明文に「**ご指定の口座へのお振込**となります」「紹介人数に上限はありません」
「★紹介先割引￥1,000/回」と書かれています。2025年6月から動いています。

**このまま配ると、確定した制度と違うことをお客様に伝えることになります。**

APIにクーポンの獲得数・利用数を返す項目はありません（OpenAPI定義で確認）。
**すでに何人が持っているかは、こちらからは分かりません。**

> **2026-09-11 オーナー：「振込なんてクーポン無いと思うけどな…。いずれにせよ使った人は
> いないから気にしなくていい。万が一持ってる人がいたら振り込むよ」**
>
> 記録として残しておきます。**クーポン自体は実機に確かに存在します**
> （`reward.type = cashBack`／説明文に「ご指定の口座へのお振込」と明記／
> 2025-06-01 から `RUNNING`）。作られた経緯までは分かりません。
> **利用実績はオーナーの認識のとおり無いものとして扱い、万が一の提示には振込で応じます。**

##### 新クーポンで、意識して書かなかったこと

旧クーポンの説明文にあった次の3つは、**制度に無いので書いていません。**

- 「キャッシュバック」「ご指定の口座へのお振込」 … 制度が違う

- 「紹介人数に上限はありません」 … 制度に無い

##### 作ってみて分かったこと

`maxTicketPerUser` は `CouponCreateRequest` に無いプロパティなので指定できませんが、
**作成後に確認したら `1` が入っていました**（既定値）。1人1枚で意図どおりです。

### 運用（今日から回せます）

```
① 新規のお客様がご予約
   → 受付（和真さん）が必ず1つ聞く
     「どちらでお知りになりましたか？ どなたかのご紹介でしたらお名前を伺えますか」
        ↓
② 顧客管理台帳の流入経路に「紹介」＋紹介者名を書く
        ↓
③ 施工が完了した時点で、紹介者へクーポンを送る
        ↓
④ 紹介者が次回ご予約 → クーポン画面を提示 → 1,000円割引
```

**③だけがこちらの仕事です。** ①②は受付に一言足すだけで済みます。

#### なぜ「施工が完了した時点」なのか

予約の時点で配ると、キャンセルされたときにクーポンだけが残ります。
**終了させると獲得済みの方も使えなくなる**ので、あとから取り消すとお客様との関係を壊します。

#### 送り方

```bash
. ~/.config/one-hitter/line.env
python3 tools/line_client.py push --to <紹介者のLINEユーザーID> \
  --name "<紹介者の氏名>" \
  --text "ご紹介ありがとうございました。" \
  --coupon <couponId> --confirm SEND
```

`--name`（か `--tel`）が無いと送りません。台帳＝本舗の方にも送りません（§2.5）。
**お客様への配信は「外に出す」ので、対象と文面が固まったらCMOへ依頼を出します。**
