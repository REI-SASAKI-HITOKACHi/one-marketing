# 公式サイト ブログ原稿の置き場と形式

公式サイト（`https://one-hitter.jp/blog/`）に載せる記事の原稿。**Markdown 1ファイル＝記事1本。**
LP担当の投稿ツール（20260912-05-lp）は、この形式を入力にする。形式を変えるときは lp と web-inflow の両方に掲示板で通す。

## 流れ（CMO決定 20260912-08）

原稿（web-inflow）→ cmo 査読 → LP担当の道具で**非公開作成** → プレビューを cmo が確認 → 公開。
最初の1本だけオーナー承認。以後は cmo 査読で自動（SNSと同じ）。

- 頻度：**週1本、毎週水曜に公開**
- 型：事例研究（現場1件＝1本）を基本に、月1本は読本の要約（赤ちゃん版・ペット版・季節もの）
- ネタは SNS（`docs/sns-投稿原稿/`）と共有してよいが、文章は書き分ける（SNSは1画面、ブログは検索で読まれる800〜1,500字）

## ファイル名

```
docs/blog/YYYY-MM-DD-<slug>.md
```

- `YYYY-MM-DD` は**公開予定日（水曜）**。front matter の `date` と一致させる
- `<slug>` は半角英数とハイフン。地名とメニューと中身が分かる程度（例：`edogawa-aircon-fin-and-louver`）。公開URLに使えるならそのまま使う

## front matter（YAML）

| フィールド | 必須 | 内容 |
|---|---|---|
| `title` | 必須 | 記事タイトル。全角60字程度まで。地名1つ＋メニュー1つまで（詰め込まない） |
| `date` | 必須 | 公開日 `YYYY-MM-DD`（水曜） |
| `category` | 必須 | `事例研究` / `読本` / `お知らせ` のいずれか1つ |
| `eyecatch` | 必須 | アイキャッチの写真ファイル名（`assets/photos/` 直下。例：`IMG_8033.jpg`）。**作業前の写真を使う**（汚れが伝わるほう） |
| `description` | 必須 | 検索結果に出る要約。全角120字以内。本文の先頭の言い直しにしない |
| `tags` | 任意 | サイト既存のタグ名を配列で（`江戸川区` `船堀` `浦安市` `ハウスクリーニング` など）。既存タグは `docs/blog/既存記事一覧.md` |
| `source` | 任意 | 元にした現場記録（`data/zukan/<id>.json`）と出典ファイル |
| `notes` | 任意 | 投稿時の注意（写真のトリミング指示など）。**サイトには出さない** |
| `status` | 任意 | `draft` / `reviewed` / `published`。省略時は `draft` |

例：

```yaml
---
title: "江戸川区のエアコンクリーニング事例｜吹き出し口の黒い筋と、灰色になった熱交換器"
date: 2026-09-16
category: 事例研究
eyecatch: IMG_8033.jpg
description: "2026年9月、江戸川区の壁掛けエアコン1台。フィルターを外した先の吹き出し口と熱交換器に何が付いていて、分解洗浄でどこまで落ちたかを写真で。料金は10,780円（税込）。"
tags: [江戸川区, ハウスクリーニング]
source: data/zukan/2026-09-09-aircon.json
status: draft
---
```

## 本文

- **800〜1,500字**（front matter を除き、見出し・写真行・URLを除いた本文の文字数。`tools/` に数える道具ができるまでは `python3 -c` で数える）
- 見出しは `##` から（`#` は使わない。タイトルが h1 になる）。`###` までにする
- 短い文。「私たち」の一人称でよい。会社名は「ワンヒッター」だけ
- 事例研究の章立て（この順で。章を飛ばすときは理由を `notes` に書く）
  1. 何が起きていたか（お客様の言葉は使わない。特定できる情報は書かない）
  2. 原因として考えられること（事実だけ。断定しない）
  3. どこまで落ちたか（写真）
  4. 作業時間の目安と料金（税込。`docs/price-master.md` から。現場記録に時間が無ければ「目安」と明記するか書かない）
  5. 自分でできる手入れ（メーカー公式・公的機関の一次資料の原文引用のみ。`docs/読本-出典.md` にある引用は使ってよい）
  6. ご予約（1行。下のURL）

## 写真

- `assets/photos/` にある**当社の実物だけ**。Markdown の画像記法で、パスは `assets/photos/` からの相対（ファイル名だけ）

```markdown
![作業前｜吹き出し口のレール](IMG_8033.jpg)
*作業前。レールに黒い筋が並んでいる。*
```

- 画像の直後の `*…*` の1行がキャプション。投稿ツールはこれを figcaption にする
- **作業前と作業後を並べるのは、`data/zukan/<id>.json` の `組写真` に入っている組だけ。** 同じ場所・同じ角度と確認できた組しか入っていない。それ以外を並べて「ビフォーアフター」と書かない
- 組で載せるときは、作業前 → 作業後の順に2枚を続けて置き、alt を `作業前｜…` `作業後｜…` で始める（投稿ツールが横並びにできる）
- 汚水は `汚水｜…` で始める
- 銘板・製造番号・メーカーロゴ・表札・郵便物・私物が写っているものは使わない。トリミングが必要な写真は `docs/photo-inventory*.md` の指示に従い、`notes` に書く
- alt に地名や日付を入れない（本文にある）

## 予約導線（本文の最後に1行）

| メニュー | URL |
|---|---|
| エアコン | `https://one-hitter-lp.netlify.app/aircon/?src=blog` |
| 水回り（レンジフード・浴室・洗濯機・キッチン・トイレ） | `https://one-hitter-lp.netlify.app/mizumawari/?src=blog` |

`?src=blog` は計測担当が GA4 の `traffic_src` で拾う。変えない。

## 書かないこと（SNSと同じ線）

- 除菌・病気・危険・守る・殺菌・抗菌（東京消防庁の原文引用の中だけは可）
- 効果・健康に関する言い切り（「〜が減る」「〜に効く」）。数字は一次資料か現場記録にあるものだけ
- 「ビフォーアフター」（確認済みの組以外）
- お客様が特定できる情報（氏名・住所・建物・使用年数など記録に無いもの）
- 他社名・「おそうじ本舗」・旧電話番号。電話番号はそもそも書かない（LPに任せる）
- AIっぽい定型句：ここからは／お伝えします／いかがでしょうか／ぜひ／安心／大切な／しっかり
- 料金は `docs/price-master.md` の税込価格だけ。「（税込）」を必ず併記。5〜7月・12月の繁忙期加算 3,300円（税込）に触れる

## 査読の頼み方

```
echo "docs/blog/YYYY-MM-DD-<slug>.md を査読してください。文字数 N字、写真 M枚、出典は docs/読本-出典.md #x #y" \
  | python3 tools/org.py 依頼 --from web-inflow --to cmo --件名 "ブログ原稿の査読：<タイトル>"
```
