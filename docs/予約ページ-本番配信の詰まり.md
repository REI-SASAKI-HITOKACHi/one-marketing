# 予約ページの空き枠が本番に届かない件と、その外し方

- 2026-09-18 オーナー承認：「許可ルールを足す（推奨）」
- **結論：CMO側では外せませんでした。オーナーの操作が1回だけ要ります。**

## 何が起きているか

毎時のルーティンが `python3 tools/deploy-booking.py` を実行しようとして、毎回止められています。
その結果、**本番 `yoyaku.onehitter.jp/slots.json` は 2026-09-16 07:43 生成のまま**で、
**9/25 は終日の施工で埋まっているのに「09:00〜17:00 空き」と出続けています。**
お客様が取れば二重予約です。

## 止めているのは権限ルールではありません

`.claude/settings.json` の `permissions.allow` には **`Bash(python3:*)` が元から入っていて**、
このスクリプトは権限の面ではすでに許可されています。
**止めているのは自動モードの分類器**で、`[Production Deploy]`（本番配信）という理由で拒否します。
これは権限ルールとは別の仕組みです。

## 外し方：`autoMode.allow` に例外を1つ足す

**CMO（Claude）自身がこれを書き込もうとすると `[Self-Modification]` で拒否されます。**
自分の安全装置を自分で緩める操作にあたるためで、迂回はしません。**オーナーが足してください。**

`.claude/settings.json` の末尾、`"permissions": { ... }` の閉じ括弧のあとにカンマを足して、
下のブロックを貼ってください。

```json
  "autoMode": {
    "allow": [
      "$defaults",
      "`python3 tools/deploy-booking.py`（引数 --old / --dry-run / --notify を含む）の実行を許可する。本番配信だが、オーナーが 2026-09-18 に明示的に承認済み。このスクリプトは予約フォームの2ホスト（サイトIDを決め打ちにしてある onehitter-yoyaku と one-hitter-booking）へ lp/booking/ の中身を送るだけで、LPサイトには構造的に触れない。毎時のルーティンがこれを実行できないと、渡辺さんのカレンダーで埋まった時間帯が本番の予約ページに『空き』として出続け、二重予約になる。"
    ]
  }
```

`"$defaults"` は**既定の判定をそのまま残す**という意味です。これを消すと他の安全装置まで外れます。**消さないでください。**

## 貼らずに今回だけ直す場合

```
python3 tools/deploy-booking.py
python3 tools/deploy-booking.py --old
```

**今回の食い違いは直りますが、同じ詰まりが毎時また起きます。**

## このスクリプトが触る範囲（なぜ安全と言えるか）

`tools/deploy-booking.py` の先頭にサイトIDが**決め打ち**で書かれています。

| | サイト |
|---|---|
| 新（お客様に出している） | `39408b76-...` ／ onehitter-yoyaku |
| 旧（送信済みSMSのリンク先。`--old` のとき） | `83984fb0-...` ／ one-hitter-booking |

送るのは `lp/booking/` の中身（`index.html` と `slots.json`）だけ。
**LPサイト（one-hitter-lp）は別のスクリプト（`deploy-netlify.py`）の担当で、取り違えが起きないように分けてあります。**
