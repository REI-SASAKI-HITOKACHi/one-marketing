# 年末LP に置く「ギフトの入口」── 原稿と置き場所

作成: 2026-09-20 ／ 作成者: ギフト事業担当（`gift`）
出どころ: 企画書 `docs/gift/2026-09-14-企画書.md` §4.2（宿題3）
対象: **`lp/nenmatsu/index.html`（`lp` の持ち物）**／実装は `lp`・計測は `measurement`

> ## この入口の目的は「売ること」ではありません
> **11月中旬に広告費を出すかどうかを、推測ではなく数字で決めるため**です（企画書 §4.2・経営企画室の案／CMO採用）。
> **前回は「出してみたら0だった」。今回は出す前に反応を見ます。**
> **掲出期間は 10月10日（金）〜11月中旬。広告費0円**（開始日は 2026-09-20 CMO決定）。

---

## 0. 先に、いちばん大事な設計判断

**「ギフトのページへのリンク」を置くのではなく、「お知らせを受け取る」で預かります。**

| | 案A リンクを置く | **案B（推奨）お知らせ登録で預かる** |
|---|---|---|
| 何が取れるか | **クリック数だけ** | **クリック数＋メールアドレス** |
| 11月にどう使えるか | 数字を見て出稿を判断するだけ | **判断に使える＋11月に直接ご案内できる** |
| ギフトLPの公開 | **必要**（＝「外に出す」のでオーナー承認が要る） | **不要。年末LPの中だけで完結する** |
| お客様への誠実さ | **まだ買えないページに送ることになる** | **「11月にご案内します」と正直に書ける** |

> ### **案B を推します。理由は3つです。**
>
> **① いま送れる先がありません。** ギフトLP（`lp/gift/index.html`）は**未配信**で、
> **公開はオーナーの承認事項**です。10月中旬の掲出に間に合う保証がありません。
> **リンクだけ置いて行き先が無い、が最悪**です。
>
> **② クリック数だけでは、11月の判断に足りません。**
> 「100人が押した」と「100人が住所を預けた」は、**意思の強さがまったく違います。**
> **広告費を出すかどうかを決めるのに、弱いほうの数字で決めたくありません。**
>
> **③ 測るだけでは、その人を取り逃します。**
> 10月に興味を持った人に、11月に**もう一度会う方法がありません。**
> **預かっておけば、広告費0円で11月の初速が作れます。**

**※ お知らせのメール本文そのものは `gift` では作りません。**名乗り照合の規則により **`crm` の持ち物**です（CLAUDE.md）。
**ここで作るのは、年末LPに載せる原稿と、預かる項目だけ**です。

## 1. 置き場所

### 推奨：**「ご利用いただいた方から」（Voice）の直後、FAQ の前**

```
… 料金ビルダー → それぞれ何をするのか → 仕上がりの基準
  → 必要なときに、必要な分だけ（Policy）
  → ご利用いただいた方から（Voice）
  → ★ ここにギフトの入口 ★
  → よくあるご質問 → 対応エリア → WEB予約フォーム
```

**理由：**

| # | |
|---|---|
| 1 | **本線の予約導線を邪魔しません。**料金ビルダーと予約CTAを通り過ぎた後ろです |
| 2 | **他の方の体験を読んだ直後が、「実家もそろそろかな」がいちばん降りてくる場所**です |
| 3 | **FAQ・対応エリアまで行くと、読む人が減ります。**測る以上、見られない場所には置けません |
| 4 | 画面下の固定バー（`料金を見る`）は常に出ているので、**本線に戻る道は塞がりません** |

> **⚠ 料金ビルダーより前には置かないでください。**
> **年末LPに来た人の用は「自分の家」です。**そこへ先に別の話を挟むと、**本線の予約が落ちます。**
> **ギフトは「ついでに思い出すもの」の位置で十分**です。

## 2. 原稿（そのまま使える形）

> ### 書き方の軸（クリエイティブ指示書 §1 と同じ）
> **「ギフト」「プレゼント」を見出しに置きません。**この商品が売っているのは**親孝行の段取り**です。
> 年末LPの文体（**言い切らない・盛らない・限界を先に言う**）に合わせてあります。

```
［見出し］
ご実家のこと、気になっていませんか

［リード］
年末に帰省されるなら、その前に。
ご実家のお掃除を、贈り物としてお申し込みいただけるようにする準備を進めています。
お代はご依頼主さま、作業はご実家で。当日はご一緒に立ち会っていただけます。

［箇条書き 3つ］
・ご依頼主さまがお支払い、ご実家で作業いたします
・ご実家が 東京都・千葉県・神奈川県 の場合にお伺いできます
・作業は年明け1〜2月が中心です（年末は予約が埋まりやすいため）

［注記］
ご実家の方に内緒で進めることはできません。
当日ご在宅いただく必要があるため、お申し込み前にお話しいただく形をお願いしています。

［CTA ボタン］
準備ができたらお知らせする

［ボタン下の小さい文字］
11月上旬にご案内をお送りします。この時点でのお支払いはありません。
```

### 登録フォーム（ボタンを押すと開く）

```
お知らせの送り先

メールアドレス　［必須］
ご実家の郵便番号　［必須］　お伺いできる地域かを、その場でお調べします

□ 個人情報の取扱いに同意する

［ 登録する ］
```

> ### ✅ 2026-09-20 CMO決定：**郵便番号は必須。ただしエリア外はその場で正直に出す**
> **エリア内の件数が取れないと11月の判断ができない**、が決め手。
> **前回の受注0の主因がエリア外への出稿だったので、同じ穴を測れないまま繰り返すのがいちばん高くつく。**

### 🔑 郵便番号を入れた直後の表示（**送信前・その場で出す**）

**エリア内のとき：**

```
お伺いできる地域です。
```

**エリア外のとき：**

```
申し訳ありません。いまお伺いできるのは東京都・千葉県・神奈川県のみです。
エリアが広がりましたら、こちらからご連絡いたします。
```

> ### ⚠ **エリア外でも、登録は受け付けてください**（CMO決定）
> **将来のエリア拡大の需要データになります。**
> **ただし「伺えます」と誤解させないこと。入力した直後に分かるようにしてください。**
> **あとでメールで断るのが、いちばん悪い形です。**

**送信後の表示：**

| | |
|---|---|
| **エリア内** | `ありがとうございます。11月上旬にご案内をお送りします。` |
| **エリア外** | `ありがとうございます。エリアが広がりましたら、こちらからご連絡いたします。`<br>**※「11月上旬にご案内」とは書かない。送る予定が無いのに書くと約束になります** |

> ### 🚨 実装の注意 ── **判定は入力直後と受信側の2回**
> **入力直後の表示は、お客様への親切であって守りではありません。**
> **送られてきた郵便番号を、受け取る側でもう一度判定してください。**
> **エリア内／外のフラグを画面の表示だけに頼ると、§4 の内訳が信用できない数字になります。**
> （申込フォーム仕様 §4-1 と同じ構造の話です）

## 3. 🔑 原稿で、わざと不利なことを3つ書いています

**隠すと、11月に取れる数字が嘘になります。**

| # | 書いたこと | なぜ書くか |
|---|---|---|
| 1 | **「東京都・千葉県・神奈川県」** | **前回の受注0の主因がエリア外への出稿**（企画書 §1.2）。**ここで絞らないと、10月の数字がまた「買えない人の反応」になります** |
| 2 | **「作業は年明け1〜2月が中心」** | **12月施工は限界利益が−35%**（§4.1）。**年末に施工できると思わせてから断るのは、いちばん悪い順番**です |
| 3 | **「内緒で進めることはできません」** | **企画書 §3.2.1。**サプライズのつもりで登録した人が11月に離脱すると、**10月の数字が使えなくなります** |

> **3つとも、登録数を減らす方向に働きます。それでいいと考えています。**
> **10月に測っているのは「何人が興味を持つか」ではなく「何人が、条件を知ったうえで手を挙げるか」**です。
> **前者で11月の出稿を決めると、前回と同じことが起きます。**

## 4. 測ること（`measurement` へ）

**広告費0円なので、比較できるのは「年末LPに来た人のうち何%か」だけです。**

| # | 指標 | 取り方 |
|---|---|---|
| 1 | **入口の表示回数** | セクションが画面に入った数（スクロールで到達した人） |
| 2 | **CTAのクリック数** | `準備ができたらお知らせする` の押下 |
| 3 | **登録の完了数** | フォーム送信の完了 |
| 4 | **⭐ 郵便番号のエリア内／外の内訳** | **登録時の郵便番号を判定。前回の主因がここなので、必ず分けて取ってください** |

**イベント名はギフトLPと揃えたいので、`gift_zip_submit`（`lp/gift/index.html` L631・仕様確認待ち）と
同じ命名で設計してください。** ここは `measurement` の持ち物なので、**私からは名前を決めません。**

### 見る順番

```
到達 → クリック（1 に対する率）→ 登録完了（2 に対する率）→ うちエリア内（4）
```

**11月の判断に使うのは、いちばん右の「エリア内の登録数」**です。**クリック数ではありません。**

## 5. ⚠ 合格ラインは、まだ置きません

**置ける根拠がないからです。**

| 分からないこと | なぜ |
|---|---|
| 年末LPの10月中旬〜11月中旬の**想定到達数** | **広告費0円なので、自然流入しだい。`measurement` の実績が要ります** |
| ギフト入口までの**スクロール到達率** | **このセクション自体が新設。前例がありません** |
| 登録 → 11月の**購入への転換率** | **ギフトの販売実績がゼロ**（企画書 §8.3） |

> **推測で「◯件なら出稿」と書くと、前回の「価格が主因だ」と同じ間違いをします**（自分で撤回した仮説）。
> **10月末の判断点（企画書 §9）の時点で、実際に出た数字を見て決めます。**
>
> **ただし1つだけ、いま言えることがあります。**
> **エリア内の登録が0件なら、11月に広告費を出す根拠はありません。**
> **0 と 1 のあいだには、他のどの区切りよりも意味があります。**
