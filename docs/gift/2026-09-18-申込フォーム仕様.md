## 0. 🔑 先に決めた2つの原則

### 原則1：**この商品は、サプライズにできない**

**他人が親の家に入ります。受け取る方の了解なしには成立しません。**
**隠したまま進めると、当日いちばん悪い形で表面化します。**

> **だからフォームの最後に、必須の確認を1つ置きます。**
> **「ご実家に、この贈り物のことをお話しされていますか」**
>
> ここを押さえると、**企画書 §6.4 の未確認論点「受け取る方の個人情報を贈り主から取得すること」**も
> 実務として和らぎます（本人が知っている状態で預かることになる）。**法務の代わりにはなりませんが、設計としては筋が通ります。**

### 原則2：**必須項目は、1つ増えるごとに申込が落ちる**

**電話が課金の前に入る設計**（申込 → 電話 → 日程確定 → 支払い）なので、
**フォームで全部を聞き切る必要がありません。聞けることは電話で聞きます。**
**フォームの仕事は「話を始められる状態にすること」だけ。**

## 1. ⭐ CMO の問い②への答え：**受け取る方の電話番号は「任意」にします**

**必須にしません。** 理由は3つ。

| # | 理由 |
|---|---|
| 1 | **贈り主が、親の携帯番号をその場で思い出せないことがある。**「実家の固定電話なら分かるが携帯は…」で手が止まる。**ここで落ちるのがいちばんもったいない** |
| 2 | **課金の前に、贈り主へ必ず電話します。** その場で聞けば済みます |
| 3 | **必須にしても、正しい番号が入る保証がない。** 曖昧な記憶で入れられるほうが、あとで困ります |

**フォームにはこう書きます。**

```
ご実家のお電話番号（任意）
お分かりになる範囲で構いません。分からなければ、このあとのお電話で伺います。
```

> **ただし「無くてよい」わけではありません。**
> **前日の確認連絡と当日の到着連絡に必要**なので、**電話の場で必ず取り切る**こと。
> **取れないまま日程を確定しない。** これは運用側の約束にします。

## 3. CMO の問い④：Square の決済導線をどこに置くか

**フォームの送信後の画面には、決済リンクを置きません。**

```
申込 → 【送信後の画面】→ 贈り主へ電話 → 日程確定 → 【ここでSquareを送る】→ 前日連絡 → 施工
```

### 3.1 送信後の画面（サンクス）の文言

```
お申し込みを承りました。

このあと、担当より お電話（080-8043-8259）でご連絡いたします。
作業の内容とお日にちをご相談してから、確定いたします。

お支払いは、お日にちが決まってからです。
この時点では、まだ費用は発生していません。

※ お電話は 8:00〜20:00 のあいだにいたします。
※ 番号を登録しておいていただけると、お受け取りいただきやすくなります。
```

**最後の1行は、2026-09-12 の事故（お客様に番号をスパム登録されると二度と届かない）を踏まえたものです。**

### 3.2 ✅ 決済経路は決まりました ── **Square リンク決済（3.6%）で4手段**

> ### 2026-09-20 CMO決定
> **集金は「Square 請求書 3.25%」ではなく「リンク決済 3.6%」に寄せる。**
> 前払いで出すのは **クレジット／デビット・PayPay・メルペイ・d払い** の4つ（2026-09-17 CMO決定は有効）。

**私が (a) を勧めた理由が、そのまま採られました。**

| | |
|---|---:|
| 0.35ポイントの差（10,780円のとき） | **38円** |
| 決済画面で1人止まったときの損失 | **限界利益 9,434円** |

> **38円 × 248回 で、ようやく離脱1人ぶん。**
> **4手段が確実に出る経路を選ぶほうが、料率0.35ポイントより価値が大きい。**

**返金設計（施工前は全額返金・手数料は当社が飲む）**を成立させるうえでも同じです。
**経路ごとに使える手段が割れていると、返金のときに揉めます。**

> ※ **請求書で4手段が実際に選べるかの確認**（`20260919-01-browser`）は**出ていますが、待ちません。**
> 「請求書でも4つ出る」でも判断は変わらず、「出ない」ならこの決定が正解だったというだけです。

**フォーム側の実装への影響はありません。** §3 のとおり**送信後の画面に決済リンクは置かず**、
**日程確定後に、贈り主へ個別にリンクを送る**形は変わりません。

## 4. CMO の問い③：エラーの出し方

### 4-1 🚨 まず、郵便番号をフォームで書き換えられないようにしてください

**LPのゲートを通った郵便番号を、フォーム内で編集可能にすると、ゲートが無意味になります。**
**エリア外の人がゲートで止められたあと、フォームまで辿り着いて番号を書き換える、という抜け道が生まれます。**

```
ご実家の郵便番号　134-0081　（お伺いできる地域です）
　　　　　　　　　　　　　　　［ 別の郵便番号で調べ直す ］
```

**表示のみ**にして、変えたい人は**ゲートに戻す。**

> ### ✅ 2026-09-20 CMO 同意
> 「**LPのゲートを通った値を読み取り専用で持ち込む形にしてください**」

> ### 🚨 ただし、**読み取り専用は「守り」ではありません**
> **`readonly` も `disabled` も、画面上の話でしかありません。**
> ブラウザの開発者ツールでもURLの書き換えでも、**送信される値は変えられます。**
> **「フォームで編集できない」ことと「エリア外の申込が入らない」ことは別です。**
>
> **受け取る側でもう一度判定してください。3つとも要ります。**
>
> | # | どこで | 何をするか |
> |---|---|---|
> | 1 | **LPのゲート** | 入口で止める（**お客様のための親切。ここは守りではない**） |
> | 2 | **フォーム** | 読み取り専用で表示する（**書き換えさせない導線**） |
> | 3 | **⭐ 受信側** | **送られてきた郵便番号を、もう一度エリア判定にかける。これが唯一の守り** |
>
> **3 で外れていたら、申込は受けたうえで「お伺いできない地域でした」とお詫びする**運用にします。
> **画面で弾いて終わりにしない。**すり抜けた人を黙って落とすと、**お客様は「送ったのに返事が来ない」状態**になります。
>
> ※ **課金は電話のあとなので、すり抜けても金銭事故にはなりません。**
> 　 ただし**贈り主の期待を一度持ち上げてから落とすこと**になるので、**早く気づくほど傷が浅い**です。

### 4-2 エラーの出し方の原則

| | |
|---|---|
| **どこに出すか** | **項目のすぐ下。** ページ上部にまとめて出さない（どこを直すか探させない） |
| **いつ出すか** | **送信ボタンを押したとき。** 入力の途中で赤くしない |
| **何を書くか** | **「何が足りないか」ではなく「なぜ要るか」** |
| フォーカス | 最初のエラー項目へ移動する |

**文言の例：**

| ✕ 書かない | ○ 書く |
|---|---|
| 入力してください | **お電話番号をご記入ください。日程のご相談で、こちらからおかけします** |
| 必須項目です | **受け取る方のお名前をご記入ください** |
| 形式が正しくありません | **メールアドレスをご確認ください（控えをお送りします）** |
| 同意が必要です | **利用規約と個人情報の取扱いに、ご同意をお願いします** |
