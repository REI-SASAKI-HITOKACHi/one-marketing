# ギフト 申込フォーム 仕様

作成: 2026-09-18 ／ 作成者: ギフト事業担当（`gift`）／ 実装: CMO
前提: `lp/gift/index.html`（未配信）／`docs/gift/2026-09-17-お掃除機能付きエアコンの運用設計.md`

## 0. 🔑 先に決めた2つの原則

### 原則1：**この商品は、サプライズにできない**

**他人が親の家に入ります。受け取る方の了解なしには成立しません。**
**隠したまま進めると、当日いちばん悪い形で表面化します。**

> **だからフォームの最後に、必須の確認を1つ置きます。**
> **「ご実家に、この贈り物のことをお話しされていますか」**
>
> ここを押さえると、**企画書 §6.4 の未確認論点「受け取る方の個人情報を贈り主から取得すること」**も
> 実務として和らぎます（本人が知っている状態で預かることになる）。**法務の代わりにはなりませんが、設計としては筋が通ります。**

### 原則2：**必須項目は、1つ増えるごとに申込が落ちる**

**電話が課金の前に入る設計**（申込 → 電話 → 日程確定 → 支払い）なので、
**フォームで全部を聞き切る必要がありません。聞けることは電話で聞きます。**
**フォームの仕事は「話を始められる状態にすること」だけ。**

## 1. ⭐ CMO の問い②への答え：**受け取る方の電話番号は「任意」にします**

**必須にしません。** 理由は3つ。

| # | 理由 |
|---|---|
| 1 | **贈り主が、親の携帯番号をその場で思い出せないことがある。**「実家の固定電話なら分かるが携帯は…」で手が止まる。**ここで落ちるのがいちばんもったいない** |
| 2 | **課金の前に、贈り主へ必ず電話します。** その場で聞けば済みます |
| 3 | **必須にしても、正しい番号が入る保証がない。** 曖昧な記憶で入れられるほうが、あとで困ります |

**フォームにはこう書きます。**

```
ご実家のお電話番号（任意）
お分かりになる範囲で構いません。分からなければ、このあとのお電話で伺います。
```

> **ただし「無くてよい」わけではありません。**
> **前日の確認連絡と当日の到着連絡に必要**なので、**電話の場で必ず取り切る**こと。
> **取れないまま日程を確定しない。** これは運用側の約束にします。

## 2. 入力項目と順番（CMO の問い①）

**順番の原則：軽いものから。「選ぶ」→「実家のこと」→「自分のこと」→「確認」。**
※ 郵便番号はLPのゲートで入力済み。**ここでは引き継ぎ表示のみ。**

### セクション1：ご希望の内容

| 項目 | 必須 | 形 | 備考 |
|---|---|---|---|
| メニュー | **必須** | ラジオ | エアコン1台 10,780円／浴室 18,480円／レンジフード 18,480円／エアコン＋浴室 25,960円／**その他・相談したい** |
| お掃除機能付きですか | **必須** | ラジオ | **はい／いいえ／わからない**。※**エアコンを含むメニューを選んだときだけ表示** |
| ご希望の時期 | **必須** | ラジオ | 年内／1月／2月／**まだ決めていない** |

**お掃除機能付きの補助文：**
```
分からなくて大丈夫です。「わからない」をお選びいただくと、お掃除機能付きの料金（17,380円）でお預かりし、
当日ノーマルタイプだった場合は 6,600円 をお返しします。
```

### セクション2：ご実家（お届け先）のこと

| 項目 | 必須 | 形 | 備考 |
|---|---|---|---|
| 受け取る方のお名前 | **必須** | テキスト | |
| 贈り主さまとのご関係 | 任意 | セレクト | 母／父／両親／義理の親／その他 |
| ご実家の郵便番号 | **必須** | **表示のみ・変更不可** | **⚠ §4-1 参照** |
| ご実家のご住所（番地まで） | 任意 | テキスト | 「お電話で伺っても構いません」 |
| **ご実家のお電話番号** | **任意** | テキスト | **§1 のとおり** |

### セクション3：贈り主さま（お客様）のこと

| 項目 | 必須 | 形 | 備考 |
|---|---|---|---|
| お名前 | **必須** | テキスト | |
| お電話番号 | **必須** | テキスト | **「日程のご相談で、こちらからおかけします」** |
| メールアドレス | **必須** | テキスト | 控えの送付先 |
| **連名で贈る方のお名前** | 任意 | テキストエリア | **「3名様まで。ご実家へのカードに連名でお入れします」** ← **商品設計の一部**（企画書 §3.3） |

### セクション4：お伝えしたいこと

| 項目 | 必須 | 形 |
|---|---|---|
| ご実家へのメッセージ | 任意 | テキストエリア（100字程度） |
| その他のご要望 | 任意 | テキストエリア |

### セクション5：確認

| 項目 | 必須 | 形 | 文言 |
|---|---|---|---|
| **お話し済みか** | **必須** | ラジオ | **「ご実家に、この贈り物のことをお話しされていますか」** → **はい／これからお話しします** |
| 同意 | **必須** | チェック | 利用規約・個人情報の取扱いに同意する |

**「これからお話しします」を選んでも、止めません。** 電話のときに「先にお話しいただけますか」と案内します。
**選択肢として存在させることに意味があります**（正直に答えられる）。

### 送信ボタン

```

※ この時点でのお支払いはありません
```

## 3. CMO の問い④：Square の決済導線をどこに置くか

**フォームの送信後の画面には、決済リンクを置きません。**

```
申込 → 【送信後の画面】→ 贈り主へ電話 → 日程確定 → 【ここでSquareを送る】→ 前日連絡 → 施工
```

### 3.1 送信後の画面（サンクス）の文言

```
お申し込みを承りました。

このあと、担当より お電話（080-8043-8259）でご連絡いたします。
作業の内容とお日にちをご相談してから、確定いたします。

お支払いは、お日にちが決まってからです。
この時点では、まだ費用は発生していません。

※ お電話は 8:00〜20:00 のあいだにいたします。
※ 番号を登録しておいていただけると、お受け取りいただきやすくなります。
```

**最後の1行は、2026-09-12 の事故（お客様に番号をスパム登録されると二度と届かない）を踏まえたものです。**

### 3.2 ⚠ 決済手段と料率のトレードオフに、1つ気づきました

**CMO の決定：前払いで出す決済は クレジット／デビット・PayPay・メルペイ・d払い の4つ。**
**別の決定：集金は Square 請求書（3.25%）が第一候補**（リンク決済3.6%より安い）。

> **この2つが両立するか、確認できていません。**
> **Square 請求書は「お客様がカード情報を入力する」形です。**
> **PayPay・メルペイ・d払い が請求書で使えるのか、こちらでは分かりません。**
>
> **使えないなら、選択肢は2つです。**
> - **(a) リンク決済（3.6%）にして、4つ全部出す** ── 0.35ポイント高い
> - **(b) 請求書（3.25%）にして、カード決済のみにする** ── 安いが申込を落とす可能性
>
> **gift の意見は (a)。** 0.35ポイント（1万円で35円）より、**決済で止まるほうが高くつきます。**
> **ただし請求書で4つ使えるなら、それがいちばん良い。CMO の確認項目に追加してください。**

## 4. CMO の問い③：エラーの出し方

### 4-1 🚨 まず、郵便番号をフォームで書き換えられないようにしてください

**LPのゲートを通った郵便番号を、フォーム内で編集可能にすると、ゲートが無意味になります。**
**エリア外の人がゲートで止められたあと、フォームまで辿り着いて番号を書き換える、という抜け道が生まれます。**

```
ご実家の郵便番号　134-0081　（お伺いできる地域です）
　　　　　　　　　　　　　　　［ 別の郵便番号で調べ直す ］
```

**表示のみ**にして、変えたい人は**ゲートに戻す。**

### 4-2 エラーの出し方の原則

| | |
|---|---|
| **どこに出すか** | **項目のすぐ下。** ページ上部にまとめて出さない（どこを直すか探させない） |
| **いつ出すか** | **送信ボタンを押したとき。** 入力の途中で赤くしない |
| **何を書くか** | **「何が足りないか」ではなく「なぜ要るか」** |
| フォーカス | 最初のエラー項目へ移動する |

**文言の例：**

| ✕ 書かない | ○ 書く |
|---|---|
| 入力してください | **お電話番号をご記入ください。日程のご相談で、こちらからおかけします** |
| 必須項目です | **受け取る方のお名前をご記入ください** |
| 形式が正しくありません | **メールアドレスをご確認ください（控えをお送りします）** |
| 同意が必要です | **利用規約と個人情報の取扱いに、ご同意をお願いします** |

## 5. 送信先とデータ

| | |
|---|---|
| 送信 | **Netlify Forms**（既存の予約フォームと同じ仕組み） |
| フォーム名 | `gift`（`予約_Web` と混ざらないように分ける） |

**⚠ お客様に届くメール・SMS の文面は `gift` では作りません。** 名乗り照合の規則により `crm` に依頼します。
