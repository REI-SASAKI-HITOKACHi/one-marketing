## 3. 公式サイトには、すでにGA4が入っている

これは事前に把握されていなかった重要な事実です。TOPページの先頭に、次が入っています。

```html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-8MV0E0GZHS"></script>
...
gtag('config', 'G-8MV0E0GZHS', {});
gtag('config', 'UA-239916628-78', {});
```

- `G-8MV0E0GZHS` … **GA4の測定ID。** つまり公式サイトのアクセスは、少なくとも
  2026-09-06 時点で GA4 に記録されています。
- `UA-239916628-78` … 旧・ユニバーサルアナリティクスのID。**2023年7月に計測が停止**
  しているので、いま何かを記録しているわけではありません。害はないので放置で構いません。

### ここが分かれ目です

**このGA4プロパティに、オーナーがログインできるかどうかで進め方が変わります。**

`UA-239916628-78` の末尾の「-78」は、1つのアカウントの中の78番目のプロパティ、という意味です。
**制作会社（リアライズ）が複数の顧客サイトをまとめて管理しているアカウントの可能性が高い**
と考えられます。断定はできません。管理画面を見ないと分かりません。

| もしオーナーがログインできるなら | できないなら |
|---|---|
| そのプロパティにLPを合流させる。公式サイトとLPを1つの画面で見られる | LP専用に新しいGA4プロパティを作る。公式サイト側は当面そのまま |
| 過去のデータも遡って見られる | ゼロから貯め直し |

**→ 手順書の第1章で、まずここを確かめていただきます。** どちらでも計測は始められますが、
「どちらか」を決めないとプロパティを作れないので、最初にこれを潰します。

### 公式サイトの申込フォームも、いまは成果として数えられていません

`https://one-hitter.jp/contact/` のフォームはCMSが持っているもので、送信すると
`/contact/` に POST し直す作り（入力 → 確認 → 完了 を同じURLで切り替える方式）です。
**完了画面に固有のURLが無いため、いまのGA4では「送信された」ことを検知できません。**

サイト経由の受注が 18件 → 4件（−64%）に落ちている件は、
**フォームが壊れているのか、そもそも人が来ていないのかすら、今のままでは切り分けられません。**
GA4は入っているので、管理画面にログインできれば流入数だけは遡って見られます。
→ これも手順書の第1章で確かめます。

## 4. 電話は、いま1件も測れていません

### 番号が2つあります（重要）

| どこに載っているか | 番号 |
|---|---|
| 公式サイト（TOP・プライバシーポリシー・フッター） | **080-1755-7275** |
| LP 3本（ヘッダー・フォーム下・追従バー・送信完了ページ） | **080-8043-8259**（受付：渡辺） |

`docs/tracking-setup.md` は「LPの番号を 080-1755-7275 とは別の転送番号に差し替える」
という前提で書かれていますが、**LPは最初から別番号（080-8043-8259）です。**
番号が分かれていること自体は良いことです。ただし——

- **これは転送サービスの発番ではなく、担当者の携帯番号**と思われます。
  つまり**着信の記録が残らず、何件かかってきたかを後から数えられません。**
- 案A・案B・水まわりで同じ番号なので、**どのLPが電話を生んだのかも分かりません。**

### だから、いま分かること・分からないこと

| | |
|---|---|
| 分かる | 電話が鳴った（その場にいれば） |
| **分からない** | 何件鳴ったか／LPを見てかけたのか／案Aと案Bのどちらか／広告経由か／取りこぼした件数 |

成果地点が「作業完了ベース・成果単価3,000円」で、この業種は電話申込の比率が高い以上、
**ここが空白のまま広告を回すと、成果の半分が見えません。**

→ **月額0円で始められる方法があります。** Google広告には、広告経由の訪問者にだけ
LP上の電話番号を専用の転送番号に自動で差し替える機能があり、**無料**です。
詳細は `docs/calltracking-vendors.md` の第5章、手順は手順書の第4章。

## 5. 見つかった不具合（計測以前の問題）

調べる過程で、成果に直接効く不具合が3つ見つかりました。**いずれも修正済みですが、
配信していないので本番はまだ直っていません。**（配信は承認が要るため）

### ① 案B（aircon-b）は、フォームを送ると404になる ← 影響が大きい

```
https://one-hitter-lp.netlify.app/aircon-b/thanks    → 404 Not Found
https://one-hitter-lp.netlify.app/aircon/thanks      → 200 OK
https://one-hitter-lp.netlify.app/mizumawari/thanks  → 200 OK
```

送信完了ページを手で2枚だけ置いていたため、あとから追加した案Bの分がありませんでした。
**お客様は申し込んだあと「ページが見つかりません」を見ることになります。**

申込自体はNetlify側で受理され、通知メールも届いていると考えられます（未検証。確かめるには
本番のフォームに実際に送信する必要があり、オーナーの受信箱にテストメールが飛ぶため
実施していません）。ただし**お客様から見れば失敗したようにしか見えないので、
そのまま電話に切り替えるか、離脱します。**

→ テンプレートから全LP分を生成する方式に変更しました。**A/Bテストを始める前に配信が必要です。**
そもそも成果（`generate_lead`）はこの完了ページで数える設計なので、無いと計測が成立しません。

### ② 予備のPHP版で、案Bの申込が案Aとして記録されていた

ロリポップ用の `deploy/htdocs/form/send.php` が、`aircon-b` からの送信を `/aircon/` に
丸めていました。A/Bのどちらが取れた申込か分からなくなります。
現在はNetlify配信なので本番影響はありませんが、切り戻したときに効くので直しました。
通知メールの件名でも「エアコン（パターンA）／（パターンB）」を見分けられるようにしています。

### ③ 1ページに `<title>` が2つあった

LPのソースはArtifact用の断片で、先頭に `<title>` が残っていました。包むときに
`<body>` の中へ入り、1ページに2つある状態でした。**GA4はページタイトルでレポートを
並べるので、紛れの元になります。** 包むときに落とすようにしました。

## 6. 法令・規約まわりで、先に片づけておくこと

**GA4や広告タグを入れると、閲覧者の情報がGoogleに送られます。**
これはプライバシーポリシーに書いていないと、Google側の規約に反します。

現在の `https://one-hitter.jp/privacy_policy/` を読んだ結果：

- 「8．Cookieについて」に**一般的なCookieの記載はあります。**
- しかし **Googleアナリティクス・広告・アクセス解析・外部送信という語は1つも出てきません。**

Googleアナリティクスの利用規約は、**利用者に対して「Cookieを使ってデータを収集し
Googleに送っていること」をプライバシーポリシーで開示するよう求めています。**
公式サイトには既にGA4が入っているので、**この開示は今この瞬間から必要な状態です**
（LPに入れる前の話です）。

追記する文案は、手順書の第5章に用意しました。

> **補足：** 2023年6月施行の電気通信事業法「外部送信規律」は、対象が検索・SNS・
> メッセージング・オンラインショッピング等の事業者に限られており、
> **ハウスクリーニング業の自社サイトが対象になるとは考えにくい**というのが調べた範囲での
> 理解です。断定はできません。ただし上記のGoogle側の規約は業種に関係なく適用されるので、
> **いずれにせよ追記は必要**です。

## 7. いま実装した仕組み（コミット済み・未配信）

LPの本文には一切手を触れていません。**書き出すときに計測タグを差し込む方式**にしたので、
LPのデザインや文言を持っている別スレッドと衝突しません。

| 置き場所 | 中身 |
|---|---|
| `tracking/measurement.json` | 測定IDと電話番号の設定。**ここを書き換えて再ビルドするだけ** |
| `tracking/events.js` | クリック・送信を拾う本体 |
| `tools/build-site.py` | 上の2つを全ページへ差し込む |
| `tools/check-tracking.py` | 書き出したHTMLに計測が入っているかの確認。**配信前に通す** |

**IDが空のままでもビルドは通り、タグは出力されません。** つまり「GA4の準備ができるまで
何も進められない」という状態にはなっていません。ID欄を埋めて再ビルドすれば、その時点から
計測が始まります。

動作確認は、ビルド済みのページをブラウザで実際に開いて行いました。
電話・LINE・CTAのクリック、料金シミュレーター、エリア判定、フォーム送信、送信完了ページまでを
通しで実行し、全イベントが送られること、見積り金額 (10,780+3,300)×2＝**28,160円** が
成果イベントの金額として引き継がれることを確認しています。

## 10. 前提として気をつけること

- **ドメイン `one-hitter.jp` は 2026/09/30 が有効期限で、まだ更新されていません。**
  そのため、この計測設計は `lp.one-hitter.jp` を前提にしていません。
  当面 `one-hitter-lp.netlify.app` のまま進めます。独自ドメインを当てるときは、
  GA4側で「参照元除外」の追加が必要になります（手順書の第6章）。
- **料金の数字（`data/prices.json`／`docs/price-master.md`）には一切触れていません。**
- LPのデザイン・コピー・価格も変更していません。変更したのは計測タグの差し込みだけです。
