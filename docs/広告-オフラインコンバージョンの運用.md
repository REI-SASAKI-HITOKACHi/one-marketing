# 受注が決まった申込を、Google広告へ戻す（オフラインコンバージョン）

作成 2026-09-22 ／ 計測担当
依頼 `20260922-01-measurement`（CMO）／ 実装 `tools/ads-offline-cv.py`

---

## なぜ要るのか

**サンクスページのコンバージョンだけを見ていると、申込1件はどれも同じ「1」に見えます。**

| | |
|---|---|
| 申し込んだが、日程が合わず流れた人 | **1件** |
| 電話で追加メニューが決まって 108,900円になった人 | **1件** |

**この状態で自動入札に任せると、「申し込むだけの人」を集めるほうへ最適化していきます。**

当社は **申込から入金まで2〜4週間** かかり、**1件の金額は 33,660円から10万円超まで開きます。**
**どの広告が「金額の大きい仕事」を連れてきたかは、申込の時点では分かりません。**

**あとから実際の売上を戻す**のがオフラインコンバージョンです。
そのために `gclid` をフォームに残してあります（`docs/広告-コンバージョン計測.md` 第5章）。

> **残していなければ、後から復元できません。**
> だから出稿の前に入れました（2026-09-14、`720d1e7`）。

## 1. 誰が・いつ・何を

| | |
|---|---|
| **誰が** | **計測担当**がCSVを作る。**アップロードはブラウザ担当かオーナー**（管理画面にこちらは入れない） |
| **いつ** | **毎月1回。月初**（前月ぶんをまとめて） |
| **入力** | **`予約_Web` タブのCSV 1本だけ**（台帳は開きません） |
| **出力** | Google広告のオフラインCVインポート用CSV |
| **台帳** | **読むだけ。1文字も書き換えません** |

### なぜ月1なのか（週1ではなく）

**入金の確認に2〜4週間かかるからです。** 週1で回すと、**毎週ほとんどの行が「まだ入金前」で弾かれ、
同じ行を何度も見ることになります。**

> ### ⚠️ ただし、**90日を空けてはいけません**
>
> **クリックから90日を過ぎた成約は、Google広告が受け取りません**
> （コンバージョンアクションのクリックスルー計測期間を90日にしてあるため）。
>
> **月1なら、いちばん遅い行でも「申込の翌月初」＝最大60日で戻せます。** 間に合います。
> **2か月飛ばすと、そこで取りこぼしが出ます。**
>
> `tools/ads-offline-cv.py` は、**90日を超えた行を件数と金額つきで警告します。**
> **警告が出たら、運用が滞っている合図です。**

## 2. どの列を使うか（2026-09-22 CMO確認を反映）

**台帳（`◯月_売上`）には `order_id` も `gclid` もありません。台帳には足しません。**
**予約_Web 側で完結させます。**

| 予約_Web の列 | 何に使うか |
|---|---|
| **`注文ID`**（AB。LPが採番した `OH-…`） | 申込1件の識別 |
| **`NetlifyのID`** | **予約フォーム経由は注文IDが無い**（LPが採番するものなので）。そのときの鍵 |
| **`gclid`**（AC）／予約フォームは「広告のクリックID」 | Google広告へ戻す先 |
| **`★売上（税込）`** | 戻す金額 |
| **`★台帳の最終施工日`** | コンバージョンの日時 |
| 申込日時 | **90日の期限を測る起点** |

**`★` の列は crm が台帳と紐づけたものです**（`20260913-03-crm`）。

> ### 氏名・電話で突き合わせない、は変えていません
>
> **同姓同名・番号の変更・入力の揺れで、別人の売上を別人のクリックに結び付けます。**
> **間違った金額で自動入札が学習すると、原因が分からないまま予算が歪みます。**
> **`★` の列は crm が別の方法で紐づけた結果**なので、こちらはそれを読むだけです。

> ### 申込日時の列が無いと、期限を見られません
>
> **道具は「90日の期限を見ていません」と断り書きを出します。**
> **黙って期限切れを混ぜません。**

## 3. 金額を「値」に入れるか → **入れます。それがこの運用の目的です**

| | 何を入れるか |
|---|---|
| **Conversion Value** | **実際の売上（税込・円）** |
| Conversion Currency | `JPY` |
| Conversion Time | **施工日**（入金日ではなく） |

### なぜ施工日なのか

**入金日だと、支払い方法の違いがそのまま日付の差になります。**
現金なら当日、振込なら数日後、カードならもっと後。**広告の良し悪しと関係のない差です。**

**施工日は「仕事が実際に発生した日」**で、金額が確定する日でもあります。
**90日の期限にも余裕が出ます。**

### 何を落とすか

| 落とすもの | 理由 |
|---|---|
| `gclid` が空 | **広告経由ではありません。** 戻す先がない |
| 売上が0または空 | キャンセル・未確定。**0円のコンバージョンを送ると平均単価が下がって見えます** |
| 予約_Web に無い `order_id` | 突き合わせられない（電話申込・紹介など） |
| クリックから90日超 | **Google広告が受け取りません** |

## 4. どのコンバージョンアクションに入れるか

> # ⛔ タグで撃っている「申込」と**同じ名前にしないでください**
>
> **同じ申込が2回数えられます。**
> サンクスページで1回（タグ）、受注が決まってもう1回（オフライン）です。
> **CPAが実際の半分に見えて、入札が暴走します。**

**新しく「受注（オフライン）」というコンバージョンアクションを作ってください。**

| | 設定 |
|---|---|
| 名前 | **受注（オフライン）** |
| 目標 | 「購入」または「その他」 |
| 作成方法 | **インポート → アップロード（オフライン コンバージョン）** |
| 値 | **アップロードした値を使う** |
| カウント方法 | **1回** |
| **アクションの最適化** | **最初はサブアクション。** 数が貯まってから主に切り替える |

### なぜ最初はサブなのか

**件数が少ないうちに主コンバージョンにすると、自動入札が数件の受注に引きずられます。**

10月の見込みは13日で期待CV 2.3件（`20260916-04-cmo` のCMO試算）。
**そのうち受注まで進むのはさらに一部です。**

**30件くらい貯まってから、主CVを「申込」から「受注（オフライン）」に切り替える**のが順当です。
**そこが本当のゴールで、申込はその手前の代理指標にすぎません。**

## 5. 手順（月初・15分）

```
0. ★ crm に `tools/yoyaku-match.py --kaku` を1回回してもらう
   （予約_Web の ★列を、台帳の最新に合わせる）
1. 予約_Web タブを CSV で書き出す（それだけ。台帳は開かない）
2. 下見する（何も書かない）
   python3 tools/ads-offline-cv.py 予約_Web.csv

3. 件数と金額を見て、おかしくなければ書き出す
   python3 tools/ads-offline-cv.py 予約_Web.csv --out data/ads-offline-2026-10.csv

4. ★ Google広告 → [目標] → [コンバージョン] → [アップロード] → ファイルを選ぶ
5. ★ **必ず「プレビュー」で確かめてから適用する**
6. アップロードしたファイルを data/ に残す（二重に上げないための控え）
```

**★ が他スレッドの手番です**（0 は crm、それ以外の ★ は管理画面なのでブラウザ担当かオーナー）。
**この道具はアップロードしません。**

> ### なぜ 0 が要るのか
>
> **`★売上（税込）` と `★台帳の最終施工日` は、crm の `tools/yoyaku-match.py` が埋めています**
> （crm ブランチ `de2904d`。既定は下見で、`--kaku` を付けたときだけ書きます）。
>
> **それが回るのは毎週月曜固定なので、月初まで最大6日空きます。**
> **その6日ぶんの施工・入金が★列に入っていないと、戻せるはずの受注がそのまま落ちます。**
> **落ちた行は次の月に回りますが、90日の期限はその間も進みます。**

### 最初の1回だけ：列名を突き合わせる

**管理画面からテンプレートCSVを落として、1行目の列名を見比べてください。**

```
Parameters:TimeZone=Asia/Tokyo
Google Click ID,Conversion Name,Conversion Time,Conversion Value,Conversion Currency
```

**こちらは公開されている一般的な形に合わせていますが、画面の版で細部が変わることがあります。**
違っていれば `--header` で差し替えられます（コードを直す必要はありません）。

## 6. 出さないもの

**CSVに入るのは5つだけです。**

```
gclid ／ コンバージョン名 ／ 日時 ／ 金額 ／ JPY
```

**氏名・電話番号・住所・メニューは1文字も出しません。**
`tools/test-ads-offline-cv.py` で、**個人情報が混ざらないことを毎回確かめています。**

> **これは `CLAUDE.md` の「個人情報を含む機密情報を外に出す」に当たらない形にするためです。**
> **Google広告へ渡るのは、Google自身が発行したクリックIDと金額だけ**です。
