# 11/1 広告の日予算を上げるかの判定シート（ひな形）

- 作成：経営企画室（planning）2026-10-16 ／ 依頼：cmo 20261016-02-planning（MTG 7-4 No.5）
- 目的：11/1 の朝に、**日予算を ¥5,000 → ¥7,000（＋地域かキーワードを広げる＝A案）にするかを、数字を入れるだけで決める**
- A案を出すと決まったら、CMO からオーナーへ承認を取る（お金を使う）。このシートは「出すか」までを決める
- 対象期間：**10/16〜10/31**（入口の直し・入札切替の後）。11月施工の件数は 11/1 朝の時点の予約

## 1. 指標と基準値

| # | 指標 | 基準 | 11/1 の値（記入） |
|---|---|---|---|
| ① | 11月施工の広告のお客様の件数 | **3件** | |
| ② | 広告の LP表示 → 予約ページ表示 | **8%** | |
| ③ | SMS 2便目・公式LINE からの予約数 | 記録（基準なし。主の指標に足す） | |
| ④ | GBP から来た人の入力開始 | **1以上** | |
| ⑤ | （前提）広告の受注1件あたりの費用 | **¥30,500 以下** | |

## 2. 取り方と担当

**11/1（日）08:00〜09:00 に CMO が流す**（2026年シート・GA4 の鍵が CMO の環境にしか無いため）。結果の JSON を push し、planning が 10:00 までに判定の文を掲示板に返す。

### コマンド（CMO・この順で）

```
git pull
# ①③：月次タブと予約_Web（件数だけ。氏名・電話・住所は出さない）
python3 tools/chakuchi-shuukei.py --kijun 2026-11-01
# ②④：GA4 の経路別4段（measurement ブランチの道具。10/15 に流したのと同じ）
git show origin/claude/measurement-ga4-calltracking:tools/funnel-keiro.py > tools/funnel-keiro.py
python3 tools/funnel-keiro.py --start 2026-10-16 --end 2026-10-31 --save data/chakuchi/funnel-1016-1031.json
git add data/chakuchi/ && git commit -m "11/1 判定用の集計" && git push
```

`tools/funnel-keiro.py` はコミットしない（measurement の持ち物。git show で取ってくるだけ）。

### 各指標の読み方

| # | どこを見るか | 数え方 |
|---|---|---|
| ① | `data/chakuchi/2026Q4-20261101-*.json` の `売上 → 11月 → 明細` | キーが `One Hitter|広告|…` の件数の合計。**月次タブに入ったもの（＝受注確定）だけで判定**。同じ JSON の `予約_Web` で `広告|11月|その他|…`（受注前の申込）があれば横に参考で書く |
| ② | `data/chakuchi/funnel-1016-1031.json` の表の「広告」行 | 予約ページ表示 ÷ LP表示。**LP表示が100未満なら「数が足りない」として②は8%未満と同じ扱い**（入口を先に見る） |
| ③ | `2026Q4-20261101-*.json` の `予約_Web` | `SMS|…` と `LINE|…` のうち、**受信日が SMS 2便目の送信日以降**で、状態が キャンセル・空送信でないもの。月次タブの 11月 `流入経路＝SMS・LINE` も並べる |
| ④ | `funnel-1016-1031.json` の「GBP」行 | 入力開始の数 |
| ⑤ | measurement の判定表（`tools/ad-group-hyou.py`）、または 10/16〜31 の広告費 ÷ 同期間の広告受注 | 受注が0件なら「判定できない」として A は出さない |

- 予約_Web の src が `gads*` は広告、`sms*` は SMS、`line*` は公式LINE、`gbp*` は GBP（`tools/chakuchi-shuukei.py` の `src_kubun()`）
- funnel-keiro は `src=line` を「直接・その他」に入れる。③は予約_Web の方で数える

## 3. 判定の文（上から順に当てはめて、最初に当たったものが結論）

| 順 | 条件 | 結論 | 次の手（持ち主） |
|---|---|---|---|
| 1 | ⑤ が ¥30,500 超、または広告受注0件 | **A は出さない** | 広告文・着地の作り直し（measurement・lp） |
| 2 | ② が 8% 未満（LP表示100未満を含む） | **A は出さない。入口を先に直す** | 水まわり・年末LPの主ボタン（lp）。11/10 の C対E 判定を待たずに次の直しへ |
| 3 | ② が 8% 以上 かつ ① が 3件未満 | **A をオーナーへ上げる**（日¥7,000＋地域かキーワード拡大。11月 +約¥6万・+2〜3件の見込み） | CMO がオーナー承認を取る。広げる地域・語は measurement・web-inflow |
| 4 | ② が 8% 以上 かつ ① が 3件以上 | **据え置き**（日¥5,000） | 11/15 にもう一度この表を回す |

**④ は日予算の判定には使わない。** ④ が0のままなら、GBP の着地（日付が選べるか・料金が出るか）の直しを web-inflow・lp に出す（お金は掛からない）。
**③ も日予算の判定には使わない。** 11月の主の指標（ネット経由全体）に足して、10件に対する残りを書く。

### 記入例（数字は架空）

> ① 2件／② 9.1%（LP表示 230・予約ページ 21）／③ 2件（SMS 1・LINE 1）／④ 0／⑤ ¥21,000
> → 順1 非該当、順2 非該当、**順3 該当：A をオーナーへ**。④ が0なので GBP の着地の直しを web-inflow へ。11月の主の指標は ①2＋③2＋直接 … ＝ 残り◯件

## 4. 判定の後

- 結論と5つの値を、MTGシート 7-4 No.5 の結果欄と `docs/2026-11月ネット10件の経路別逆算.md`（11/1 の置き直し）に書く
- A を出したときの承認の文は CMO が作る（金額・期間・見込み件数・止める条件）。止める条件の案：**A を始めて14日で、増えた分のクリックから受注0件なら元に戻す**
