# 11/1 広告の日予算を上げるかの判定シート（ひな形）

- 作成：経営企画室（planning）2026-10-16 ／ 依頼：cmo 20261016-02-planning（MTG 7-4 No.5）
- 目的：11/1 の朝に、**日予算を ¥5,000 → ¥7,000（＋地域かキーワードを広げる＝A案）にするかを、数字を入れるだけで決める**
- A案を出すと決まったら、CMO からオーナーへ承認を取る（お金を使う）。このシートは「出すか」までを決める
- 対象期間：**10/16〜10/31**（入口の直し・入札切替の後）。11月施工の件数は 11/1 朝の時点の予約

## 1. 指標と基準値

| # | 指標 | 基準 | 11/1 の値（記入） |
|---|---|---|---|
| ① | 11月施工の広告のお客様の件数 | **3件** | |
| ② | 広告の LP表示 → 予約ページ表示 | **8%** | |
| ③ | SMS 2便目・公式LINE からの予約数 | 記録（基準なし。主の指標に足す） | |
| ④ | GBP から来た人の入力開始（**機械のアクセスを除く**） | **1以上** | |
| ⓪ | （前提）予算による制限が出ているか | **出ている／IS損失率（予算）10%以上** | |
| ⑤ | （前提）広告の受注1件あたりの費用 | **¥30,500 以下** | |

## 2. 取り方と担当

**11/1（日）08:00〜09:00 に CMO が流す**（2026年シート・GA4 の鍵が CMO の環境にしか無いため）。結果の JSON を push し、planning が 10:00 までに判定の文を掲示板に返す。

## 3. 判定の文（上から順に当てはめて、最初に当たったものが結論）

| 順 | 条件 | 結論 | 次の手（持ち主） |
|---|---|---|---|
| 1 | ⑤ が ¥30,500 超、または広告受注0件 | **A は出さない** | 広告文・着地の作り直し（measurement・lp） |
| 2 | ② が 8% 未満（LP表示100未満を含む） | **A は出さない。入口を先に直す** | 水まわり・年末LPの主ボタン（lp）。11/10 の C対E 判定を待たずに次の直しへ |
| 3 | ② が 8% 以上 かつ ① が 3件未満 | **A をオーナーへ上げる。中身は ⓪ で変わる**：⓪ 制限あり → 日¥7,000＋地域かキーワード拡大（11月 +約¥6万・+2〜3件の見込み）／**⓪ 制限なし → 日予算は上げず、地域かキーワードを広げるだけ**（上げても費用もクリックも増えないため。measurement 10/16：エアコン広告 約7.5クリック/日・制限なし）。広げた結果、費用が日¥5,000に張り付いたら予算を上げる | CMO がオーナー承認を取る。広げる地域・語は measurement・web-inflow。上げたら §5 で測る |
| 4 | ② が 8% 以上 かつ ① が 3件以上 | **据え置き**（日¥5,000） | 11/15 にもう一度この表を回す |

**④ は日予算の判定には使わない。** ④（機械を除く）が0なら、GBP からは人が予約ページに来ていない＝着地ではなく **GBP の見られ方（投稿・写真・クチコミ）** の問題として web-inflow に出す（お金は掛からない）。
**③ も日予算の判定には使わない。** 11月の主の指標（ネット経由全体）に足して、10件に対する残りを書く。
**別の線（11月10件に届くか）：** 11/1 の朝に **11月施工のネット経由が合計4件**（広告＋SMS＋直接）あれば届く見込み（`docs/2026-11月ネット10件の経路別逆算.md`）。①（広告だけ・3件）とは別に、この線も一緒に書く。

### 記入例（数字は架空）

> ① 2件／② 9.1%（LP表示 230・予約ページ 21）／③ 2件（SMS 1・LINE 1）／④ 0／⑤ ¥21,000
> → 順1 非該当、順2 非該当、**順3 該当：A をオーナーへ**。④ が0なので GBP の着地の直しを web-inflow へ。11月の主の指標は ①2＋③2＋直接 … ＝ 残り◯件

## 4. 判定の後

- 結論と5つの値を、MTGシート 7-4 No.5 の結果欄と `docs/2026-11月ネット10件の経路別逆算.md`（11/1 の置き直し）に書く
- A を出したときの承認の文は CMO が作る（金額・期間・見込み件数・止める条件）。止める条件の案：**A を始めて14日で、増えた分のクリックから受注0件なら元に戻す**


## 5. 上げた分だけを測る（オーナー決定 10/16「上げてもいいが効果を確認できる前提」）

measurement の `docs/広告-増額の測り方.md`（measurement ブランチ 5b6aa999）を、上げ幅 **¥5,000 → ¥7,000** に合わせて入れた。

| 項目 | 中身 |
|---|---|
| 上げる前に | ⓪ を確かめる（制限が出ていなければ上げても増えない） |
| 期間 | **上げる前の14日（基準）と、上げた日からの14日**を比べる。増額期間中は C対E の振り分け以外の変更を入れない（入れたら日付をこのシートに書く） |
| 指標 | **上げた分の申込1件あたり ＝ 増えた費用 ÷ 増えた申込**。増えた費用＝（増額期間の1日平均 − 基準の1日平均）×14（広告_日次）。申込は**予約_Web の `src=gads_*`**（Google広告の CV は使わない）。受注率は見張り |
| 続ける | 上げた分の申込1件あたりが **¥16,200 以下** |
| 戻す（14日目） | 増えた申込が **0件以下**、または上げた分の申込1件あたりが **¥16,200 超** |
| 途中で戻す（7日目） | **増えた費用が ¥14,000 を超えた（日¥2,000×7日）のに、増えた申込が0件** |
| 判断が割れたとき | 申込は1桁なので、差がはっきりしなければ14日延ばす（戻す条件は生きたまま） |
| 季節の注意 | 10月後半〜11月は上げなくても申込が増えうる。**前年の同じ時期の申込（台帳）を並べて、季節の分を差し引いて読む** |
| 受注の判断 | 申込から施工まで1〜2週間ずれるので、増額期間の申込が施工まで済んでから |

- 上げ幅を変えるときは、途中で戻す線を「日の増加額 × 7日」に直す（例：¥5,000→¥7,500 なら ¥17,500）
- ¥16,200 は申込1件あたり。受注率83%なら受注1件あたり約¥19,500 で、LTV の線（次の1回までで回収 ¥30,500）の内側
