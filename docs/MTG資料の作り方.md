## 2. レイアウトの決まり

**値は `tools/format-mtg-sheet.py` がそのまま読んで判定している。目分量で決めず、下の記号をそのまま使うこと。**

### 2-1. 行の種類と色（`tools/format-mtg-sheet.py` の値をそのまま）

| 行の見分け方（A列） | 背景色 RGB | 文字 | 何に使うか |
|---|---|---|---|
| `━` で始まる | `55,71,79`（濃紺グレー） | 白・太字・12pt | **回の区切り**。`━━━…　第N回　YYYY-MM-DD　◯◯の回　━━━…` |
| `■` で始まる | `207,216,220`（薄いグレー） | 太字・11pt | **章見出し**。`■ 3-1　会社の数字（出典：…）` |
| A列が `No.` `区分` `月日` `状態` `提携先` `月` のどれか、かつ中身が3つ以上ある | `236,239,241`（もっと薄いグレー） | 太字 | **表の見出し行** |
| `【` で始まる | （塗らない） | 太字 | 章の中の小見出し（`【A】` `【現状の数字】` など） |
| 行のどこかに `🔴` がある | `255,235,238`（薄い赤） | — | **見落とすと困るもの** |
| 行のどこかに `✅` がある | `232,245,233`（薄い緑） | — | **済んだもの** |
| `★` で始まる | `255,248,225`（薄い黄） | 太字 | **今日いちばん見てほしいところ** |
| 1行目 | `55,71,79` | 白・太字・14pt | シートのタイトル。**1行目は固定**される |

判定は上から順で、**最初に当たったものだけが効く**（`🔴` の行でも A列が `■` なら章見出し色になる）。

### 2-2. 列の役割（A〜I の9列。これ以外の列は使わない）

**「今日決めること」の表＝9列の正式な形。これを基準にする。**

| 列 | 幅(px) | 見出し | 中身 |
|---|---:|---|---|
| A | 54 | `No.` | 連番。**この列が `No.` かどうかでプルダウンの範囲が決まる** |
| B | 210 | `区分` | 記録／提携／年末／受注／実行／台帳／報酬／広告／SMS など |
| C | 250 | `議題` | 一言で |
| D | 290 | `論点・背景` | 数字と出典。**いちばん広い列** |
| E | 250 | `決めること` | **オーナーが「はい／いいえ」または一択で答えられる形**にする |
| F | 74 | `決定` | **プルダウン**（決定／保留／取り下げ／持ち帰り）。オーナー記入欄 |
| G | 260 | `決定内容・メモ` | オーナー記入欄。**空で出す** |
| H | 62 | `期限` | 本日／今週／今月／済 |
| I | 92 | `担当` | 嶺／和真／マーケ部長／両者／ブラウザ担当 など |

ほかの表も**同じ9列の中に収める**（列数が少ない表はA列から詰める）。実際の例：

| 表 | 列 |
|---|---|
| 前回の決定の追跡（3-2） | `No.`／`議題`／`◯/◯ の決定`／`いまの状況`／`次に動かす人`／**`更新情報`（F列＝オーナー記入欄）** |
| 和真さんへの確認（3-3【B】） | `No.`／`確認したいこと`／`なぜ`／**`回答`（D列＝和真さん記入欄）** |
| 会社の数字（3-1） | `区分`／`実績・受注`／`予算`／`達成率`／`補足` |

> **F列は「相手が書き込む列」**（決定表・3-2）。3-3【B】だけは D列が回答欄。
> 相手が書く列は**必ず空にして出す**。こちらの想定を書き入れない。

### 2-3. 結合・折り返し・プルダウン

| 何 | 決まり |
|---|---|
| 折り返し | **全セル `WRAP` ＋上揃え ＋10pt**。いちばん効く。長い文章が切れずに読める |
| 折り返さない行 | **1行目と「━━━ 第N回 …」の区切り行だけは `OVERFLOW_CELL`（はみ出して表示）・高さ 21px。** オーナー指示 2026-09-26「1行目や333行目の日付変更行を毎回僕が直してるから、初めから僕と同じようにセル内で行を折り返さないようにしてね。行が太くなりすぎて見づらいから」。ツールが自動で当てる。1行目は結合しない |
| 行の高さ | 結合のあとに自動調整（`autoResizeDimensions`） |
| 結合 | **A列だけに中身があり、30文字以上の行**（または `■` で始まる行）は **A〜I を結合**して横幅いっぱいに。→ 説明文が縦に伸びない |
| プルダウン | A列 `No.` かつ F列 `決定` の見出し行を機械で見つけ、**その下の連番行**（A列が数字だけ）に `決定／保留／取り下げ／持ち帰り` を当てる。`strict:false`（手入力も通る）。**F〜G列は薄い黄（`255,248,225`）で塗る＝未記入が目立つ** |
| 回が増えたとき | プルダウンは見出しから自動で見つける。**手で範囲を指定しない** |

### 2-4. 数値の書式（`tools/format-mtg-numbers.py`）

| 種類 | 書式 | 見え方 |
|---|---|---|
| 金額 | `CURRENCY` / `"¥"#,##0` | `¥1,120,607` |
| 割合 | `PERCENT` / `0.0%` | `94.5%` |
| 件数 | `NUMBER` / `#,##0` | `1,005` |

- **値ではなく「列の見出しの文字」で振り分けている。**
  割合＝`達成率` `割合` `率` `比` ／ 件数＝`件数` `日数` `月数` `回数` `通数` `人数` `台数` `文字数` `数量` ／
  金額＝`売上` `金額` `予算` `実績` `受注` `利益` `給与` `報酬` `単価` `差` `累計` `販売管理費` `経費`
- 語で拾えない見出し（`今朝の台帳` `いま` `うち早期予約…` など）は、ツールの `MIDASHI_MEIJI` に**名指しで足す**。
  **見出しを書き換えたら、ここも直すこと**（9/19 に `補った後` → `いま` に変えて追加した実例あり）。
- **判定できない列の数値は触らない。** 間違った書式を当てるより素のままのほうがまし。
- 安全弁：`割合` 列でも 0〜1 でなければ触らない／`金額` `件数` 列でも 0〜1 の小数なら触らない。
- 頭に `'` を付けた文字セル（`'9/08` `'28,160`）には数値書式は効かない。**害は無いので、無理に数値へ戻さない。**

## 3. ★作る順番（いちばん大事）

**値を入れ直したら、必ずこの順で流す。**（`tools/format-mtg-sheet.py` の docstring が正）

```
1. 値を入れる（sheets_client.py の write）
2. python3 tools/format-mtg-sheet.py   --jikkou   # 色・折り返し・結合・プルダウン
3. python3 tools/format-mtg-numbers.py --jikkou   # ￥・％・3桁区切り
4. python3 tools/link-mtg-sanshou.py   --jikkou   # リンク　★かならず最後
```

| なぜこの順か | 理由 |
|---|---|
| **リンクが最後** | `format-mtg-sheet.py` は `repeatCell` でセル全体の `userEnteredFormat.textFormat` を上書きする。リンクは `textFormatRuns` と `textFormat.link` に入っているので、**後から流すと消える。** 2026-09-19 に **65本 → 33本** に減らした |
| 数値書式はどこでもよいが2番目 | `format-mtg-numbers.py` は `fields` を `userEnteredFormat.numberFormat` に限定しているので、**色・折り返し・結合・プルダウンを壊さない。** ただしリンクより前に置く（同じ理由） |
| 全ツール `--jikkou` なしで先に実行 | どのセルに何を当てるかを一覧で出すだけ。**必ず目で見てから `--jikkou`** |

**流したあとの確認（毎回やる）**

- `format-mtg-numbers.py --jikkou` は、当てたあとに全セルを読み直して**値が1つも変わっていないことを自動で突き合わせる**。`🔴 値が変わったセル` が出たら止めて戻す
- `link-mtg-sanshou.py` は「リンクを張るセル数／本数」を出す。**前回より減っていたら、順番を間違えている**

## 4. リンクの決まり

> オーナー指示（2026-09-19）「同様に、ファイル内の特定箇所を指摘して議題に挙げる場合には、必ず該当箇所に飛べるリンクを埋め込んで。」

**本文で場所を指すときは、必ず下の書き方で書く。** そう書いておけば `tools/link-mtg-sanshou.py` が自動でリンクにする。

| 本文にこう書く | 飛び先 | 仕組み |
|---|---|---|
| `T032` | `TODO` タブのその行 | `T0nn` → **6 + nn 行**（TODOタブは7行目が T001）。gid `1240265810` |
| `9月_売上/顧客 19行` / `…19行目` | そのタブのその行 | タブ名から gid を引く |
| `12月タブ 行5` | `12月_売上/顧客` の5行目 | 同上 |
| `『提携先_休眠度』` / `「タブ名」` | そのタブ | **『』か「」で囲まれているものだけ**。囲まないと拾われない（誤爆防止） |
| `docs/受注フォーム.md` | GitHub のそのファイル | **リポジトリに実在するものだけ**。存在しないパスは張られない |
| `https://…` | そのまま | — |

- 見た目は**青字（RGB 0.10 / 0.33 / 0.65）＋下線**。本文はそのまま残す。
- 重なった指定は**先に見つけたほうを残す**（前から順）。

### 4-1. セル全体に張るときと、文字の一部に張るときで方法が違う

| 場合 | 使うもの | 理由 |
|---|---|---|
| **セルの中身がまるごとリンク対象**（例：セルに `9月_売上/顧客 19行` しか書いていない） | `userEnteredFormat.textFormat.link` | `textFormatRuns` で全体を覆うと、**Sheets が「セルの書式と同じ」とみなして正規化で落とす**（2026-09-19 実測） |
| **文章の中の一部だけがリンク対象** | `textFormatRuns`（`startIndex` で区切る） | セル全体を `=HYPERLINK()` にすると**1セルに1本しか張れず、本文も消える** |

`link-mtg-sanshou.py` は両方に対応済み。**自分で `=HYPERLINK()` を書かないこと。**

### 4-2. T番号は本文に残して、末尾に対応表を置く

本文の `T0xx` はそのままにする（注釈を差し込むとセルが長くなり、かっこが二重になって読みにくい）。
代わりに**最後の章として「この回で出てくる T番号」の対応表**を置く（`tools/fix-mtg-sanshou.py` が作る）。
**見出しは TODOタブの文言をそのまま引く**（言い換えるとTODO側と食い違う）。

### 4-3. 「前回#N」と書かない

1枚に統合した結果、**同じシートに「No.1」が4つある**（第1回／第2回■4／第2回■5／第3回3-2）。
「前回#3」ではどの表の3番か決まらない。**必ず `第1回 #3` のように回を明記する。**

## 5. 各回の構成（章立て）

**毎回この形にする。** 番号は回に合わせる（第4回なら 4-1〜4-9）。
下は第3回（2026-09-19）の実物。

| N-2 | 前回に決めた◯項目の、いまの状況 | 前回の決定を1行ずつ追う。`いまの状況`／`次に動かす人`／`更新情報`（オーナー記入欄） | 前回の表をコピペ |

| N-5 | この回で新しく分かったこと | 事故・実測で分かったこと。重要なものは `🔴` を付ける | 実測値を書く |

### 5-1. ★N-9「次回MTG日程の決定」（オーナー指示 2026-09-19・必須）

```
3 | 日程 | 次回までの宿題の確認 | 今日「決定」が付いた項目のうち、次回までに動かすもの | 誰が・何を・いつまでに | （空） | （空） | 本日 | 両者
```

- **決まった日時は、その場で Google カレンダーに入れる**（MTG後の作業。6-3 参照）。
- 決まらなかったら `保留` を選んでもらい、**いつまでに決めるか**を G列に書いてもらう。**空のまま閉じない。**

## 7. やってはいけないこと

| 禁止 | 理由・根拠 |
|---|---|
| **過去回の内容を書き換える** | オーナー指示（2026-09-19）「過去分は記録を君が変更しないように、コピペで編集してね」。第1回（1〜32行）・第2回（33〜155行）は**1文字も触らない**。作り直すときは git の控え（`data/sheets/backup/MTG_2026-09-04.json.gz` など）から復元し、**1行ずつ突き合わせて食い違い0件を確認してから**次へ進む |
| **MTGタブを増やす** | 回ごとにタブを作らない。**`MTGシート` 1枚に古い順に積む。** 別タブを作ったら、その日のうちに統合して古い方を消す（消す前に控え＋突き合わせ） |
| **控えを取らずに直す** | `data/sheets/backup/` に `.json.gz` を置いてから。CLAUDE.md「事後報告でよい範囲」の条件2 |
| **オーナーの決定を要約する** | **原文で引用する。** 要約すると意味が変わる（`docs/org/README.md` 4.6） |
| **`98.8%` を使う** | 正は **98.6%**（209名中206名／2023年1月〜2025年12月）。パンフレットとサイトの 98.8% は根拠と一致しない |
| **和真さんへの確認を行番号で書く** | 和真さんからの要望（`docs/cmo-savedata.md`）。**必ず氏名・社名で**書く。行番号は「台帳の場所」列にリンクとして添えるだけ |
| **説明のための説明を書く** | 背景を先に長く書くと、**何を答えてほしいのかが分からなくなる**。3-3【B】3番への回答は「指摘内容が意味不明」だった。**1セル＝1つの問い**にし、`確認したいこと` に問いだけ、`なぜ` に1行だけ書く |
| **確かめていないことを断定する** | `docs/org/README.md` 4.11。取れないときは **「未確認」と書く**。9/19 の 3-5 にはオーナーから「おそらくハルシネーション。要再確認」と入った行がある |
| **A列を空けて B列から書く** | 列がずれる。A列に日付書式が付いてしまったら、**書式の無い新しいタブへ作り直す。** 日付・数字に化けうる値は**先頭に `'`** を付けて文字として入れる |
| **`=HYPERLINK()` を手で書く** | 1セル1本しか張れず本文が消える。4章の方法を使う |
| **リンクの後に書式ツールを流す** | リンクが消える（3章） |
| **相手が書き込む列を埋めて出す** | F列「決定」・G列「決定内容・メモ」・`更新情報`・`回答` は**空で出す** |
