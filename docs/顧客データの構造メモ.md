# 顧客データの構造で、把握しておくべきこと

最終更新：2026-09-07

分析やリスト生成のたびに踏み抜いている落とし穴を、ここに集約する。
**新しいリストを作る前に必ず読むこと。**

## 1. 「実施メニュー」列は実態を表していない

プルダウンを**1つしか選べない仕様**のため、実際にやった箇所は備考欄にしか残っていない回がある。

```
実施メニュー：エアコン(ノーマル)
備考：ノーマル1.浴室1.浴室換気扇1.エプロン内部1.
```

2026年分だけで21行・14名が該当。
**「このメニューを買っていない人」を実施メニュー列だけで判定すると、
既に施工済みのお客様へ売り込む電話・SMSになる。**

→ 必ず備考欄の全文キーワード照合を併用する
（浴室・風呂・換気扇・レンジフード・キッチン・洗濯機・トイレ・洗面・エプロン・追い焚き など）。

## 2. 紹介者と実際のご利用者が別

**紹介者＝法人、エンドユーザー＝個人** という案件がある。

例：`青山リアルティ・アドバイザーズ株式会社` の行で、TEL欄に `和美躰` と入っている。
これはデータの壊れではなく、**紹介者が青山リアルティ、実際のご利用者が和美躰さん**という関係。

同種の例：`江新エンジニアリング(堀江　里香さま)` と `堀江　里香` が別レコードで存在する。

→ 現状は氏名欄・TEL欄に押し込まれている。**紹介者と利用者を分けて持てる列が要る。**
　 紹介料の計算（消費者紹介は一律1,000円／事業者紹介は5〜15%・原則12%）にも効く。
→ リストを作るときは、TEL欄に数字以外が入っている行を「壊れ」と判断しないこと。

## 3. TELの表記ゆれ

全1,487件中6件が異常値。

| 型 | 例 |
|---|---|
| 2番号併記 | `0358780339/09065235985` |
| 桁数過多 | `070447793940`（12桁） |
| 氏名の混入 | `和美躰`（＝上記2の構造） |
| 半角スペース入り | — |
| 桁数不足 | `0802099777`（10桁・080始まりで1桁欠け／山口　英雄さん）★要確認 |

**`再販リスト` タブのTELは先頭の0が落ちている**（例 `9046722646`）。**架電・配信に使わないこと。**

## 4. 流入経路は「初回の入口」ではない

`冬季見込み客_2026` や `再販リスト` の流入経路は、**その年の最終施工時**の値。
初回が楽ラクーンでも、2回目以降がリピートなら「リピート」になる。

「初回の入口別LTV」を見たいときは `docs/流入経路の分析.md` を参照
（初回の入口で集計しなおしたもの。マッチングPFのリピート率2%はこちら）。

## 5. 「送信系統」列が接触可否の判定軸

`冬季見込み客_2026` の `送信系統` 列が `自社` / `本舗` に分かれている。
**`本舗` はおそうじ本舗経由・マッチングサイト経由のお客様。**
ワンヒッターから直接ご案内してよいかは契約次第で、**2026-09-07時点で未確認・判断待ち**。

優先1だけで11名、2026年のクロスセル対象133名では82名がこの層。

## 6. 未来日の予約が混ざる

「2026年に施工」で抽出すると、まだ作業していない先の予約（2026/10〜11）が5名入る。
同時提案の好機ではあるが、**架電トークは分けること**（「先日は」と言えない）。

## 7. 元データの欠落（既知・未修正）

株式会社レジェンドの **2024/06/28 ¥54,120** が、
`【毎月更新】リピート/業務提携` タブにはあるのに 2024年の月次タブに存在しない。
顧客管理台帳の総受注額との差 ¥54,120 はこの1件が原因。

**過去の実績データのため、CMO側では書き換えない。** 修正はオーナー判断。

## 8. Drive経由でシートを読むと途中で切れる

`mcp__Google_Drive__read_file_content` は大きいシートを最後まで返さない。

| タブ | 実際 | 読めた分 |
|---|---|---|
| 顧客管理台帳 | 957名 | 62行 |
| 冬季見込み客_2026 | 965名 | 146行 |

集計タブが切れていても、**月次タブ（1月〜12月の売上/顧客）は完結して読める。**
正確な集計が要るときは、集計タブではなく月次タブ48枚（2023〜2026）から作り直すこと。
