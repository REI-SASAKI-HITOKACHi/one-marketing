## これで何が変わるか

いまは、SMSやLINEを見たお客様が電話をかけてきて、渡辺さんが現場から出て
日程を口頭で調整しています。**この往復がなくなります。**

```
今            お客様 → 電話 → 渡辺さんが現場で出る → 口頭で日程調整 → カレンダーに手入力
これから      お客様 → フォームで空き枠から選ぶ → 【仮】でカレンダーに入る → 確認の電話1本
```

- お客様には**渡辺さんが本当に空いている時刻だけ**が出ます。予定の中身は一切出しません
- 入った予約は**カレンダーに【仮】で入り**、グループLINEに通知が飛びます
- **【仮】のままでは確定ではありません。** 確認の電話をして、渡辺さんが【仮】を外します

いきなり確定にしないのは、フォームのURLを知っていれば誰でも送信できるからです。
現場を人が押さえる形は変えません。

## 手順2（佐々木さん）Apps Script を置く

**所要5分。** LINEのwebhookを入れたときと同じ流れです。

1. スプレッドシート「2026_売上/顧客情報管理」を開く
2. **［拡張機能］→［Apps Script］**
3. リポジトリの **`tools/booking-api.gs`** の中身をすべてコピーして貼り付け、保存
   - LINE webhookと同じプロジェクトで構いません。新しいファイルとして追加してください
4. 左メニュー **［プロジェクトの設定］**
   - **タイムゾーンが「東京」**になっているか確認する
     （UTCのままだと空き枠が9時間ずれます）
   - **［スクリプト プロパティ］**に次の2つを追加する
     | プロパティ | 値 |
     |---|---|
     | `LINE_TOKEN` | LINEのチャネルアクセストークン（webhookで使っているもの） |
     | `LINE_GROUP` | `Cdaad037f60f5bc8b2c8138ce0afffc78` |
   - この2つを入れないと、LINE通知だけが飛びません。予約自体は動きます
5. エディタで関数 **`kakunin`** を選んで［実行］
   - 初回は権限の承認ダイアログが出ます。許可してください
   - 実行ログに「書き込み: できました」と出れば手順1も含めて成功です
   - 「★ 書き込めません」と出たら、手順1の権限が「予定の表示」のままです
6. 右上 **［デプロイ］→［新しいデプロイ］→ 種類：ウェブアプリ**
   | 項目 | 値 |
   |---|---|
   | 説明 | 予約フォーム |
   | 次のユーザーとして実行 | **自分** |
   | アクセスできるユーザー | **全員** ← ここが「全員」でないとお客様から使えません |
7. 表示された **`https://script.google.com/macros/s/.../exec`** のURLを控える

> **注意：コードを直したら、毎回［デプロイ］→［デプロイを管理］→ 鉛筆マーク →
> バージョン「新バージョン」→［デプロイ］**をしてください。
> 保存しただけでは公開中のURLに反映されません。

## 運用

### 予約が入ったとき

1. グループLINEに通知が飛びます（お名前は姓のみ・住所と電話は載せません）
2. カレンダーに **`【仮】〇〇様 メニュー`** の予定が入ります
   - お名前・お電話・ご住所・ご要望は**予定の詳細**に入っています
3. **渡辺さんが確認の電話をして、タイトルの【仮】を外す** → これで確定
4. スプレッドシートの **`予約_Web`** タブに全件残ります（状態は「未確認」で入ります）

### 空き枠の出しかた（変えたいときは `tools/booking-api.gs` の `SETTEI`）

| 設定 | いまの値 | 意味 |
|---|---|---|
| `kaishiJikoku` / `shuuryouJikoku` | 9 / 18 | 9:00〜18:00 に収まる枠だけ出す |
| `idouFun` | 60 | 前後の予定との間に1時間の移動時間を空ける |
| `kyuusokuFun` | 360 | 夜勤明けは、終了から6時間は枠を出さない |
| `saitanNichi` / `saichouNichi` | 2 / 21 | 明後日から3週間先まで |
| `kizamiFun` | 30 | 30分刻み |

**終日予定（TODO）は塞がりとして扱いません。** TODOが1件あるだけで
その日が予約不可になってしまうためです。実際の施工・バイト・通院は
すべて時刻の入った予定なので、これで足ります。

### 実データで確かめた結果（2026-09-08 時点）

渡辺さんのカレンダーをそのまま入れて計算しました。

| 日 | 出る枠 | 理由 |
|---|---|---|
| 9/16（水） | 11:00〜 | 前夜のバイトが5:00まで → 休息6時間 |
| 9/17・9/18 | なし | クラスリフォーム 9:00〜18:00 |
| 9/20（日） | 13:00〜 | 健康診査 9:00〜12:00 ＋移動1時間 |
| 9/24（木） | なし | 加藤木さま 9:00〜19:00 |
| 9/28（月） | 〜15:00開始 | 18:00からの土建に間に合うように |

## 料金の出しかた

`data/prices.json` から生成しています。**手で書き写していません。**
価格を変えるときは `data/prices.json` を直して `python3 tools/build-booking.py` を再実行します。

- 2箇所目以降は**同時施工価格**
- **1箇所のときだけ早期予約割引**（複数箇所は同時施工割引と併用しない、というルールのため）
- 5・6・7・12月は**1箇所あたり +3,300円**の繁忙期加算
- 画面には必ず「**概算です。確定金額は担当からのお電話でお伝えします**」と出ます
