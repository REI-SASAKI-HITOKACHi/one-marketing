# LINE公式アカウントをAPI（Messaging API）で運用する

調査日: 2026-09-05 / 調査対象: LINEヤフー公式ドキュメント（developers.line.biz / lycbiz.com）のみ
前提: ワンヒッター株式会社は**すでにLINE公式アカウントを運用中**（LP上のリンク `https://lin.ee/7kD9WGN`）。
このドキュメントは「既存アカウントに Messaging API を後付けする」ケースを扱う。

> 本文中、公式ドキュメントで確認できた画面名・ボタン名は［ ］で示す。
> 裏が取れなかったものは **「公式に記載なし・要確認」** と明記した（§7に一覧）。

---

## 1. 結論

- **できる。** 既存のLINE公式アカウントに Messaging API を後付けでき、CMO（AIエージェント）からプッシュ／マルチキャスト／ナローキャスト配信、**クーポンの作成と配布**、リッチメニューの操作、友だち追加イベント（Webhook）の受信、友だちの表示名・ユーザーIDの取得ができる。
- **クーポンはAPIで配れる。** 2025年8月にクーポンAPIが追加され、`POST /v2/bot/coupon` で「1,000円割引」を固定額で作成し、クーポンメッセージとして送信できる。紹介者割引の自動配布は実現可能。
- **既存運用は基本的に壊れない。** 友だち・チャット・あいさつメッセージ・応答メッセージ・OAM側のリッチメニューは並存する。ただし**Messaging APIチャネルとの紐づけは後から解除できない**（プロバイダー変更も不可）。これが唯一の不可逆操作。
- **費用はプラン次第。** Messaging API 自体の利用料はなく、送信通数がLINE公式アカウントの料金プランにそのままカウントされる。月200通以内なら¥0、超えるならライトプラン月額¥5,000（税別）。
- **注意点2つ。** ①ナローキャスト（属性配信）はターゲットリーチ100人以上・送信対象50人以上でないと使えない。②友だち全員のユーザーID一覧取得は**認証済アカウント限定**。

## 2. 有効化の手順

**所要: 15〜30分。オーナー本人（管理者権限を持つLINEアカウント）が操作する必要がある。**

### フェーズA：LINE公式アカウントマネージャー側（manager.line.biz）

> 出典: [LINEヤフー for Business「Messaging API」マニュアル](https://www.lycbiz.com/jp/manual/OfficialAccountManager/account-settings_messaging_api/)
> ※「**管理者**」権限をもつユーザーのみ操作が可能。**WEB版管理画面からのみ**設定可（スマホの管理アプリからは不可）。

1. [LINE公式アカウントマネージャー](https://manager.line.biz/)にログインし、対象のアカウント（ワンヒッター）を選ぶ。
2. 画面右上の「**設定**」＞「**Messaging API**」を選択する。
3. 「**Messaging APIを利用する**」をクリックする。
4. **プロバイダーを作成**する（または既存のプロバイダーを選択する）。
   - プロバイダーとは「チャネルを管理する事業者の単位」。**入力するのはプロバイダー名だけ**。
   - 推奨: `ワンヒッター株式会社` など、自社名そのもの。
   - ⚠️ **プロバイダーは後で変更できません。** 公式マニュアルに「※プロバイダーは後で変更はできません。プロバイダー設定・作成する際は十分に確認してください」と明記されている。
   - ⚠️ 代理店や外部ツール会社が管理するプロバイダー配下には作らないこと。公式ドキュメントも「チャネルの運用ツール等を運営するサービス（企業）が管理するプロバイダーの配下にチャネルを作成する」ケースを名指しで注意喚起している。
   - 将来LINEログインやLINEミニアプリと連携する予定があるなら、そのチャネルと同じプロバイダーにする。
5. 「**同意する**」をクリックする。
6. 確認画面が出るので「**OK**」をクリックする。→ **Messaging APIが有効になる。**

> **初回のみ:** LINE公式アカウントマネージャーのログインアカウントで LINE Developers コンソールに初めてログインする場合、途中で**開発者情報を登録する画面**が表示される。**名前とメールアドレス**を入力して開発者アカウントを作成する。
> 出典: [LINE Developers「Messaging APIを始めよう」](https://developers.line.biz/ja/docs/messaging-api/getting-started/)

### フェーズB：LINE Developersコンソール側（developers.line.biz/console）

7. [LINE Developersコンソール](https://developers.line.biz/console/)に、**手順1と同じアカウント**でログインする。
8. 手順4で選んだ**プロバイダー**をクリック → 作成された**Messaging APIチャネル**をクリックする。
9. **チャネルシークレットを控える。**
   ［**チャネル基本設定**］タブを開く。ここに**チャネルID**と**チャネルシークレット**がある。
   （取得にはチャネルのAdmin権限が必要。同タブの［**発行**］を押すと再発行でき、再発行すると現在のシークレットは無効になる。）
   出典: [Webhookの署名を検証する](https://developers.line.biz/ja/docs/messaging-api/verify-webhook-signature/)
10. **チャネルアクセストークンを発行する。**
    ［**Messaging API設定**］タブを開く。長期のチャネルアクセストークンはこのタブからいつでも発行できる。
    → どのトークンを使うべきかは下の「トークンの選び方」を参照。
11. **（Webhookを使う場合のみ）Webhook URLを設定する。**
    出典: [ボットを作成する](https://developers.line.biz/ja/docs/messaging-api/building-bot/)
    1. ［**Messaging API設定**］タブをクリック
    2. ［**Webhook URL**］の［**編集**］をクリックし、HTTPSのURLを入力して［**更新**］をクリック
       （自己署名証明書は不可。一般に信頼されている認証局のSSL/TLS証明書が必要）
    3. ［**検証**］をクリック。受信できていれば「**成功**」と表示される
    4. ［**Webhookの利用**］を有効にする
    ※ 配信するだけ（友だち追加イベントを受けない）なら、この手順11はスキップしてよい。
12. **（任意・長期トークンを使う場合）呼び出し元IPを制限する。**
    ［**セキュリティ設定**］タブでIPアドレス（個別またはCIDR記法）を登録すると、そのIPからしかAPIを呼べなくなる。

### トークンの選び方（長期 vs ステートレス vs v2.1）

出典: [チャネルアクセストークン](https://developers.line.biz/ja/docs/basics/channel-access-token/)

| 種類 | 有効期間 | チャネルごとの発行数 | 発行方法 | 取り消し |
|---|---|---|---|---|
| **長期** | **無期限** | 1 | LINE Developersコンソールの［Messaging API設定］タブ | できる |
| **チャネルアクセストークンv2.1** | 最大30日（自分で指定） | 30 | API（JWTを使う。事前にアサーション署名キーの登録が必要） | できる |
| 短期 | 30日 | 30 | API | できる |
| **ステートレス** | **15分** | 無制限 | API（チャネルID＋チャネルシークレットから発行） | **できない** |

- 公式の推奨は **v2.1**（[ボットを作成する](https://developers.line.biz/ja/docs/messaging-api/building-bot/)に「（推奨）」と明記）。ただし公開鍵の登録とJWT生成の実装が必要で、初期構築の手間が大きい。
- **今回の推奨: まず「長期のチャネルアクセストークン」で始める。**
  - 理由: コンソールのボタン1つで発行でき、更新の仕組みを作らなくてよい。オーナーの手作業をなくすのが目的なので、トークン更新のために人が介在する構成は本末転倒。
  - 代わりに、①［セキュリティ設定］タブでIP制限をかける、②漏洩時はすぐ取り消す、の2点で守る。
- **長期トークンの再発行**: 再発行すると現在有効な長期トークンは無効になる。ただし**再発行時に、現在のトークンの有効期間を最大24時間まで延長できる**ので、無停止で入れ替えられる。
- ステートレストークンは「チャネルを使うたびに発行する」設計。取り消せないので、漏れても15分で自然に無効になるのが利点。CMOの実行環境がトークンをファイルに置きたくない場合はこちらも選択肢。

## 3. 既存運用への影響と、元に戻せるかどうか

**ここが一番重要なので、確認できたことと確認できなかったことを分けて書く。**

### 3-1. 壊れないと公式で確認できたもの

| 機能 | Messaging API有効化後 | 根拠 |
|---|---|---|
| **チャット（手動応答）** | 使える。2022年11月30日以降、**Webhookとチャットは併用可能**になった（それ以前は［応答モード］で Bot / チャット の二者択一だった） | [LINE公式アカウントでWebhookとチャットが併用できるようになりました](https://developers.line.biz/ja/news/2022/12/01/use-both-chats-and-webhooks/)（※本文の直接取得はできず。§7参照） |
| **あいさつメッセージ** | 使える。LINE公式アカウントマネージャー側の設定がそのまま効く。LINE Developersコンソールの［Messaging API設定］タブにも［あいさつメッセージ］の［編集］があり、押すとOAMが開く（＝同じ設定を見ている） | [ボットを作成する](https://developers.line.biz/ja/docs/messaging-api/building-bot/) |
| **応答メッセージ（自動応答）** | 同上。使える。オフにすることもできる | 同上 |
| **リッチメニュー（OAMで作成済みのもの）** | 残る。**ただしAPIで作ったリッチメニューとは別管理**で、相互に編集できない | [リッチメニューを使う（概要）](https://developers.line.biz/ja/docs/messaging-api/rich-menus-overview/) |
| **メッセージ配信（OAMからの手動配信）** | 使える。APIと併用できる | [Messaging APIの料金](https://developers.line.biz/ja/docs/messaging-api/pricing/) |
| **クーポン（OAMで作成）** | 使える。逆に**APIで作ったクーポンをOAMからメッセージとして送信することもできる** | [クーポンを作成してユーザーに送る](https://developers.line.biz/ja/docs/messaging-api/send-coupons-to-users/) |

**リッチメニューの表示優先順位**（1が最優先）。既存のOAMリッチメニューは消えないが、APIでデフォルトを設定すると**そちらが優先表示される**ので注意。

1. Messaging APIで設定するユーザー単位のリッチメニュー
2. Messaging APIで設定するデフォルトのリッチメニュー
3. LINE公式アカウントマネージャーで設定するデフォルトのリッチメニュー

### 3-2. 挙動が変わる可能性があるもの

- **あいさつメッセージ／応答メッセージのデフォルト値**
  公式ドキュメントには「この［あいさつメッセージ］と［応答メッセージ］は、**チャネルを作成したとき**にデフォルトの設定が［有効］になっています」とある。
  → 新規アカウントの話なのか、既存アカウントに後付けした場合も既存設定を上書きするのかは**公式に記載なし・要確認**。
  → **対策: 有効化の直前に、［設定］＞［応答設定］と［あいさつメッセージ］の現在の設定内容をスクリーンショットで控えておく。** 有効化後に見比べれば5分で確認できる。

- **重複応答**
  あいさつメッセージ／応答メッセージをオンのままCMO側でもWebhookに応答すると、**ユーザーに2通届く**。公式も「開発者自身が混乱してしまうことがあります」「初めて作成するときは［オフ］にしておくことをお勧めします」としている。
  → **対策: 当面はWebhookの応答処理を実装せず、配信（プッシュ／クーポン）だけに使う。** 既存のあいさつ・応答メッセージはそのままオンで運用する。

### 3-3. 友だち・過去のメッセージ・クーポンはどうなるか

- **公式に「消える」「リセットされる」という記載は一切ない。** 手順上も、Messaging APIの有効化は「既存のLINE公式アカウントに Messaging APIチャネルを追加する」操作であって、アカウントの作り直しではない（公式手順に「既存のLINE公式アカウントでMessaging APIを有効にするには、手順2を参照してください」と明記）。
- ただし「**影響しません**」と明言した公式ページも見つけられなかった。**公式に記載なし・要確認**（§7）。
- 1点だけ確実な仕様上の制約: **APIで取得できる過去メッセージは Messaging API 経由のものだけ**で、LINE公式アカウントマネージャーから送信したメッセージは含まれない（[Messaging APIの概要](https://developers.line.biz/ja/docs/messaging-api/overview/)）。既存の配信履歴をAPIで遡って読むことはできない。

### 3-4. 元に戻せるのか — **半分だけ戻せる**

出典: [Messaging APIの利用を停止する](https://developers.line.biz/ja/docs/messaging-api/stop-using-messaging-api/) / [Messaging APIを始めよう](https://developers.line.biz/ja/docs/messaging-api/getting-started/)

**戻せること（機能の停止）**
1. LINE Developersコンソールで対象チャネルを選択
2. ［**Messaging API設定**］タブ →［**Webhook設定**］セクションの［**Webhookの利用**］を**無効**にする
3. チャネルアクセストークンを取り消す（種類ごとの取り消しエンドポイントを使う。※ステートレストークンは取り消せない）

→ これでAPIからの操作は完全に止まる。LINE公式アカウントは今まで通り使える。

**戻せないこと（不可逆）**
- ❌ **LINE公式アカウントとMessaging APIチャネルの紐づけは、後から解除できない。**
- ❌ **プロバイダーを後から別のものに変更できない。**
- ❌ **LINE公式アカウントを残したまま、Messaging APIチャネルだけを削除することはできない。**
- ❌ 上記の手順で停止しても**チャネル自体は残り続ける**。LINE Developersコンソールのチャネル一覧では他の利用中チャネルと見た目の区別がつかず、LINE公式アカウントマネージャーの［Messaging API］画面のステータスも「**利用中**」のままになる。

**判断**: 実害は「見た目が消えない」だけで、既存運用への機能的な影響はない。ただし**プロバイダー名だけは慎重に決める**こと（一度きり・変更不可）。

## 4. 料金

### 4-1. LINE公式アカウントの料金プラン

出典: [LINE公式アカウントの料金プラン](https://www.lycbiz.com/jp/service/line-official-account/plan/) / [Messaging APIの料金](https://developers.line.biz/ja/docs/messaging-api/pricing/)

| | コミュニケーションプラン | ライトプラン | スタンダードプラン |
|---|---|---|---|
| 月額固定費 | **¥0** | **¥5,000**（税別） | **¥15,000**（税別） |
| 無料メッセージ通数（月） | **200通** | **5,000通** | **30,000通** |
| 追加メッセージ | **不可** | **不可** | 〜¥3/通（税別・従量） |

- 初期費用なし。年払いなし（月払いのみ）。見積書の発行はできない。
- **アカウント開設時はコミュニケーションプランに設定されている。** 上位プランを使うには開設後にプラン変更が必要。
- **料金プランによって使える機能に差はない**（公式FAQ）。違うのは無料通数と追加メッセージの可否だけ。
- コミュニケーション／ライトは上限を超えると**配信できなくなる**（プラン変更が必要）。
- 支払いはクレジットカード。請求書払いは**認証済アカウントのみ**。
- 月中のアップグレードは差額支払いで即時適用＋差分の通数付与。

> **2026年10月1日に追加メッセージ料金が改定される**（20万通/月までは1通¥3、20万通超過分から1通¥2.5、税別）。
> これは**スタンダードプランの従量課金部分のみ**の改定で、月額固定費と無料メッセージ通数は変わらない。今回の想定利用量（数百通）には影響しない。
> 出典: [【重要：再掲】LINE公式アカウント 追加メッセージ料金改定のお知らせ](https://www.lycbiz.com/jp/news/line-official-account/20260216/)

### 4-2. API経由のメッセージは通数にカウントされるか → **される**

公式の料金ページとMessaging APIの料金ページ、両方で明記されている。

| カウント**される** | カウント**されない** |
|---|---|
| メッセージ配信（絞り込み配信・ステップ配信含む） | LINEチャットの送受信 |
| Messaging API の **Push API**（プッシュメッセージ） | **応答メッセージ**（Reply API） |
| Messaging API の **Multicast API**（マルチキャスト） | **あいさつメッセージ** |
| Messaging API の **Broadcast API**（ブロードキャスト） | |
| Messaging API の **Narrowcast API**（ナローキャスト） | |

**カウントの数え方（Messaging APIの場合）**
- 通数＝**送信対象となった人数**。1回のリクエストに指定したメッセージオブジェクトの件数は通数に影響しない。
  例: メッセージオブジェクトを4件指定したプッシュメッセージを5人のトークルームに1回送る → **5通**。
- **ブロック中のユーザーや存在しないユーザーIDに送った分はカウントされない。**
- リッチメニューの設置・更新はメッセージ送信ではないので**カウント対象外**（公式のカウント対象リストに含まれていない）。

### 4-3. Messaging API 自体の追加費用 → **なし**

- Messaging API の利用料という独立した課金項目は、公式の料金ページにもMessaging APIの料金ページにも存在しない。送信通数がプランにカウントされるだけ。
- クーポンAPI・リッチメニューAPI・プロフィール取得APIなどにも別途料金の記載はない。

### 4-4. 想定利用量での試算

**前提が1つ足りない: 現在の友だち数が不明（要確認）。** 通数＝配信回数×友だち数なので、これが決まらないと確定しない。

| 想定 | 月の通数 | 必要プラン | 月額（税別） | 月額（税込10%） |
|---|---|---|---|---|
| 友だち50人 × 月2回配信 | 100通 | コミュニケーション | **¥0** | **¥0** |
| 友だち100人 × 月2回配信 | 200通 | コミュニケーション（ぴったり上限） | **¥0** | **¥0** |
| 友だち150人 × 月2回配信 | 300通 | **ライト** | **¥5,000** | **¥5,500** |
| 友だち300人 × 月2回配信 | 600通 | **ライト** | **¥5,000** | **¥5,500** |
| 友だち500人 × 月4回配信 | 2,000通 | **ライト** | **¥5,000** | **¥5,500** |
| 友だち1,000人 × 月5回配信 | 5,000通 | **ライト**（ぴったり上限） | **¥5,000** | **¥5,500** |

**結論: 「月に数百通」なら、200通を超えた時点でライトプランの月額¥5,000（税別）が必要。それ以上の費用はかからない。**
プッシュ／マルチキャストを使い分けても単価は同じ（人数で数えるため）。ライトプランの5,000通に収まる限り、月額は¥5,000で固定。

**節約のコツ**
- クーポン配布を「全員へのブロードキャスト」ではなく「該当者だけへのプッシュ／マルチキャスト」にすると通数を大幅に削減できる。紹介者割引は該当者だけなので、**プッシュで十分**（数通〜数十通で済む）。
- 応答メッセージ（Reply API）はカウントされないので、ユーザーからの問い合わせへの自動返信は通数を消費しない。

**確認事項: 現在契約中のプランが何か（要確認）。** LINE公式アカウントマネージャーの［設定］＞［利用と請求］で確認できる。

## 5. APIでできること・できないこと

| やりたいこと | 可否 | 手段・制約 |
|---|---|---|
| **特定の友だちにメッセージを送る** | ⭕️ | `POST /v2/bot/message/push`。宛先はユーザーID。友だち追加済み or メッセージを送ってきたユーザーが対象。**1通としてカウント** |
| **複数人にまとめて送る（マルチキャスト）** | ⭕️ | `POST /v2/bot/message/multicast`。**1リクエストあたり最大500ユーザーID**。グループトーク・複数人トークには送れない。人数分カウント |
| **全友だちに一斉送信（ブロードキャスト）** | ⭕️ | `POST /v2/bot/message/broadcast`。人数分カウント。レート制限60リクエスト/時 |
| **属性やオーディエンスで絞って送る（ナローキャスト）** | ⚠️ | `POST /v2/bot/message/narrowcast`。**属性指定はターゲットリーチ100人以上が必須**（未満は403）。さらに**最終送信対象が50人以上**でないと送信開始時にエラー。友だちが少ないうちは実質使えない。非同期送信なので進行状況APIで確認する |
| **クーポンの配布（紹介者割引1,000円）** | ⭕️ | ①`POST /v2/bot/coupon` でクーポン作成（`reward.priceInfo` に `type:"fixed"`, `fixedAmount:1000` で1,000円割引を指定可）→ ②返ってきた `couponId` を**クーポンメッセージ**として push / multicast / broadcast / narrowcast / reply のいずれかで送信。**抽選形式**（`acquisitionCondition.type: "lottery"`）も指定できる |
| クーポンの修正 | ❌ | 作成後の内容変更は不可。変えたければ終了させて作り直す。「下書き」保存もAPIでは不可（OAMなら可） |
| クーポンの終了 | ⭕️ | `PUT /v2/bot/coupon/{couponId}/close`。**終了させると獲得済みユーザーも使えなくなり、再有効化はできない** |
| クーポンの一覧・詳細取得 | ⭕️ | `GET /v2/bot/coupon` / `GET /v2/bot/coupon/{couponId}`。有効なクーポンは最大5,000件まで作成可能 |
| **リッチメニューの操作** | ⭕️ | 作成・画像アップロード・デフォルト設定・ユーザー単位のリンク／解除・削除・統計取得。1アカウントあたりAPI経由で最大1,000件。**OAMで作ったものはAPIから編集できない（逆も同じ）** |
| **友だち追加イベントの受信（Webhook）** | ⭕️ | **フォローイベント**（友だち追加／ブロック解除時）、**フォロー解除イベント**（ブロック時）、メッセージイベント、ポストバックイベントなど。Webhook URLは1つだけ。**署名検証（チャネルシークレットでHMAC-SHA256）は必須** |
| **友だちの表示名・ユーザーIDを取得** | ⭕️ | `GET /v2/bot/profile/{userId}` → `displayName`（表示名）, `userId`, `language`, `pictureUrl`, `statusMessage`。**ユーザーIDはWebhookイベントから取得する**（LINEアプリに表示される「LINE ID」は使えない） |
| 友だち**全員**のユーザーID一覧を取得 | ⚠️ | `GET /v2/bot/followers/ids`。**認証済アカウントまたはプレミアムアカウント限定**（未認証アカウントは403）。ブロック中・プロフィール取得に未同意・LINEアカウント削除済みのユーザーは含まれないため、OAMに表示される友だち数とは一致しない |
| 友だち数の取得 | ⭕️ | `GET /v2/bot/insight/followers?date=YYYYMMDD`。レート制限60リクエスト/時 |
| **氏名・電話番号・メールアドレスの取得** | ❌ | Messaging APIに該当エンドポイントは存在しない。取得できるのはLINE上の**表示名**のみで、本名とは限らない |
| ユーザーIDから顧客台帳と突き合わせる | ⚠️ | ユーザーIDは**プロバイダーごとに別々の値**が割り当てられる。ユーザーが同じでもプロバイダーが違えば別IDになる。台帳との紐づけは「クーポン利用時に本人に名乗ってもらう」「LINEログイン／LIFFで別途情報を取得する」などの設計が必要 |
| 「この人は友だちか」を判定 | ❌ | 特定ユーザーがフォロワーかを直接確認する方法はない（公式FAQに明記）。プロフィール取得が404かどうかで間接的に推測するしかない |
| 過去の配信履歴（OAM側）の取得 | ❌ | APIで取得できるのはMessaging API経由のものだけ |

### プライバシー上の制約

- プロフィール情報の取得には**ユーザーの同意**が必要。iOS版／Android版LINEを使っているユーザーは利用開始時に同意済みなので実質問題ないが、**PC版LINEだけを使っているユーザーは同意できない**ため、表示名もユーザーIDも取得できない（Webhookのイベントオブジェクトにも含まれない）。
- 以下のいずれかに当てはまるとプロフィールは取れない: 同意していない／友だち追加していない／友だち追加後にブロックした。
- サブプロフィールは取得できない（メインプロフィールのみ）。

## 6. チャネルアクセストークンの安全な渡し方

### 漏れると何ができてしまうか

公式ドキュメントが挙げている具体例をそのまま引く。

> 例えばMessaging APIの場合、ブロードキャストメッセージという「LINE公式アカウントと友だちになっているすべてのユーザーに、同じメッセージを送る機能」があります。チャネルアクセストークンが漏洩すると、**第三者がブロードキャストメッセージを送信でき、結果として悪意のあるメッセージがすべての友だちに送信されてしまいます。**
> — [チャネルアクセストークン](https://developers.line.biz/ja/docs/basics/channel-access-token/)

これに加えて、トークンを持つ第三者は次のこともできる。

- 友だち全員へのメッセージ送信（＝**通数を消費し、課金が発生する**。スタンダードプランなら青天井）
- リッチメニューの差し替え・削除（トーク画面の見た目が乗っ取られる）
- クーポンの作成と配布、および**既存クーポンの強制終了**（獲得済みユーザーも使えなくなる／復活不可）
- 認証済アカウントであれば、友だち全員のユーザーIDと表示名の吸い出し

**Webhookの署名検証に使うチャネルシークレットも同じくらい重要**（漏れると偽のWebhookをボットサーバーに送り込める）。

### 保管と受け渡し（一般論）

**やること**
- **リポジトリに絶対にコミットしない。** `CLAUDE.md` の禁止事項どおり。`.gitignore` に入れるだけでなく、そもそもリポジトリ配下に置かない。
- **環境変数、またはシークレットマネージャーに置く。** 実行環境の秘密情報ストア（例: GitHub Actions Secrets、クラウドのSecret Manager、`.env` をリポジトリ外に配置）を使う。
- **受け渡しはチャット・メール本文に貼らない。** パスワードマネージャーの共有機能か、閲覧後に自動削除されるワンタイムURLを使う。どうしてもテキストで渡す場合は、渡した直後にトークンを再発行して古いものを無効化する運用にする。
- **［セキュリティ設定］タブでIP制限をかける。** 長期トークンを使うなら必ず設定する。CMOの実行環境のIPが固定できるなら、これが最も効く防御。
- **ログに出さない。** APIのリクエストヘッダーをそのままログに落とさない。
- **漏洩が疑われたら即取り消す。** 長期トークンなら再発行（旧トークンは無効化。必要なら最大24時間の猶予を設定できる）、チャネルシークレットは［チャネル基本設定］タブの［**発行**］で再発行。

**やらないこと**
- スプレッドシートやNotionに平文で置く
- スクリーンショットに写り込ませる
- 複数の用途で1つのトークンを使い回す（公式は「開発チームや利用者のグループごとに発行する」運用を想定している。トークンを分けておけば、片方が漏れてももう片方に影響しない）

## 7. 裏が取れなかった項目（正直に列挙）

### 公式ドキュメントで確認できなかったもの

1. **Messaging API有効化が既存の友だち・過去のメッセージ・クーポンに影響しないこと。**
   「影響する」という記載も「影響しない」という明言も見つけられなかった。手順の書きぶり（既存アカウントへのチャネル追加）からは影響しないと読めるが、公式に断言した文はない。
2. **既存アカウントに後付けした場合、あいさつメッセージ／応答メッセージの設定が上書きされるかどうか。**
   公式には「**チャネルを作成したとき**にデフォルトの設定が［有効］になっています」とだけあり、既存設定を持つアカウントの扱いは書かれていない。→ 有効化前にスクリーンショットで控えることを推奨。
3. **LINE公式アカウントマネージャーの［設定］＞［応答設定］に［Webhook］のオン／オフ項目があるか。**
   現行の[応答設定マニュアル（2026.03.25更新）](https://www.lycbiz.com/jp/manual/OfficialAccountManager/account-settings_response/)には Webhook の記載がない。確認できたのは LINE Developersコンソール側の［Webhookの利用］トグルのみ。
4. **「応答モード」廃止・Webhookとチャット併用可の公式ニュース本文。**
   [該当ページ](https://developers.line.biz/ja/news/2022/12/01/use-both-chats-and-webhooks/)はJavaScriptでレンダリングされるSPAのため、本文を直接取得できなかった。**検索エンジンのインデックス経由の要約でのみ内容を確認**している。ただし現行の応答設定マニュアルに「応答モード」の項目が存在しないこと、および LINE Developers の各ドキュメントが Bot/チャットの二者択一に触れていないことから、廃止済みという結論は妥当と判断した。
5. **スマホの「LINE公式アカウント」管理アプリからの手動応答が Messaging API 有効化後も使えるか。**
   応答設定マニュアルには現在も「管理アプリ（APP）」の操作手順が載っているが、Messaging API との関係については記載がない。上記4と合わせれば使えるはずだが、公式の明言は見つからなかった。
6. **長期のチャネルアクセストークンを発行するボタンの正確な画面文言。**
   公式には「［**Messaging API設定**］タブより、いつでも発行できます」とあるだけで、ボタンのラベル（「発行」なのか等）は記載されていない。同タブを開けば見つかるはず。
7. **LINE公式アカウントマネージャーで作成したクーポンを、APIから送信できるか。**
   逆方向（APIで作ったクーポンをOAMから送る）は公式に明記があるが、この方向は記載がない。`GET /v2/bot/coupon`（クーポンの一覧を取得する）がOAM作成分も返すのかどうかも不明。
8. **クーポンAPIにアカウント種別（認証済／未認証）の制限があるか。**
   リファレンスに制限の注記がないため制限なしと判断したが、明示的な記述はない。
9. **プロバイダー名に文字数・文字種の制限があるか。**
   公式マニュアルに記載なし。
10. **LINE公式アカウントマネージャーの［Messaging API］画面にチャネルIDやチャネルシークレットが表示されるか。**
    マニュアルには記載がなく、LINE Developersコンソール側で確認する前提になっている。

### ワンヒッター側で確認が必要な情報（調査では分からないもの）

11. **現在の友だち数** — 料金プランの判断に必須。LINE公式アカウントマネージャーの［分析］または［ホーム］で確認できる。
12. **現在契約中の料金プラン** — ［設定］＞［利用と請求］で確認できる。
13. **アカウント種別（認証済アカウントか、未認証アカウントか）** — 認証バッジ（緑）の有無で判別できる。**未認証だと友だち全員のユーザーID一覧取得APIが使えない**ため、顧客台帳との突き合わせ設計に影響する。なお認証済アカウントの申請・利用自体は無料。
14. **LINE公式アカウントの管理者権限を持つLINEアカウントが誰か** — 有効化操作には管理者権限が必要。
15. **CMOの実行環境のIPアドレスが固定できるか** — ［セキュリティ設定］でのIP制限が使えるかどうかを左右する。
