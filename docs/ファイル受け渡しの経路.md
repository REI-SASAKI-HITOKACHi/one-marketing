## 結論：claude.ai の「受け渡し棚」に置く

- 置き場：**https://claude.ai/artifact/EQ7uN8LPGmBGbQXYvomzia**（非公開・オーナーのアカウント）
- 原本：`deliver/okiba/index.html`（ページ）＋ `deliver/okiba/files.json`（一覧）。PDF 本体はリポジトリに入れない（Artifact の保管庫にだけ置く）
- 受け取る側の操作（ファイルごとにボタン2つ）
  - **端末に保存**：スマホ・PCにダウンロード（確認が1回出る）
  - **ドライブに保存**：嶺さんの Google ドライブ「休眠3社_送付用PDF（2026-10）」（`1zBP7etIT0D0HcYqp1HFPGNO_X9uhTx86`）に保存。Gmail の「ドライブを使用してファイルを挿入」で添付できる。段ごとに別フォルダも指定できる（files.json の `folder`）

## CMO の置き方（毎回）

1. Artifact ツールで資産を上げる：`url`＝上の棚、`asset: true`、`file_paths`＝PDF（1回25本まで・1本20MiBまで）。返ってきた id を控える
2. `deliver/okiba/files.json` の `dan`（送り先ごとの段）に `{name, asset, size}` を足し、`updated` を書き換える
3. 同じ `file_path`（`deliver/okiba/index.html`）と `files: {"files.json": ...}` で再公開（capabilities は省略＝引き継ぎ）
4. 渡した相手に「棚に置いた」と1行（嶺さんはチャット、和真さんは業務連絡LINE。LINE に鍵付きURLは貼らない＝棚のURLは鍵ではない）
5. 用が済んだ段は files.json から外す。資産の削除は相手の受け取りを確認してから（元に戻せない）

## 和真さんに渡すとき（未済の前提）

- 棚は**非公開**。和真さんが開くには、嶺さんがページの「共有」から和真さんのアカウントを招待する必要がある（Claude からは共有を変えられない）。招待は「外に出す」に当たるのでオーナーの操作
- 公開リンクにはしない（顧客の地域・取引記録が入るため）
- 和真さんが claude.ai のアカウントを持たない場合は、当面は嶺さん経由（棚から保存 → LINE で転送）

## 試して分かったこと（なぜこの経路か）

- 公式ドキュメント（code.claude.com／support.claude.com、2026-10-26 子エージェント調査）に、クラウドのセッションから PC・ドライブへファイルを直接渡す手段の記載は無い。記載があるのは git push と teleport、Google ドライブ・コネクタ（サイズ上限は未記載）、Artifact だけ
- Gmail・Drive コネクタを CMO が直接呼ぶと、PDF を base64 で引数に書くことになり、数MBは現実的でない
- 一時的な公開URLに置いて Apps Script で取り込む案は、Claude の自動判定（公開へのアップロード）で止まった。回避しない
- Artifact の資産は PDF を 20MiB まで置ける。ページから閲覧者のコネクタを `$file` 引数で呼ぶと最大16MiBまで渡せるので、ドライブへの保存は**嶺さん本人の権限**で行われる（CMO は鍵を持たない）
- Gmail の下書きへの直接添付は、1回の呼び出しで `$file` を1つしか渡せず、下書き更新は添付を毎回まるごと置き換えるため、2本以上は付けられない → ドライブ経由で添付する
