# 架電台本の原則

最終更新：2026-09-07（オーナー指示）

**既存顧客へ電話をかける台本は、案件が何であれ必ずこの型を守ること。**
SMS・LINE・メールの文面を作るときも、可能な範囲で同じ考え方を通す。

## 必須の型

```
1. 名乗り
   「お世話になっております、ワンヒッターの〇〇です。」

2. 想起
   「〇月に〇〇のクリーニングでお伺いした者です。その節はありがとうございました。」
   ★ いつ・何をやったかを必ず具体的に言う。「以前は」で済ませない。

3. アフターフォロー  ← ★これを絶対に飛ばさない★
   「その後、〇〇の調子はいかがでしょうか。何か不具合などございませんか？」
   ★ ここでお客様の返答を最後まで聞く。すぐ本題に入らない。

4. 本題（案内・提案）
   「実は本日は〇〇のご案内でお電話しました。」

5. 締め（日程を取りにいく）
   「〇月・〇月でご都合のよい日はありますでしょうか？」
```

## なぜ 3 を必須にするか

- **想起**：お客様が前回のことを思い出す時間になる。いきなり売り込みにならない。
- **アフターフォロー**：不具合をその場で拾える。放っておくと二度と呼ばれない。
- **受け取られ方**：「売りに来た電話」ではなく「様子を見てくれた電話」になる。

3 を入れるかどうかで、同じ提案でも成約率と、その後のリピートが変わる。
省略してよい理由は無い。

## 不具合を言われたときの扱い

**売上より優先する。** 提案は中断して、そちらを先に聞く。

```
「すぐ確認にうかがいます」→ 日程を取る
記録は「要対応（内容）」
```

その場で提案を続けない。次の接点で改めて出す。

## 各案件の台本を作るときのチェック

- [ ] 2 に「いつ」と「何を」が具体的に入っているか
- [ ] 3 が入っているか。3 の直後に本題を続けていないか（返答を聞く指示があるか）
- [ ] 4 の訴求が値引きではなく、事実にもとづく理由になっているか
      （例：12月からの繁忙期加算 +3,300円／箇所 を「回避できる」という言い方）
- [ ] 断られたときの引き際が書いてあるか（粘らせない）
- [ ] 記録の書き方が4〜5語で済むようになっているか

## 実装

- `tools/todo-calendar.gs` から配信する指示文でも、架電を含む日はこの型を必ず入れる。
- 過去の適用例：`docs/架電リスト-2026秋.md`（2026-09-07 渡辺さん）
