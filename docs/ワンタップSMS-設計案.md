# ワンタップSMS（次回から）— 設計案

依頼 `20261015-01-crm`（オーナー 10/13「次回以降はワンタップで済むように対応してね」）。
**実装はしていない。** CMO が見てから。オーナーの許可が要る点は最後にまとめた。

## 条件

- **電話番号と本文が入ったリンクを、スプシにも公開ホストにも書き出さない**（11月SMSでは `s.html#to=…&b=…` の書き込みが安全確認で止まり、F列の本文をコピーする運用になった）
- 安全確認をすり抜ける工夫ではなく、**電話番号と本文をどこにも置かずに済む**形にする
- **名乗り照合（meigi_hyou）が送信の直前にかかる**こと

## 案：2026スプシに紐づく Apps Script の「送るボタン」（推し）

```
送信タブ（スプシ）          Apps Script（スプシに紐づく・社内だけ）           和真さんのスマホ
顧客ID / 照合OK日時 / 送信済み   ← 置くのはこれだけ（電話・本文なし）
  ▶ 送る = WebアプリURL?id=C0123&c=nov  ──タップ──▶  ① 台帳から電話番号を読む
                                                   ② 送ってよいかを確かめる（下）
                                                   ③ 本文をその場で組み立てる
                                                   ④ sms:（宛先・本文入り）へ移る ───▶ SMSアプリが開く
```

- **シートに置くもの**：顧客ID・キャンペーン名・照合OK日時・送信済み。**電話番号の列も本文の列も持たない。**
  リンクに入るのも顧客IDとキャンペーン名だけ。
- **電話番号と本文が存在するのは、タップした瞬間の和真さんの画面の中だけ**。どこにも保存しない。
- 本文のひな形はスクリプト（または個人情報を含まない雛形セル）に置き、差し込む値（姓・前回の時期・メニュー）はタップ時に台帳から読む。
  CMO の個別文面の道具（`nov-sms-kobetsu.py`）の作り方を、そのまま Apps Script に移す。
- sms: の開き方（iPhone と Android の違い）は今の `s.html` と同じ処理を使う。

### 名乗り照合を「送る直前」にかける — 2段構え

| いつ | 誰が | 何を |
|---|---|---|
| 送る日の朝 | crm（Python） | `meigi_hyou()`（2022〜2026年の台帳・同日ルールつき）で全員を照合し、送信タブに「照合OK＋日時」だけを書く。外れた人は行ごと出さない |
| タップした瞬間 | Apps Script | ①照合OKが**24時間以内**か ②照合のあとに**2026年の月次タブにその人の本舗の行が増えていない**か ③台帳の**クレーム履歴（AG）が空**か ④**個別除外の印**が無いか ⑤**送信済みでない**か。どれか外れたら SMS を開かず理由を出す |

5年分の台帳を毎回 Apps Script で読むのは重いので、全体の照合は朝の Python、直前の確認は「朝から変わったか」だけにする。

### check-public-page との関係

- Webアプリの公開範囲は **「組織内のみ」か「指定したユーザーだけ」**。**「全員（匿名）」にはしない**（電話番号を返すページになるため）。
- 配信の前に、ログインしていない状態で URL を開いて**ログイン画面になる（中身が出ない）**ことを確かめる手順を入れる。
  `check-public-page.py` は「公開してよいページの点検」なので、この URL は**公開ページの一覧に載せない**（対象外であることを明記）。

## 他の案（推さない）

| 案 | 推さない理由 |
|---|---|
| シートの式で `sms:` リンクを作る | シートアプリでは sms: をタップしても開かない（s.html を作った理由）。結局リンクに電話と本文が入る |

## オーナーの許可が要る点（ここで止めて CMO に返す）

1. **スプシに Apps Script を追加し、Webアプリとしてデプロイする**（スプシの持ち主のアカウントで権限の承認が要る）
2. 公開範囲（組織内のみ／和真さんのアカウントだけ）と、**実行するユーザー**の選択。推しは「アクセスしたユーザーとして実行」（和真さんの権限で台帳を読む。和真さんが見られない情報は返らない）
3. 台帳に「連絡の個別判断」列を足すこと（これは CMO 判断で可）
