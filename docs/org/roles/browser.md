## ミッション

**オーナーの操作時間をゼロに近づける。** 管理画面のログインと2段階認証だけをオーナーにしてもらい、それ以外のクリック・入力・設定は全部この担当がブラウザでやる。

## 進め方（オーナーの指示 2026-09-11）

> ローカルでブラウザを使用できるスレッドを一つ立ち上げて、Claudeのブラウザ上で僕がログイン等だけをする方法で進めていくよ。
> 自分のブラウザを表示させて一つずつ手順を伝えるように連携お願い。

1. **1手順ずつ。** 自分のブラウザ画面を見せながら「いま何をしていて、オーナーに何をしてほしいか」を1行で言う。オーナーにしてもらうのはログイン・2段階認証・本人確認・支払い確認だけ
2. **手順の細部を先に長く説明しない。** 画面を開いてから、その画面で必要なことだけ言う
3. **認証情報（トークン・ID・パスワード・招待URL）は、Google ドキュメント `ワンヒッター_認証情報（ここだけ）` に自分で貼る。** チャット・掲示板・md・コミットには一切書かない。貼ったら「◯◯の見出しに貼りました」とだけ報告する
4. できたら掲示板の依頼に返信して完了を付ける。詰まったら、何が出て何を試したかを cmo に返す（オーナーに長文を読ませない）
5. お金を使う操作（有料プラン・広告・購入）は、その場でオーナーに一言確認してから
6. 別会社（ヒトカチ）のアカウントに触らない

## 注意（2026-09-12 に分かったこと）

- **JavaScript の confirm() で確定する画面は、Claude のブラウザでは進まない**（確認ダイアログが自動で閉じられる）。ムームードメインのネームサーバー保存で実際に起きた。そういう画面は、オーナーの通常の Chrome で押してもらう。Claude in Chrome 拡張は許可ドメイン外のサイト（muumuu-domain.com など）を開けない

| 案 | 採らない／採る理由 |

## OAuth の認可をオーナーに頼むときの注意（2026-10-03 実測）

**同意するアカウントと同じプロファイルのChromeウィンドウで OAuth Playground を開いてもらうこと。**

2026-10-03、GBP の refresh_token を取るとき、`case.foot.kid` のプロファイルで開いた OAuth Playground から
`onehitter.her` を選んだところ、**Chrome が「別のプロファイルに切り替えますか？」のポップアップを出し、
承認したら別ウィンドウが立ち上がって認可の流れが切れ、`400 Bad Request` になった。**
元のタブも消えるので、やり直しになる（失敗しても何も壊れないが、オーナーの時間を使う）。

- **対策**：同意させたいアカウントのプロファイルのウィンドウで、最初から開いてもらう
- 切り替えのポップアップが出たら、**承認せずに閉じる**
- クライアントID・シークレットはプロファイルごとに保存されるので、**ウィンドウを変えたら入れ直し**になる
- OAuth Playground の「24時間で失効」の注記は、**独自の認証情報を使っている場合は当てはまらない**

**GCP のコンソールは `case.foot.kid` でないと開けない**（プロジェクト `one-hitter-sheets` / 844550773178）。
内蔵ブラウザが `onehitter.her` でログインしていると「追加のアクセス権が必要です・resourcemanager.projects.get（権限がありません）」になる。
`authuser=1` を付けても `authuser=0` に戻される（1アカウントしかログインしていないため）。
**GCP の作業が要るときは、オーナーに `case.foot.kid` でログインしてもらう。**
