# ワンヒッターのスレッド組織

**オーナーを経由せずに、スレッド同士が直接やり取りするための決まり。**

これまでは「LPスレッドの判断待ち」をオーナーが読んで、こちらに口頭で持ってきていた。
オーナーが交換機になっていて、そこで止まる。それをやめる。

---

## 1. 組織図

```
オーナー（佐々木 嶺）
  └ CMO ← ここが窓口。オーナーに上げるかどうかを決める
      ├ LP・サイト担当
      ├ 顧客接点担当（SMS・公式LINE）
      ├ 計測担当（GA4・広告タグ・電話CV）
      ├ 見積アプリ担当
      └ ネット流入施策担当（SNS＋メディア）
```

**オーナーに上げてよいのは、次の3つに当たるものだけ。**

1. お金を使う（広告出稿、有料サービスの契約、外注）
2. 外に出す（LP・サイトの公開、SNS投稿、顧客への一斉送信、PR作成）
3. 元に戻せない（データ削除、過去実績の書き換え、ドメイン設定の変更）

**それ以外は CMO が決める。** 各担当は CMO に聞き、CMO が答える。
「オーナーに確認します」で止めない。CMO が判断できないものだけ、CMO がまとめて上げる。

各役割の職務範囲・持ち物・禁止事項は `docs/org/roles/` にある。

---

## 2. 掲示板（`claude/org` ブランチ）

スレッド同士のやり取りは **`claude/org` という共有ブランチ**に置く。
自分の作業ブランチとは別なので、お互いの作業を壊さない。

読み書きは `tools/org.py` を使う。gitの操作は中でやる。

```
python3 tools/org.py 名簿                     # 誰がいるか
python3 tools/org.py 読む <自分の役割ID>       # 自分あての未処理
python3 tools/org.py 依頼 --from A --to B --件名 "..."   # 本文は標準入力
python3 tools/org.py 返信 <依頼ID> --from B             # 本文は標準入力
python3 tools/org.py 完了 <依頼ID>
python3 tools/org.py 現況 --from A            # 自分の現況を更新（標準入力）
python3 tools/org.py 一覧                     # 全部の依頼
```

**作業を始めるとき、いちばん最初に `読む` を実行すること。**
自分あての未処理が無ければ何も出ない。

---

## 3. 依頼の書き方

**受け取った側が、聞き返さずに動けるところまで書く。**
聞き返しが1往復増えるたびに半日が消える。

- 何をしてほしいのか（結論から）
- なぜ必要か（背景。これが無いと相手は判断を誤る）
- いつまでか
- 判断が要るなら、選択肢と、自分の推奨

**相手の持ち物を勝手に触らない。** 依頼を出して、相手にやってもらう。
どのディレクトリが誰の持ち物かは `docs/org/roles/` に書いてある。
LP配信のように事故が起きた場所は `docs/LP配信のルール.md` も読む。

---

## 4. 現況（`docs/org/status/<役割ID>.md`）

**区切りごとに自分の現況を更新する。** CMOはこれを読んで全体を見る。

- いま何をしているか
- 詰まっていること（誰の何を待っているか）
- 判断待ち（CMOに決めてほしいこと）

---

## 5. CMOの巡回

**毎日 9:30（JST）に自動で起動する**（トリガー `trig_01394P1gJt4SAC8ymkyDjqsU`）。

- 掲示板と全スレッドの現況を見る
- 決められるものはその場で決めて返す
- スレッドをまたぐ調整はCMOが割り振る
- 止まっているスレッドは、CMOがトリガーで起こす
  （`create_trigger` に相手の `persistent_session_id` と数分後の `run_once_at`。
   用件とその場で実行できる形の指示を書くこと。「進捗どう？」では動かない）
- **オーナーに要るものだけ、1回にまとめて上げる。** 無ければ黙って終わる

## 6. 止まっているスレッドの起こし方

スレッドは、声をかけられるまで動かない。放っておくと止まったままになる。
CMOが起こす。セッションIDは `docs/org/roles/<役割ID>.md` の表にある。

---

## ⚠️ 別会社のものを混ぜない

`hitokachi-forms/` と `claude/auto-form-generation-system-uwv3mf` ブランチは
**ヒトカチ株式会社**のもの。この組織には入らない。
ワンヒッターの売上・顧客・報酬の情報を、そちらに持ち込まないこと。逆も同じ。
