## C. 「承認が多すぎる」の原因（2026-10-10 各セッションを実測）

| スレッド | 権限の設定 | 起きていること |
|---|---|---|
| **ブラウザ担当**（嶺さんのPC） | 既定（毎回確認） | Bash を使うたびに嶺さんの許可待ちで止まる。**承認の大半はここ** |
| **ネット流入担当** | acceptEdits（編集だけ自動） | コマンド・予約投稿などで確認が出る |
| 計測・顧客接点・LP・見積アプリ・経営企画・ギフト・CMO | auto（自動） | 確認なしで動く。ただし**本番への配信**は安全チェックが「名指しの承認」を毎回求める |

ルール（docs/org/README.md 4.6.1「承認待ちで作業を止めない」）は全スレッド共通で入っている。止まっている原因は**セッションの権限の設定**のほう。

**直し方（嶺さんの設定。CMO は設定ファイルを触れない決まり）**
1. ブラウザ担当：嶺さんのPCの Claude Code で、そのセッションを **auto モード**にする（`/permissions` か、起動時に `--permission-mode auto`）。
2. ネット流入担当：claude.ai/code のセッション設定で、権限モードを **auto** に変える。
3. 配信の承認を減らす場合：「MTGで決定済みの配信」「CMO査読済みのSNS投稿」は承認不要、と CLAUDE.md の「確認が必要なのは3つだけ」に例外を書き足す（嶺さんの決定が要る。決まれば CMO が文面を直す）。そのうえで、本番の配信のコマンド（tools/deploy-netlify.py・tools/deploy-booking.py）を auto モードの許可ルールに足すと、安全チェックでも止まらなくなる。
