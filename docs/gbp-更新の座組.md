## 座組（これで回す）

### ① 最新情報は、写真なしでブラウザ担当が投稿する（毎週）

- 原稿：web-inflow が書く → CMO が査読 → **ブラウザ担当が投稿**
- **予約投稿を使って、数週間分をまとめて入れる**（1回の作業で1か月ぶん）
- オーナーの出番：**なし**

### ② 写真は「貯金」方式（月1回・オーナー5分）

- 投稿に添付するのではなく、**プロフィールの「写真」タブに10〜15枚まとめてドラッグ**
- 順番は `docs/gbp-写真の掲載順.md`（24枚の並びが決まっている）。上から順に
- 変換済みJPEGはブラウザ担当が用意して渡す（Drive の HEIC → JPEG）

**なぜこれで足りるか**：GBPの「写真」は投稿とは別枠で表示される。
**写真が毎月増え、最新情報が毎週出る**なら、利用者から見た更新の鮮度は保てる。

### ③ 恒久策：API の利用申請を出す（承認まで数週間）

承認されれば、**写真付きの投稿まで Apps Script で自動化**できる（Driveのフォルダ＋シートの原稿を読んで投稿）。
申請は外部への提出なので、**オーナーのGOが要る**。下書きはブラウザ担当が作る。

### ④ 任意：Claude in Chrome に `business.google.com` を許可

許可を1回足せば、オーナーのChrome経由でブラウザ担当が**写真を添付できる可能性**がある（ファイルアップロードの口が使えるため）。
**確実とは言えない**ので、許可が出たらまず検証する。通れば②も不要になる。

## やらないこと

- **オーナーに毎回ドラッグしてもらう**（今回の指示で否定された運用）
- **有料の予約投稿ツール**（お金が増える。①の予約投稿で足りる）
- **写真を投稿に添付するための迂回**（自動判定が拒否した経路を回り込まない）
