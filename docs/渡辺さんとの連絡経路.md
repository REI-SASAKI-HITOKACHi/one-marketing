# 渡辺さんとCMOの連絡経路

最終更新：2026-09-07

## 何が問題だったか

TODOシートに書いても見に行く習慣がない、という前提で
「Googleカレンダーの予定として通知する」方式を決めた（TODOタブ 検討事項11番）。

ところが実装が **終日予定** だった。
終日予定は Google カレンダーの既定では通知が鳴らない。
（既定の通知設定が「当日 午前0時に通知」などになっていて、寝ている間に消える）

結果、通知の仕組みとして機能していなかった。

## どう直したか

**時刻を指定した15分の予定**に変える。時刻つきの予定なら既定のポップアップ通知が確実に鳴る。

| | 旧 | 新 |
|---|---|---|
| 予定の形 | 終日 | 15分枠 |
| 置く時刻 | — | その日の **07:00以降で最初に空いている枠** |
| 通知 | 実質なし | 開始時 と 10分前 のポップアップ |
| 中身 | タイトルのみ | 説明欄にその日のTODO全文（なぜ・やり方つき） |
| 件数 | TODO 1件につき1予定 | **1人1日1予定**にまとめる（通知が5回鳴らない） |
| 自分の枠 | 塞ぐ | 塞がない（予定あり扱いにしない） |

実装：`tools/todo-calendar.gs`
入れ方：スプレッドシート → 拡張機能 → Apps Script → 貼り付け → `tesuto()` で確認 → `toroku_trigger()` で毎朝6:30の自動起動をON

## ★ 権限の制約（把握しておくこと）

渡辺さんのカレンダー `wk09015963@gmail.com` は、佐々木さんに対して **閲覧のみ** の共有になっている。

- 予定を **読む** ことはできる（CMO側で空き枠を計算できる）
- 予定を **書く** ことはできない

そのため現状は「佐々木さんのカレンダーに予定を作り、渡辺さんをゲストに招待する」形にしている。
渡辺さんのカレンダーにも表示され、渡辺さん側の既定通知で鳴るので、実用上は問題ない。

**当面はこの招待方式で運用する（2026-09-07 オーナー判断）。**
渡辺さんに権限変更をお願いする手間に見合わないため、権限は現状のままとする。

将来そうしたくなった場合：渡辺さんのカレンダー → 設定と共有 → 特定のユーザーとの共有
→ 佐々木さんの権限を「予定の変更権限」に。付いたら `SETTEI.chokusetsu = true` に変えるだけ。

## 「バイト」の扱い

渡辺さんのカレンダーには `バイト` が **23:00〜翌16:00** のような長時間ブロックで入っている。
これをそのまま予定として数えると、一日中どこにも空き枠が無くなる。

実際にはこのブロック中にも施工に入っている（例：2026/09/02 09:00 小池様トイレ）ので、
これは「予定」ではなく生活時間の目印とみなし、空き枠の計算から除外している
（`SETTEI.mushi` の正規表現）。

> 補足：バイトの開始が23:00の日が多いので、07:00の通知は夜勤明けに近い時間帯に当たる可能性がある。
> 07:00で運用してみて反応が悪ければ `SETTEI.kaishiJikoku` を 8 か 9 に上げる。

## 逆方向（渡辺さん → CMO）

渡辺さんからの返しは **TODOタブのB列「状態」のプルダウン** だけ。文章は不要。
CMO側が1日1回シートを見て、進んだものは次の手を打つ。

## オーナーのTODOの消込

佐々木さん担当のTODOは、CMOとの会話の中で片付いているものが多い。
シート上で「未着手」のまま残っていると、渡辺さんから見て
「会社側が何も動いていない」ように見えて不安になる。

→ **CMOが1日1回シートを見て、完了しているものを「完了」に落とす。**
　 完了メモには「いつ・何をもって完了か」を1行で書く。

現状これには **サービスアカウント鍵が必要**（CMO側からシートに書き込むため）。
鍵は再作成待ちのため、再開後すぐに日次運用へ入れる。

## 2026-09-07 追記：経路をLINEへ移す

**今日わかったこと。** カレンダーの招待は渡辺さんのカレンダーに現れなかった
（招待への返答が `needsAction` のまま、彼のカレンダー一覧にも出てこない）。
Googleカレンダーの「招待状を自動的に追加」が「返信した場合のみ」になっていると、
返信するまで予定が現れず、通知も鳴らない。

実際の指示はオーナーがLINEで個別に送って伝わった。**LINEは届く。カレンダーは届かなかった。**

→ **届ける経路はLINEに一本化する。** 手順は `docs/グループLINE-手順書.md`。

| | 役割 |
|---|---|
| グループLINE | **届ける**。その日のやること、リスト、確認事項 |
| スプレッドシート | **溜める**。架電シート、TODO、記録 |
| カレンダー | **予定**。施工の予定のみ。TODOの通知には使わない |

`tools/todo-calendar.gs` は当面保留にする。設置は急がない。
（カレンダー側の設定が直れば使えるが、LINEが動けば要らなくなる可能性が高い）

**残る課題：記録がされない。** 2026-09-07 は指示が届いたうえで、
架電シートの結果欄が17:30時点で0件だった。
届ける経路を直しても、記録の習慣は別の問題として残る。
LINEから返信できるようにして、CMO側がシートへ転記する形にするのが現実的。
