## 1. なぜ「送信完了ページ」で数えるのか

**送信ボタンを押した時点（`form_submit`）では数えません。**

押しただけでは、入力エラーで弾かれたり、二度押しされたりします。
**それを成果として数えると、実際より多く見える → 入札が上がる → 予算が溶けます。**

サンクスページは「Netlify Forms が受理した後にしか出ない画面」なので、
**ここが唯一信用できる地点**です。

```
LPを見る → フォームに入力 → 送信を押す → （受理）→ サンクスページ
                              form_submit        generate_lead ← これを数える
```

## 2. なぜ電話タップも数えるのか

**この業種は電話が多いからです。** 数えないと、広告の効果を実際より低く見積もります。

**ただし、タップ＝申込ではありません。** かけずに切った人も1件になります。
なので **主CV（申込）と副CV（電話タップ）は、Google広告側で別のコンバージョンとして
登録し、入札の目標には主CVだけを使う**のが安全です。

> **ユニークコール（電話番号の出し分け）は今回使いません。**
> 費用がかかるうえ、Google広告の「電話番号の動的挿入」と競合します（CMO決定 2026-09-14）。
> **実際に何分通話したかは測れません。** タップの数だけです。

## 2-b. なぜLINEタップも数えるのか

**両LPが、ファーストビューでLINEへ誘導しています。**

| LP | 文言 | クリックできるLINE導線（2026-09-16 実測） |
|---|---|---:|
| `mizumawari` | 「LINEからご予約・ご相談いただいた方には、**防カビコーティングを無料**」 | **2本**（ヒーロー／追従バー） |
| `aircon` | 「LINEご登録の方には、**防カビコート（通常3,630円）を無料**」 | **2本**（同上） |

`aircon` のファーストビューは **［WEB予約］と［LINEで無料クーポンを受け取る］の2つ**が並んでいます。

**無料特典でLINEへ送っておいて、そこから来た申込を広告の成果として数えないと、
「CVが少ない」と見えます。** 10/1 のCPA判定で、**効いている広告を止めかねません。**

> ### ⛔ ただし、LINEタップも**サブアクション**です。入札に使いません
>
> **LINE登録は受注ではありません。** 申込・電話と同じ重みで数えると **CPAが実態より良く見えます。**
> 自動入札に切り替えたときに「LINE登録を集める」ほうへ最適化されると荒れます。
> **知りたいのは「LINE経由が何件あったか」だけ**で、判定のときに人が足して考えます。

## 3. 🚨 二重計上をどう防ぐか（いちばん大事）

Google広告にコンバージョンを渡す道は2つあり、**両方を有効にすると同じ申込が2回数えられます。**

| 道 | 中身 |
|---|---|
| **A：直接タグ**（採用） | LPから `gtag('event','conversion',{send_to:'AW-…/ラベル'})` を直接撃つ |
| B：GA4からインポート | GA4のキーイベントをGoogle広告に取り込む |

**Aを採ります。** 理由は2つ。

1. **すぐ届く。** Bは GA4 の処理を挟むので、数字が出るまで時間がかかります。
   自動入札は学習が早いほど効くので、立ち上げ期はAが有利です
2. **すでに実装済みです。** `tracking/measurement.json` にIDとラベルを入れるだけで動きます

> ## ⛔ Google広告の管理画面で、GA4のキーイベントをインポートしないでください
>
> **これが二重計上の唯一の原因になります。**
> 二重に数えると、Google広告は「CPAが実際の半分」だと誤解します。
> **入札を上げすぎて、予算が倍の速さで溶けます。**
>
> 画面での確認：**[目標] → [コンバージョン] → [概要]** を開き、
> **「ウェブサイト」以外（とくに「Google アナリティクス 4」）の行が無い**ことを確かめる。
>
> **2026-09-15 確認：GA4からのインポートは無い**（コンバージョンアクションは3件、発生元はすべて「ウェブサイト」）。

### ⚠️ もう1つの二重計上の芽：ウィザードが作った「リードフォームの送信」

アカウント開設のウィザードが作った**「リードフォームの送信」**が、**メインアクション**のまま
アカウント単位の目標に入っています（トラッキングステータスは「無効」＝いまはタグが撃たれていない）。

**いまは0件ですが、これは「撃たれていないから0」であって「数えない設定だから0」ではありません。**
何かの拍子（Googleの自動検出やタグの張り替え）に申込を拾い始めると、
**`generate_lead` と同じ申込を2回数えます。** しかもメインなので入札の目標に直接効きます。

**対処：サブアクションに落とし、アカウント単位の目標から外す。** 元に戻せる操作です。
**削除は急ぎません**（外部サービス側の削除はオーナー判断）。

## 5. `gclid` を保存している理由（あとから効く）

**当社は、申し込んだその日には受注が決まりません。** 電話で日程を詰め、現地で見積りを確定し、
施工して入金——**2〜4週間かかります。**

サンクスページのCVだけを見ていると、

- 申し込んだが結局やらなかった人
- 電話で追加メニューが決まって10万円になった人

が**どちらも同じ「1件」**になります。**この状態で自動入札に任せると、
「申し込むだけの人」を集めるほうへ最適化していきます。**

そこで、**広告のクリックID（`gclid`）を申込と一緒に残しています。**
あとから「この申込は実際に◯◯円で成約した」をGoogle広告へ戻せます
（オフラインコンバージョンのインポート）。

**残していなければ、後から復元できません。** だから出稿の前に入れてあります。

| | |
|---|---|
| 拾うもの | `?gclid=` ／ `?wbraid=` ／ `?gbraid=`（後者2つはiOSなどで代わりに付く） |
| 置き場所 | ブラウザの `localStorage`（`oh_gclid`）。**90日で捨てる** |
| 申込への紐づけ | フォームの隠し欄 `gclid`。**Netlify Forms の受信内容に残る** |

**広告から来たあと、別のページを見てから申し込んでも残ります。** ここが肝です。

## 6-b. 広告のURLに付けるパラメータ（2026-09-19 決定）

最終ページURLは、この形にします。

```
https://lp.onehitter.jp/aircon/?src=gads_aircon&cid={campaignid}&ag={adgroupid}
https://lp.onehitter.jp/mizumawari/?src=gads_mizumawari&cid={campaignid}&ag={adgroupid}
```

| | 何のため | いま情報を運ぶか |
|---|---|:--:|
| `src` | **申込1件ごとの出どころ**をフォームの記録に残す | ○ |
| `cid`（`{campaignid}`） | キャンペーンの別 | **✗ いまは1本だけなので定数**。11月にギフトが別キャンペーンになると効く |
| **`ag`（`{adgroupid}`）** | **広告グループの別** | **○** |

### なぜ `ag` を足すのか

**水まわりの3グループ（`B_レンジフード` `B_浴室` `C_ハウスクリーニング`）は、
着地先も `src` も同じです。** `ag` が無いと、**GA4でもフォームでも見分けがつきません。**

**Google広告の管理画面では広告グループ別に見えますが、あちらが知っているのは
「申込が何件か」までです。** 当社は申込1件の金額が 33,660円から10万円超まで開きます。
**件数だけで広告グループを比べると、安い申込ばかり集めるグループを「優秀」と誤読します。**

### なぜ「いま」なのか

**広告を作ったあとにURLを直すには、人の手とオーナーの携帯の本人確認が要ります。**
**いまなら貼るのが1回で済みます。** 情報は貯め始めないと後から復元できません。

### ⭐ 受け側の実装は要りません

**GA4は着地URLをクエリ付きで持っています**（`landingPagePlusQueryString`）。
**`ag` をURLに足すだけで、広告グループ別のセッションが取れます。**

- LPの hidden 欄を増やさなくてよい
- Netlify Forms も、`tools/booking-inbox.py` も、`予約_Web` の列もそのまま

`tools/ga4-weekly.py` が**週次で広告グループ別に出す**ようにしました（検算は `tools/test-ga4-weekly.py`）。

```
## 広告グループ（`?ag=`）別のセッション

| 広告グループID | 着地ページ | セッション |
|---|---|---:|
| `777` | `/mizumawari/` | 7 |
```

> **申込1件ごとに広告グループまで追いたくなったら、そのとき hidden 欄を増やします。**
> **13日で期待CV 2.3件の段階では、そこまでの仕掛けは要りません。**
> **受注額まで戻したいなら `gclid` のほうが正確です**（Google広告側が広告グループを知っているため）。

## 8. ⚠️ 出稿前に直したほうがよいもの

### 予約フォームに `traffic_src` が入っていない

| ページ | `traffic_src` |
|---|:--:|
| LP（`lp.onehitter.jp/mizumawari/` ほか） | **あり** |
| **予約フォーム（`yoyaku.onehitter.jp`）** | **なし** |

**広告の着地をLPにするなら支障ありません。** 予約フォームに直接広告を当てるなら、
先に入れる必要があります（予約フォームは別スレッドの持ち物なので、依頼を出します）。

### アンケートのホストが2つあり、片方にGA4が無い

| URL | GA4 |
|---|:--:|
| `lp.onehitter.jp/survey/` | **あり** |
| **`survey.onehitter.jp`（＝`one-hitter-survey.netlify.app`）** | **なし** |

中身も違います（64,643バイト と 46,902バイト）。
**現場QRがどちらを指しているかで、アンケートの計測が丸ごと消えます。**
広告とは直接関係しませんが、**予約フォームで起きたのと同じ「サイトが2つある」形**です。
