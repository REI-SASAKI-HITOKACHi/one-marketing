## 1. Google クチコミのお願い

### 前提の訂正：`tools/kanryo-okuru.py` の文面は、お客様ではなく社内に届く

`kanryo-okuru.py` の送り先は**業務連絡グループLINE**（スタッフ）。そこに1行足しても、お客様には届かない。
お客様の目に入るのは次の2か所。

| 場所 | 今 |
|---|---|
| 作業完了フォームの**画面1**（スタッフのスマホをお客様に見せる） | アンケートのQRだけ |
| アンケートの**完了画面** | **Googleクチコミのお願いが、すでに全員に出ている**（回答をそのまま下書きにしてコピー→投稿。点数で出し分けない＝Googleのポリシーどおり） |

**だから足すのは画面1 の1行。** QRを2つ並べると迷うので、QRはアンケートの1つのまま、
「最後にクチコミのご案内がある」と先に伝えて、完了画面まで進んでもらう。

## 2. 公式LINE → 予約ページの導線

### 今の状態（Messaging API で読んだ事実）

- `GET /v2/bot/richmenu/list` → **空**（API で作ったリッチメニューは無い）
- `GET /v2/bot/user/all/richmenu` → **「the richmenu is owned by another channel」**
  → **リッチメニューは LINE Official Account Manager の画面で作ったものが設定されている。**
  中身（タイル・リンク先）は API からは読めないし、API から触ると画面で作ったものと食い違う。**画面で直すこと。**
- `https://yoyaku.onehitter.jp/?src=line` は 9/27 に 200 を返した。

### リッチメニュー（browser の手番・OA Manager の画面）

1. **今のリッチメニューをスクリーンショットで控える**（戻せるように）
2. **いちばん左上のタイルを「空き枠を見て予約」にする**（いちばん押される位置）
   - アクション：リンク　`https://yoyaku.onehitter.jp/?src=line`
   - `src=line` を必ず付ける（`予約_Web` の `src` 列に入り、LINE経路の受注として数えられる）
3. 他のタイルは今のまま。タイルが足りなければ、いちばん押されていないものと入れ替える（統計は OA Manager の「リッチメニュー」画面）
4. 表示期間は無期限、メニューバーの文言は「ご予約はこちら」

### あいさつメッセージ（友だち追加時）

```
友だち追加ありがとうございます。ワンヒッター株式会社です。
エアコン・水まわりのクリーニングを、東京・千葉・神奈川でお受けしています。

▼空いている日時を見て、そのままご予約いただけます
https://yoyaku.onehitter.jp/?src=line

お電話でのご相談は 080-8043-8259（受付 8:00–20:00）へどうぞ。
```

- 受付時間はアンケートの完了画面の表記（「渡辺 8:00–20:00」）に合わせた。
- **「トークでご相談ください」は入れていない。** LINE webhook に署名の検証が無く、お客様の個人情報をこの経路に流さない決まりのため。
- 名乗り：あいさつメッセージは**自分でワンヒッターの公式LINEを追加した人**にだけ届く。1人ずつの照合はできない（誰かを知る手段が無い）が、
  名乗りは追加した相手そのもの。リッチメニューは「押した人だけが開く」もので、こちらから届けるメッセージではない。
