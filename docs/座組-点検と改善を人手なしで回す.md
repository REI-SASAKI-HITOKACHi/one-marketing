## 2. Google広告 → **広告スクリプトで塞ぐ**（オーナーの手は1回だけ）

### なぜAPIではないのか

Google広告APIには**デベロッパートークンの審査**が要る（MCC作成＋申請＋レビュー）。
**広告スクリプトは審査も外部トークンも要らない。**画面に貼って承認するだけで、
毎時／毎日の実行と、スプレッドシートへの書き出しができる
（Googleの公式ひな形「Account Anomaly Detector」が毎時実行を前提にしている）。

### かたち

```
Google広告
   │  ① 毎日1回、広告スクリプトが走る
   ▼
スプレッドシート（1TK70pw…）
   ├ 広告_日次          … 広告グループ別の費用・クリック・CV
   ├ 広告_検索語句      ← ★ここが人依存の核心だった
   ├ 広告_除外語_指示   ← ② CMO がここに書く
   └ 広告_スクリプト記録 … 失敗しても静かに終わらないための実行ログ
   │
   ▼  ③ CMO が毎日読む（サービスアカウントで既に読める）
判定・除外語の追記
   │
   └─→ ①へ戻る（翌日のスクリプトが除外語を適用する）
```

**読むだけでなく、書き戻せる。**そこが「点検と改善を繰り返す」の肝。

### スクリプトがやらないこと（意図的に）

| | なぜ |
|---|---|
| 予算の変更 | **お金を使う＝オーナーの判断**（3条件） |
| 広告・キャンペーンの停止／再開 | 同上 |
| 除外語の**削除** | 消すと、なぜ消えたのか誰にも分からなくなる |
| キーワードの**追加** | 広い語が入ると日 ¥1,667 が溶ける。人が決める |

除外語を**足す**のは「お金を使わない・外に出さない・元に戻せる」ので **CMO の判断でよい**。
1回の実行で **20語まで**（暴走の保険）。処理済みの行には結果を書くので、二度と足さない。

実体：`tools/ads/ads-script.js`

## 3. 異常の定義（気分ではなく、機械で判る形に）

**毎日この5つを当てる。1つでも当たったらオーナーへ1行、当たらなければ黙る。**

| # | 条件 | 何を疑うか | 誰が動くか |
|---|---|---|---|
| 1 | 1日の費用が **日予算の1.5倍**を超えた | 設定ミス。すぐ見る | CMO → オーナー |
| 2 | **クリック0が2日続く** | 配信が止まっている／審査落ち | CMO → ブラウザ担当 |
| 3 | 検索語句の**費用上位10語**に、除外18語に無い「買う気がゼロの語」が出た | 除外の取りこぼし | **CMO が指示タブに書く（自動で適用）** |
| 4 | **クリック30以上でCV0が7日** | LP → 計測 → 広告文 の順で切り分け | CMO |
| 5 | **CPA > 平均受注単価**（台帳から算出） | 赤字。停止か増額かの判断 | CMO → **オーナー** |

**②〜④はオーナーに上げない。**①と⑤だけ上げる（お金に直結するため）。

## 4. GBP → **API無しでも、オーナーの手を月5分まで減らせる**（2026-09-20 実測で前提が2つ変わった）

当初は「API審査の結果待ち。ここだけは塞ぎきれていない」と書いていたが、**それは誤りだった。**
ブラウザ担当が画面で確かめて、2つひっくり返った。

| 前提だと思っていたこと | 実測 |
|---|---|
| 最新情報には写真が要る | **写真なしで投稿できる**（本文13文字で［投稿］が有効になった） |
| 投稿はその都度やるもの | **予約投稿がある**（「この投稿の送信をスケジュールする」）。**数週間分をまとめて入れられる** |

**＝人の手が要るのは「写真」だけ。本文の投稿は機械で回る。**

### かたち

| | 誰が | 頻度 |
|---|---|---|
| **① 最新情報（写真なし）を予約投稿でまとめて入れる** | 原稿=web-inflow ／ 査読=CMO ／ 投稿=ブラウザ担当 | 月1回まとめて。**オーナーの出番なし** |
| **② 写真を「写真」タブにドラッグ** | **オーナー（5分）** | 月1回・10〜15枚 |
| ③ API利用申請 | 下書き=ブラウザ担当 ／ 提出=オーナー | 通れば①②とも不要になる |

②は**投稿への添付ではなくプロフィールの写真欄**。写真は毎月増え、最新情報は毎週出るので鮮度は保てる。

### 🔴 API利用申請は「出したつもり」だった可能性が高い

`docs/cmo-savedata.md` に「2026-09-14 に申請済み（ケースID `3-3170000041515`、審査7〜10営業日）」と
書いてあるが、**受領メールが1通も無い。**

- ブラウザ担当が `case.foot.kid@gmail.com` を30日ぶん検索 → **0件**
- CMO が独立に検索 → **0件**（ビジネスプロフィールからのメールは 9/13 のオーナー権限移譲の2通だけ）
- Cloud Console の割り当ては **`Requests per minute = 0`**（未承認と整合。ただし申請中でも0なので決め手にならない）

**`onehitter.her@gmail.com` の受信箱は確認できていない**ので「絶対に出していない」とまでは言えない。
**「成立していない前提」で動く。**①②が回っている限り API は急がないので、**オーナーに聞かない。**
9/28 の確認トリガー（`trig_01FZdKt4XkNo7zH5C86EEU1X`）は残す。

★ **写真の添付だけは、APIが通っても残る可能性がある。**内蔵ブラウザからファイル選択ダイアログを
操作できず、localhost・Drive からの取得はページのCSPで遮断される（2026-09-20 実測）。

## 6. まだ正直に言っておくこと

- **広告スクリプトは前日ぶんを取る。**当日の異常には最短で翌朝まで気づけない。
  日予算 ¥1,667 なので、最悪の取りこぼしは1日 ¥1,667。**毎時に上げる価値は無い**と判断した
- **CVが月5〜10件の規模では、A/Bテストは成立しない。**1パターンあたり月1件では差が判定できない。
  レスポンシブ検索広告（見出し10・説明文4）の資産別評価と、広告グループ間の比較で代える
- **GBP APIが却下されたら、GBPは人手が残る。**そのときは回数を減らす方向で設計し直す
