## 脆弱性の概要（10/21 夕方時点の報道）
- CVE-2026-109618 / CVE-2026-109619。CVSS 9.2。認証なしで遠隔からコードを実行される恐れがある。
- PHP の修正版は 10/21 23:00 JST に公開予定。影響する版は公式に未発表。報道では PHP 5 以降すべてが対象になりうる。
- 暫定策の `session.upload_progress.enabled=0` は「単体では不十分」と、提案した GMO Flatt Security 自身が訂正している。根本の対策は修正版の適用だけ。
- 情報源：[piyolog](https://piyolog.hatenadiary.jp/entry/2026/10/21/174516)、[ITmedia](https://www.itmedia.co.jp/news/article/2610/21/2000002462/)、[@IT](https://atmarkit.itmedia.co.jp/ait/articles/2610/21/news072.html)

## 23:20 再確認（CMO）
- **修正版が公開された**：8.5.12／8.4.27／8.3.36／8.2.35。**8.1 と 8.0 は公式の修正なし**（[Help Net Security](https://www.helpnetsecurity.com/2026/10/21/php2shell-php-vulnerabilities-patched-cve-2026-109618-cve-2026-109619/)、[Tenable FAQ](https://www.tenable.com/blog/php2shell-cve-2026-109618-cve-2026-109619-frequently-asked-questions-about-critical-php-remote)、[GMO Flatt](https://blog.flatt.tech/entry/php2shell)）
- **her.jp はまだ止まっていない**：トップ・`?rest_route=/` が今も `X-Powered-By: PHP/8.1.34` で応答している。browser は掲示板（20261021-03）をまだ読んでいない（オーナーの合図待ち）
- ロリポップ・リアライズの告知は、検索では見つからなかった
- 手順 B（PHPを上げる）だけでは不十分になりうる。ロリポップの 8.4／8.5 が修正済みの番号（8.4.27／8.5.12 以上）になったかは、切り替えたあとの `X-Powered-By` で確かめるまで分からない。**だから手順 A（PHPに届かせない）を先にやる**

## 10/22 07:36 朝の再確認（CMO）
- **ロリポップが緊急メンテナンス中**（[ロリポップのお知らせ](https://lolipop.jp/info/)）。「修正版の公開に先立って予防措置としてメンテナンスを実施」。ユーザー専用ページ（管理画面）・ロリポップFTP・旧WEBメーラーが使えず、**新たにログインできない**
- **her.jp は全URLが 502**（静的な license.txt も 502）。外からPHPに届かない状態なので、**今は攻撃を受けにくい**。ロリポップがサイトの表示ごと止めたと見られる
- 結果として、手順 A・B は**メンテナンスが明けるまで実施できない**。browser はログインを試さないで待つ
- メールはお知らせの停止一覧に無い（旧WEBメーラーのみ停止）
- 明けたら：① her.jp の X-Powered-By を見る（8.1.34 のままなら手順 A を即実施。修正済みの番号に上がっていれば A は念のため実施）② リアライズの件は引き続きオーナー判断
