## 1. 承認設定を置く（2分）

僕が毎回確認を求める回数を減らす設定です。**僕自身では置けません**
（エージェントが自分に権限を与えることは仕組みとして禁止されています）。

### 手順

1. このチャットで送った `claude-settings.json` をダウンロード
2. `one-marketing` のフォルダの中に `.claude` というフォルダを作る（すでにあればそのまま）
3. その中に `settings.json` という名前で置く

最終的にこうなります：

```
one-marketing/
  .claude/
    settings.json   ← ここ
  docs/
  lp/
  tools/
```

### 確認

Claude Code で `/hooks` を一度開くと設定が読み直されます。
以降、git や スプレッドシート操作の確認が出なくなれば成功です。

### 他のプロジェクトでも使う場合

**同じファイルを、各プロジェクトの `.claude/settings.json` に置いてください。**
`~/.claude/settings.json`（全プロジェクト共通）に置く手もありますが、
このセッションはクラウド上の使い捨てコンテナで動いているため、
そちらに書いても**次のセッションには残りません**。
リポジトリに置いてコミットするのが、唯一ずっと効く方法です。

## 3. サービスアカウントに権限を追加（4分）

**これをやると、今後「APIを有効にしてください」というお願いが来なくなります。**
1回きりの作業で、以後の依頼が恒久的に消えます。

### 手順

1. https://console.cloud.google.com/iam-admin/iam?project=one-hitter-sheets を開く
2. 上部のプロジェクトが **`one-hitter-sheets`** であることを確認
3. **「アクセスを許可」**（英語表示なら `GRANT ACCESS`）を押す
4. **「プリンシパルを追加」** の欄に、次をそのまま貼る

   ```
   claude-sheets@one-hitter-sheets.iam.gserviceaccount.com
   ```

5. **「ロールを選択」** を押して、検索欄に `Service Usage` と入力
6. **「Service Usage 管理者」**（`Service Usage Admin`）を選ぶ
7. **「保存」** を押す

### これで何が変わるか

新しいGoogleのAPIが必要になったとき、僕が自分で有効にできるようになります。
今日の手順2のような作業が、今後発生しません。

**やらなくても支障はありません。** その場合は毎回1クリックお願いすることになります。

## 4. Netlify のトークンを発行（6分）★今日いちばん効きます

**これが済むと、LPとアンケートの公開・更新を僕がやれるようになります。**
ネームギアが復旧しなくても、今日から公開できます。

### なぜ必要か

このセッションからは **HTTPSしか外に出られません**（実際に試して確認済み。
FTPもSSHもタイムアウトします）。Netlifyは公開用のHTTPS APIを持っているので、
トークンさえあれば僕がデプロイできます。

### 手順

1. https://app.netlify.com/signup を開く
2. **「Sign up with GitHub」** でアカウントを作る（GitHubアカウントがあるので一番早い）
   - GitHubを使いたくなければメールアドレスでも可
3. ログインしたら、右上のアイコン → **「User settings」**
4. 左メニューの **「Applications」**（または `OAuth applications` の並び）
5. **「Personal access tokens」** の欄で **「New access token」** を押す
6. 説明欄に `claude-cmo` と入れる
7. 有効期限は **「No expiration」** か、1年程度
8. **「Generate token」** を押す
9. 表示された文字列（`nfp_` で始まる長い英数字）を控える

**この文字列は一度しか表示されません。** 閉じる前にコピーしてください。

### 渡し方

**チャットに直接貼らないでください。**

1. Googleドライブで新規ドキュメントを作る
2. ファイル名を **`Netlify_トークン`** にする
3. 中身にトークンを貼る
4. **共有はしない**（自分だけが見られる状態のまま）
5. チャットには **「Netlify_トークン 置いたよ」** とだけ書く

僕がDrive連携で読み取ります。読んだら「受け取りました」と返します。

## 5. KDDI Message Cast に申し込む（12分）

詳細は `docs/sms-setup-steps.md` にありますが、要点だけ。

### 手順

1. https://kddimessagecast.jp/ を開く
2. **「お問い合わせ」または「お申し込み」** へ進む
3. 次の内容で入力

   | 項目 | 入れる値 |
   |---|---|
   | 会社名 | ワンヒッター株式会社 |
   | 業種 | サービス業（ハウスクリーニング） |
   | 利用目的 | 既存のお客様への再来案内、施工後アンケートのご案内 |
   | 想定送信数 | 月100〜200通。年末に一度だけ800通程度の一斉送信あり |
   | 利用開始希望 | 2026年9月中 |
   | プラン | **APIプラン**（管理画面プランではないと明記） |
   | 連携方法 | HTTPS API |

4. 備考欄に **「トライアルを希望します」** と書く
   （2か月・最大3,000通まで無料。年末の一斉送信がまるごと収まります）

### 必ず聞いてほしいこと（1つだけ）

> **「月1,000通程度の利用の場合、1通あたりいくらになりますか？」**

公開単価は「9.35円（税込）〜」で "〜" が付いています。

**10円（税込）を超える提示だったら、その数字だけ教えてください。**
NTT CPaaS（1通10円の確定値）に切り替えます。これが撤退ラインです。

### このあと

最短6営業日でアカウント通知書がメールで届きます。
届いたらAPIキーを発行して、**手順4と同じやり方（Driveの非公開ファイル）**で渡してください。

## 6. ネームギアの状況を調べる（10分）

**⚠️ 新規登録はしないでください。** 別のアカウントができてしまい、
いま持っているドメインの管理権とは結びつきません。**やることは「既存アカウントの特定と復旧」です。**

### なぜそう言えるか

`one-hitter.jp` は**すでにネームギアで管理されています**（実際に確認済み）。

```
$ dig one-hitter.jp NS
ns1.namegear.co.
ns2.namegear.co.
```

つまり **どこかに必ず、このドメインを持っているアカウントが存在します。**
新しく登録しても、そのアカウントとは別物です。

### 手順（順番どおりに）

**ステップ1：誰が登録したのかを調べる（3分）**

1. https://whois.jprs.jp/ を開く
2. 検索欄に `one-hitter.jp` と入れて照会
3. **「登録者名（Registrant）」** と **「登録年月日」** を見る

ここに出てくる名義で、状況が変わります。

| 登録者名 | やること |
|---|---|
| ワンヒッター株式会社 / 佐々木さん | ステップ2へ（自社のアカウントがあるはず） |
| 制作会社・前任者の名前 | **その相手に連絡**するのが最短。ステップ2は飛ばす |
| 見覚えのない名前 | スクショを送ってください。一緒に考えます |

**ステップ2：パスワードを再設定する（4分）**

1. https://namegear.co/ を開く
2. **「ログイン」** を押す
3. **「パスワードをお忘れの方」** に進む
4. **ドメインを取得したときに使ったメールアドレス**を入れる
   - 会社の代表アドレス、佐々木さんの個人アドレス、前任者のアドレスなど
   - **心当たりを片っ端から試してください。** 登録されていないアドレスなら何も届きません
5. 再設定メールが届いたら、パスワードを設定してログイン

**ステップ3：それでもダメならサポートへ（3分）**

- メール：`support@namegear.co`
- 電話：`075-325-1962`
- 運営会社：BR domain Inc.

伝えること：

```
ドメイン `one-hitter.jp` の管理アカウントにログインできません。
登録者はワンヒッター株式会社です。
アカウントの特定と、パスワード再設定の方法を教えてください。
```

法人名義の確認書類を求められる可能性があります。登記簿を用意しておくとスムーズです。

### 今日ログインできたら

ログインできたら、DNSレコードの追加画面で次を1行足してください。

| 項目 | 値 |
|---|---|
| ホスト名 | `lp` |
| 種別 | `A` |
| 値 | `118.27.125.166` |

**既存のレコード（`www`、`mail`、`@`）には触らないでください。** 追加だけです。

### 今日ログインできなくても問題ありません

**手順4（Netlify）が済んでいれば、仮のURLで先に公開できます。**
アンケートQRはスマホ画面で見せる運用なので、URLは後から差し替えられます。
ネームギアが復旧してから独自ドメインに移し、QR画像を入れ替えれば済みます。

## 8. アンケートを読んで公開の可否を決める（10分）

### 見るもの

- **現物**：チャットで送った `index.html`。開いて実際に触ってみてください

### 判断してほしいこと

1. **公開してよいか**（「外に出す」に当たるので承認が要ります）
2. **回答特典**は「次回予約割引（時期別 最大15%）」で確定。追加の特典を付けるか

   - 部屋全体・玄関・表札が写るものは、契約書に写真利用の条項がなければ避けるべき
   - 契約書に記載があれば教えてください。使える範囲が広がります
