# 読本・点検がダークモードで暗くなる — 直し方

調べたの 2026-09-12〜15 ／ LP・サイト担当 ／ **ソースがこのリポジトリに無いので、こちらでは直せません**

## 何が起きているか

端末のダークモードで開くと、**背景が `rgb(12,23,28)` の暗色になります。**
お客様が開くページはダークモード対応を入れない決まり（`docs/org/README.md` 4.8.2）に反しています。

| ページ | ダークモードでの背景 |
|---|---|
| `one-hitter-dokuhon.netlify.app`（読本） | `rgb(12,23,28)` ★暗い |
| `one-hitter-tenken.netlify.app`（無料点検） | `rgb(12,23,28)` ★暗い |
| LP4本・アンケート・予約フォーム | `rgb(243,247,249)` ほか、すべて白地 |

**この2本は、読本A6カード（印刷物）のQRの遷移先です。** 刷ってしまうと直しにくくなります。

## ソースの在処が分かりません

**このリポジトリのどのブランチにもありません。**
全リモートブランチを `dokuhon` / `tenken` で検索して0件でした。
別のワークスペースか、別のリポジトリから配信されていると思われます。
**持ち主のスレッドで直してください。**

## 直し方（公開ページから読み取った実物です）

両方とも同じ作りです。**やることは2つ、消して足すだけ。**

### ① 次の2ブロックを消す

```css
@media (prefers-color-scheme: dark){
  :root:not([data-theme="light"]){
    --ground:#0C171C;
    --surface:#12222A;
    …
  }
}
```

```css
:root[data-theme="dark"]{
  --ground:#0C171C;
  --surface:#12222A;
  …
}
```

読本では、それぞれ **779文字**と**675文字**のブロックです（点検も同じ構成）。

### ② `:root` に1行足す

```css
:root{
  color-scheme: light;   /* ← これを足す */
  …
}
```

**いまこの宣言がありません**（両ページとも0件）。
これが無いと、フォームの部品やスクロールバーがブラウザ側の判断で暗くなります。

## 直したあとの確かめ方

```bash
node tools/check-darkmode.js https://one-hitter-dokuhon.netlify.app/ https://one-hitter-tenken.netlify.app/
```

**「すべて白地です」と出て、終了コードが0になれば完了です。**
端末のダークモードON・幅390px（お客様の実機と同じ条件）で、
`body` の算出後の背景色を実測しています。

> **HTMLを grep するだけでは足りません。** どのブランチの版を見ているかで結論が変わります。
> 2026-09-12 に、掲示板では「アンケートが原因」と共有されましたが、実測すると
> アンケートは白地で、暗いのはこの2本でした。**本番のURLを開いて測ってください。**

## 直ったら

`tools/haishin-kakunin.py --honban` の最後に出る
「〔参考〕読本・点検がまだ暗いままです」が消えます。
