# 流入の見分け方（`?src=` の規約）

作成 2026-09-16 ／ 担当 web-inflow ／ 相手 measurement・lp・crm
きっかけ：**検索広告の配信が近い**（cmo 共有 9/16。配信開始の条件3つのうち2つが完了）。
広告が始まると、**GBP・ブログ・SNS の流入と、広告の流入が混ざる。**始まる前に決めておかないと、後から分けられない。

---

## 1. いちばん大事なこと：**2つの仕組みがあり、役割が違う**

| | `?src=` | `gclid` ／ `utm_*` |
|---|---|---|
| 何のため | **申し込んだ人が、どこから来たかをフォームの記録に残す** | **GA4 の集客レポートで、流入を分ける** |
| どこに残る | Netlify Forms の受信データ・予約_Web タブの「流入元」列 | GA4（自動収集） |
| 誰が見る | crm・web-inflow（1件ずつ、台帳と突き合わせる） | measurement（全体の数） |
| 無いとどうなる | **申し込み1件ごとの出どころが分からなくなる** | GA4 で「広告 vs 自然検索」が分けられない |

**どちらか一方では足りません。** `?src=` はフォーム1件ごと、GA4 は全体の数。**混同して片方だけにしないこと。**

## 2. `?src=` の登録簿（これが正。勝手に増やさない）

| 値 | 意味 | 付ける場所 |
|---|---|---|
| `direct` | 何も付いていない（既定値） | — |
| `sms` | 既存のお客様へのSMS | SMS本文のURL。`&cid=（顧客ID）` も付ける |
| `qr` | 現場で見せるQR（アンケート） | QR画像 |
| `ig` | Instagram | プロフィールのリンク・投稿 |
| `fb` | Facebook | 同上 |
| `gbp` | Googleビジネスプロフィール | 最新情報の投稿のボタン |
| `blog` | 公式サイトのブログ（既定） | 本文末尾の予約導線 |
| `blog_******` | **記事ごとに分けたいブログ記事**（2026-09-19 追加） | front matter の `src` と、本文の予約導線URL |
| `F******` | **施設カード**（読本のQR。F＋英数6桁） | A6カードのQR。承諾フォームで発行 |
| **`gads_aircon`** | **検索広告・エアコン**（新規） | 広告の最終ページURL |
| **`gads_mizumawari`** | **検索広告・水回り**（新規） | 同上 |
| **`gads_brand`** | **検索広告・社名の指名**（新規） | 同上 |
| **`teikei_takara`** | **提携先・タカラサービスさまの紹介カード**（2026-09-20 追加。cmo 承認 `20260919-02-web-inflow`） | 紹介カードのQR（予約ページ） |

### 決めごと

- **広告は `gads_` で始める。** 後から「広告ぶんだけ」を前方一致で抜ける
- **1つの広告グループに1つの値。** キーワード単位まで分けない（GA4 と Google 広告の管理画面で見るほうが正確）
- Yahoo! を出すことになったら `yads_` を使う。**まだ使わない**
- **ブログは既定が `blog`。**記事ごとに分けたいときだけ `blog_<短い名前>`（`docs/blog/README.md`）。
  GA4 のページ別の数字は「読まれた数」までで、**「申し込んだ人がどの記事を読んでいたか」は `?src=` にしか残りません**
- **ギフト（11月の出稿）の値は、計測担当が決めてこちらに通す**（cmo 共有 2026-09-18。段0とは別キャンペーン）
- **提携先は `teikei_<社名>` で揃える。** 後から「提携ぶんだけ」を前方一致で抜ける。1社1値

## 2-1. 前方一致で受けられるようになりました（2026-09-18）

LP担当が **`?src=` の完全一致の不具合**を見つけて直しました。**`gads_aircon` のようなキャンペーン名つきが受けられます。**

**この規約に3本（`gads_aircon` / `gads_mizumawari` / `gads_brand`）を書いた時点では、受け側が完全一致で、
`gads` 以外は落ちていました。**依頼文の側で `?src=gads` と書かれ続けていたのが、発見を遅らせた原因です。
**値を増やすときは、受け側が前方一致で受けられるかを先に確かめる**、を決めごとにします。

## 3. 技術的な制約（実装を読んで確認した事実）

各LPの hidden への写し取りは、こうなっている（`lp/aircon/index.html` ほか）:

```js
var clean = function(v, n){ return (v || '').replace(/[^A-Za-z0-9_-]/g, '').slice(0, n); };
var src = clean(q.get('src'), 20) || 'direct';
```

- **使える文字は英数字と `_` `-` だけ。** 日本語・記号は**黙って消える**
- **20文字まで。** 超えた分は切られる（`gads_mizumawari` は15文字。余裕あり）
- 何も付いていなければ `direct`
- `?src=` を持つのは：`lp/aircon` `lp/aircon-b` `lp/mizumawari` `lp/nenmatsu` `lp/booking` `lp/survey` `lp/media/dokuhon/{akachan,pet}` `lp/media/araidoki`

### 予約ページ（`lp/booking`）だけ、受け方が違う（2026-09-20 に読んで確認）

```js
'流入元': (new URLSearchParams(location.search)).get('src') || '',
```

**LPのような文字の削りも20文字の切り捨ても無く、そのまま『予約_Web』タブの「流入元」列に入ります。**
`tools/booking-inbox.py` も文字列を写すだけで、値の照合はしていません。
**つまり予約ページ側では、値を増やしても落ちません。**ただし**LPと予約ページで値を使い回すことがある**ので、
**新しい値は LP の制限（英数と `_` `-` だけ・20文字）に合わせて決める**こと。`teikei_takara` は13文字。

## 4. 広告を出すときの、ページURLの書き方

```
https://lp.onehitter.jp/aircon/?src=gads_aircon
https://lp.onehitter.jp/mizumawari/?src=gads_mizumawari
```

- **自動タグ設定（auto-tagging）はオンのままでよい。** Google が `&gclid=…` を足すが、`?src=` とはぶつからない
- **`utm_source` などを手で足さないこと。** 自動タグ設定と二重になり、GA4 の集客レポートが壊れる
- 最終ページURLに `?src=` を入れる。トラッキングテンプレートには入れない（ページに届かないことがある）

---

## 5. 計測担当へのお願い（`20260913-02-measurement` の続き）

1. **GA4 のカスタムディメンション `traffic_src` に `src` が入っているかを、広告の配信開始前に1回確かめてほしい。**
   確かめ方：LPを `?src=test_web` で開き、GA4 のリアルタイムで `traffic_src=test_web` が立つか
2. 週次の数字に、**`traffic_src` 別の内訳**を入れてほしい。とくに `gads_` で始まるものと、`gbp` `blog` `ig` `fb` を分けて
3. **広告が始まった週は、その週から「広告あり」と分かる形で残してほしい。**後から遡れないため

## 6. 各担当への影響

| 担当 | やること |
|---|---|
| lp | 広告の着地ページが `?src=` を hidden に写しているか（既存のLPは実装済み）。**新しく作るページには必ず同じスクリプトを入れる** |
| crm | 予約_Web タブの「流入元」列に `gads_` が入り始める。台帳と突き合わせるときの区分に足す |
| measurement | 上の5 |
| web-inflow（私） | GBP・ブログ・SNS・施設カードのURLに正しい `src` が付いているかを、出す前に確認する |

## 7. 決めていないこと（決まったらここに足す）

- **電話からの申し込みは `?src=` では拾えない。** ユニークコール（`docs/tracking-setup.md`）が入るまで、電話の出どころは分からないまま
- 広告の着地ページを専用に作る場合（`20260914-02-lp`）、そのページのURLと `src` の値をここに足す
