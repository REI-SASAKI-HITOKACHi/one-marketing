# 3. 入れ替えの順番

ブラウザ担当の案でよい。**2点だけ足す。**

```
新トークンを作る → LPスレッドに渡す → テスト配信1回 → 成功を確認 → 古いトークンを削除
```

### ① テスト配信を「空の配信」にはできない

**Netlifyの配信はサイト全体のファイル一覧を差し替えるので、
手元のビルドに無いページは本番から消える。** 配信前に必ず通す。

```bash
python3 tools/build-site.py netlify
python3 tools/check-tracking.py netlify
python3 tools/haishin-kakunin.py      # 固定URL5本の欠落もここで止まる
```

### ② 古いトークンは「新トークンで1回配信が成功してから」消す

成功を確認してから消せば、**配信が走っている最中かどうかを気にする必要がない。**

## 時間帯

**広告が動いていない時間帯はもう無い**（3本が配信中）。
ただし**差し替えは原子的で、配信中も本番は今の内容を返し続ける。**
**広告と時間帯をずらす必要はない。**

**それより「10/1 のCPA判定より前に済ませる」ほうが大事。**
判定の直前に配信が止まると、直せるのが判定の後になる。**今週中に賛成。**

# 無期限（No expiration）について

**オーナーの方針なので、そのまま進めてよい。** 1点だけ事実として。

**無期限のトークンは、漏れた場合に失効させるまで有効なまま。**
＝**置き場所の管理が、これまでより重くなる。**
**チャットに貼る回数を減らすほど安全**なので、環境変数を推す理由もこれ。

# 失敗しても本番は壊れない

`deploy-netlify.py` はトークンが無い／無効なら**配信前に止まる。**
**黙って部分配信することはない。** 入れ替えに失敗しても、止まるだけ。

# 入れ替えが済んだあとの確認

```bash
# 1. トークンが生きているか（持ち主が出れば有効）
NETLIFY_TOKEN=… curl -sS -H "Authorization: Bearer $NETLIFY_TOKEN" \
  https://api.netlify.com/api/v1/user | head -c 200

# 2. 受信箱が読めるか（予約の取り込みが生きているかの確認）
NETLIFY_TOKEN=… python3 tools/check-survey-inbox.py

# 3. 配信（点検を全部通してから）
NETLIFY_TOKEN=… python3 tools/deploy-netlify.py

# 4. 固定URL5本が生きているか
for u in aircon aircon-b mizumawari nenmatsu survey; do
  curl -sS -o /dev/null -w "$u %{http_code}\n" "https://one-hitter-lp.netlify.app/$u/"
done
```

**4番まで通って初めて「入れ替え成功」。** ここまで古いトークンは消さないこと。
