## 2. MTGシートにあって `prices.json` に無いルール

15行目の決定には、メニュー単位の分数のほかに次の2行がある。**どちらもコードに入っていない。**

> ※複数の場合は1種目につき30分/最大削減時間60分
> ※移動時間込みで1日12時間上限

- **複数施工の短縮（1種目につき−30分・最大−60分）**：`tools/build-booking.py` の `shoyouFun()` は
  メニューの分数を単純に足すだけ（401〜405行）。2種目以上のとき、**実態より最大60分長く枠を押さえている。**
- **1日12時間上限（移動込み）**：`tools/build-slots.py` は前後に `IDOU_FUN = 60` 分の移動を確保するが、
  「1日の合計を12時間で止める」制限は持っていない。16行目の「稼働22日/月・12時間/日」は現状どこにも効いていない。

## 3. どこに効くか（直したときの影響先）

| ファイル | 使い方 | 影響 |
|---|---|---|
| `tools/build-juchu.py` | `shoyou()`（65行）で `所要` から分を取り、受注フォームの「所要の目安」表示と**終了時刻の自動計算**に使う | 分が変わると終了時刻・カレンダー予定の長さが変わる |
| `tools/build-booking.py` | `shoyou_fun()`（48行）→ ページの `shoyouFun()` → `bucketKey()` で**空き枠のバケツを選ぶ** | 分が変わるとお客様に出る**空き枠が変わる** |
| `tools/build-slots.py` | `BUCKET = [60, 90, 120, 150, 180, 210, 240, 300, 360, 420, 480]` に対して枠を作る | 150・180 はバケツにあるので、値を直しても再生成で足りる |

いずれも `所要` が無いメニューは既定値60分（`KITEI_SHOYOU`）になる。

## 4. 判断が要ること（オーナー確認のうえCMOが決める）

1. **どちらを正にするか。** MTG15行目はオーナーが確定させた値なので、原則MTG側が正のはず。
   ただし `prices.json` 側の値も誰かが根拠を持って入れた可能性があるため、**上書きの前に一度確認したい。**
   とくに浴室（120→180）は**1日に入る件数が減る方向**なので、12月の受付可能件数の見込みに直接効く。
2. **洗濯機のメニューを縦型/ドラムに割るか。** MTGは縦型90分・ドラム180分（受注停止）と分けているが、
   `prices.json` は「洗濯機クリーニング」1本（120分）。分けるなら金額の扱いも要確認（**今回は金額に触れていない**）。
3. **エアコンの種類（天カセ・床置き・窓はめ 各120分）をメニューに足すか。** 現状は既定値60分で見積もられる。
4. **複数施工の短縮ルール（−30分/種目・最大−60分）を `build-booking.py` に実装するか。**
   実装しないかぎり、2種目以上の予約は枠を長く取りすぎる。
5. **床WAX** はオーナー側も空欄。分数を決める必要がある。
