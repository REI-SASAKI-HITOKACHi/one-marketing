# 紹介カードと受付の導線（案）

依頼 `20260926-01-lp` の③（オーナー補足 No.38）／ 作成 2026-09-27 LP・サイト担当
実物 … `print/shokai-card/`（作り直しは `python3 tools/make-shokai-card.py`）

## 制度（確定済み。カードはこれ以上のことを書かない）

- 消費者 → 消費者の紹介：**紹介した本人の次回料金から一律1,000円割引**。公式LINEでクーポンを配布
  （`docs/cmo-savedata.md`「紹介の制度」）
- **紹介された方：初回のお掃除から1,000円割引**（2026-09-27 オーナー決定、依頼 `20260927-01-lp`）。
  条件は**予約時に紹介者の名前を伝えること**。金額は `data/prices.json` の「紹介」に記録済み

## いま足りないもの

`docs/cmo-savedata.md` の未整備項目に**「誰の紹介かを記録する運用が未整備」**とある。
割引の制度はあっても、**紹介された方が申し込んだときに紹介者の名前を拾う場所が無い**と、
紹介した本人に割引を渡せない。カードはそこを埋めるためのもの。

## 流れ

```
① 施工後、和真さんがお客様に紹介カードを数枚手渡す（アンケートQRカードと同じ場面）
② お客様が表の下線に自分の名前を書いて、知人に渡す
③ 知人が申し込む
     WEB … 裏のQR → 予約ページ（?src=shokai）→「ご要望」欄に紹介者の名前
     電話 … 080-8043-8259 で紹介者の名前を伝える
④ 受付で「紹介者の名前」を記録する
⑤ 知人の施工が終わったら、紹介した本人に公式LINEで1,000円割引のクーポンを送る
```

- **③のWEBは「ご要望」欄で今日から回る。** 予約フォームに手を入れなくても成立する書き方にした
- `?src=shokai` は予約ページの隠し欄と GA4 の `traffic_src` に入る。**ただし予約ページの配信
  （`20260927-01-cmo`）が済むまでは、本番の予約ページが `src` を受け取れない**
- ⑤のクーポンは公式LINE経由なので、**紹介した本人が友だち追加していないと渡せない。**
  アンケート完了画面の友だち追加（依頼①）がここにも効く

## 予約フォームの案（booking は CMO の持ち物なので案だけ）

**案A（推奨）：`?src=shokai` で来たときだけ「ご紹介者のお名前（任意）」欄を出す**

- 紹介以外のお客様にはフォームが1行も増えない
- `src` はすでに読んでいるので、`src === 'shokai'` のときに欄を表示するだけ
- Netlify の受け口に `name="紹介者"` を足す（無いと送っても記録されない。`gclid` と同じ注意）
- 欄が空でも「ご要望」に書いてあれば拾える。**両方を見る**運用にする

**案B：何もしない（「ご要望」欄だけで受ける）**

- 手間はゼロ。ただし名前が自由記述に埋もれるので、受付で見落としやすい

## 受付の記録（シートは planning／crm の持ち物なので提案だけ）

- 顧客シートの `流入経路` には「紹介」がすでにある（2026年1〜9月で9件・¥348,660）
- **足りないのは「紹介者」の列。** これが無いと⑤で誰に割引を渡すかが分からない
- 紹介者の列に名前が入った行を、施工完了の時点で拾ってLINEのクーポンを送る

## 決めていないこと（お金＝オーナー判断）

- ~~紹介された方にも特典を付けるか~~ → **9/27 オーナー決定：初回1,000円割引を付ける。** 表・裏に反映済み
- **受付では「紹介者の名前」があれば、紹介された方の初回から1,000円を引く。** 名前が無ければ引かない
  （カードの裏に「ご予約のときに、ご紹介者のお名前をお伝えください」と書いてある）
- 印刷の部数と発注先（名刺サイズ・両面カラー。入稿用PDFは塗り足し3mm込みの 97×61mm）
