## 🔴 「入稿ポータルプラン」で、宛先ごとのURLが作れるか

こちらの配信設計は、**宛先ごとに違うURLを送る**前提です。

```
https://one-hitter-nenmatsu.netlify.app/?src=sms&cid=（顧客ID）
```

`cid` に顧客IDを入れることで、**誰が反応したかを台帳と突き合わせます**
（`docs/SMS配信のリンク設計.md`）。

今回のプランは **API ではなく「入稿ポータル」** です。
CSVをアップロードして送る形式と思われますが、**1行ごとに違うURLを差し込めるか**を
確認する必要があります。

- **差し込みができる** → 設計どおり進められる
- **できない（全員同じ本文）** → `cid` は使えず、`?src=sms` だけになる。
  誰が反応したかは分からず、**経路別の件数までしか測れません**

**できない場合でも施策は打てますが、効果測定の精度が落ちます。**
本番でAPIプランに移る前提なら、お試しはこのままでも構いません。

## そのほか確認すること（添付資料を開いたとき）

1. **送信元の表示**（電話番号のみか、企業名を出せるか）。SoftBank宛は共通番号になる可能性あり
2. **1通の文字数**。70文字を超えると課金が増えます
3. **短縮URLとクリック計測**の有無。無ければ本文の文字数計算に実URLの長さを入れる
4. **お試し期間の通数上限と期限**（2か月/3,000通と調査済みだが、申込書で要確認）
5. **配信ガイドライン**に、当社の文面が抵触しないか（深夜送信・広告表記など）
