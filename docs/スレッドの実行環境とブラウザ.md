# ブラウザが使えるスレッドと使えないスレッドの違い

調査日: 2026-09-07 ／ 実データで確認

## 結論：クラウドかローカルかで決まります

オーナーの見立てどおりでした。**セッションを作るときに選ぶ実行環境**で決まります。

| 実行環境 | 実体 | ブラウザ |
|---|---|---|
| `anthropic_cloud` | Anthropic側の隔離コンテナ | **使えない** |
| `bridge` | **オーナーのPC上で動くClaude Code**（リモート接続） | **使える** |

## 各スレッドの実際の値

`list_sessions` で取得した値です。

| スレッド | 実行環境 | 起点 |
|---|---|---|
| One Hitter CMO戦略（このスレッド） | `anthropic_cloud` | desktop_app |
| LP概要案プレゼン | `anthropic_cloud` | desktop_app |
| 計測スレッド／顧客接点スレッド | `anthropic_cloud` | mcp_seed |
| 見積アプリ改善 | `anthropic_cloud` | desktop_app |
| 自動帳票生成システム | `anthropic_cloud` | desktop_app |
| **導線スレッド（応募〜登録の自動化）** | **`bridge`** | claude_code_cli |
| **獲得スレッド（広告・助太刀）** | **`bridge`** | claude_code_cli |
| **システムスレッド（Conea本体）** | **`bridge`** | claude_code_cli |
| **決算作業と確定申告** | **`bridge`** | claude_code_cli |

**ConoHaやGitHubのログインを画面で対応していただいたのは、すべて `bridge` のスレッドです。**
クラウド側のスレッドでは一度もできていません。

## クラウド側で実際に何ができないのか

「インターネットに出られない」のではありません。**出口が限定されています。**

| 手段 | 結果 |
|---|---|
| `curl` / WebFetch / API呼び出し | **通る**（専用のプロキシ経由） |
| Chromium（ブラウザ） | **通らない**。`ERR_CONNECTION_RESET` |

プロキシを明示的に指定しても結果は同じでした（2026-09-07 再検証）。
つまり **ブラウザだけが外に出られない**状態です。

そのため、クラウド側のスレッドでも次のことは問題なくできます。

- サイトのHTMLを取得して中身を確認する（実際にLPの公開確認はこれでやっています）
- Google API・Netlify API・DNS照会など、APIで完結する作業
- リポジトリの操作、ビルド、デプロイ

できないのは**画面を見ながらの操作**だけです。ログイン、管理画面のクリック、
パスワード付きファイルのダウンロードなど。

## 使い分け

**次のような作業は、ローカル（`bridge`）のスレッドを立ててください。**

1. ロリポップ・ConoHa・ネームギアなど、管理画面へのログインが要る作業
2. Googleビジネスプロフィールの編集
3. KDDIのようなパスワード付きファイルのダウンロード
4. 画面を見ながらでないと判断できない作業

**クラウド（`anthropic_cloud`）のままでよいのは、次のような作業です。**

1. リポジトリのコード・ドキュメントの作成と修正
2. スプレッドシート・Drive・Netlify など、APIで動かせるもの
3. 分析、原稿作成、調査
4. 公開済みページの確認（HTMLを取得して検証できます）

## 補足

実行環境はセッションを作るときに決まり、**あとから切り替えられません。**
ブラウザ操作が必要になったら、その作業だけローカルのスレッドを立てて、
結果をこちらへ共有していただくのが現実的です。

詳しくは https://code.claude.com/docs/en/claude-code-on-the-web
