## ② 11/4 の中間判定のひな形

期間：**10/29〜11/3 の6日**（11/4 の 14:59 に 11/3 の行が入る）。7日あたりに直して比べる。

数字を入れて流すだけ：
```
python3 tools/nyusatsu-hikaku.py --start 2026-10-01 --end 2026-11-03 \
  --jiki "2026-10-01=クリック数の最大化" --jiki "2026-10-16=コンバージョン数の最大化" \
  --jiki "2026-10-28=切り替えの日（13時台に戻した）" --jiki "2026-10-29=戻した後" --tsuika 2026-10-03
```
出てくる「戻した後」の行を下の表に写す。

| 物差し | 戻した後（10/29〜11/3） | 線 | 判定 |
|---|--:|--:|---|
| 7日あたりの申込 | ＿件 | **1.8件を超える** | ○／× |
| 申込1件あたり（費用 ÷ 申込） | ¥＿ | **¥16,200 以下** | ○／× |
| （参考）クリック/日 | ＿ | CV最大化の時期 6.6 | |
| （参考）CPC | ¥＿ | 上限 ¥500 | |

判定の読み方：
- **両方○** → 戻して良くなった（中間）。11/11 の14日の時点で同じなら確定
- **申込0件** → 申込1件あたりは出せない（×）。クリックが CV最大化の時期より増えていれば「量は戻った・申込は未着」と書く
- **どちらか×** → まだ良くなったとは言えない。11/11 まで続けて見る
- 6日・申込が数件なので、**11/4 は中間**。偶然と区別できるのは14日の時点（比較表の注記のとおり）

## 増額案に使う数字（11/1 で「3件未満」になったとき）

増額は「効果を測れるとき」だけ（オーナー決定 10/16）。測り方は `docs/広告-増額の測り方.md`。今わかっている数字だけ置く：
- 月の上限 = 日予算 × 30.4。日予算 ¥5,000 → 約 ¥152,000、¥7,000 → 約 ¥212,800、¥10,000 → 約 ¥304,000
- 申込1件あたり（当社の記録）：クリック数の最大化の時期 ¥18,550、CV最大化の時期 ¥20,356。**どちらも許容CPA ¥16,200 を上回っている**
- 予算の上限で表示を落としていない（インプレッションシェアの損失は予算ほぼ0%・ランク 72〜78%、browser 10/13〜15）。**日予算を上げても表示が増えるとは限らない**。戻した後の数日で、費用が日予算に張り付くか（＝予算が足りない）を見てから額を決めるのが安全
