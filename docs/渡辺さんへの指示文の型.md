作成 2026-09-08 ／ オーナー指示にもとづく

> **渡辺さんへLINEを送るときは、必ずこの型に沿って書くこと。**
> 個別の判断で崩さない。崩すなら、崩す理由をここに追記してから崩す。

## 大前提：現場は忙しい

オーナーの指摘（2026-09-08）。

> 「（現場は忙しい）という認識を持って作成してほしい」

**渡辺さんは移動中か作業中にこれを読む。** 長文を上から順に読ませる前提で書いてはいけない。
**最初の数行だけで、やることが分かって完結する**構成にする。
whyは大事だが、whyを読まないと動けない書き方は現場を止める。

## 構成（この順番を守る）

オーナー指示（2026-09-08）そのまま。

```
・労い
・やってほしいこと（結論）
  → 端的に。解説は後述する旨を書き添える
＿＿＿ 以下は読まなくても問題にはならない ＿＿＿
・why
・やってほしいことの背景
```

**区切り線より上だけで、指示として完結していること。**
区切り線から下は、時間のあるときに読んでもらう部分。

### 1. 労い・感謝・褒め ― 毎回入れる

オーナー指示（2026-09-08）。

> 「渡辺さんへの感謝や褒めを常に入れるように意識してほしい。誰しもやる気が変わるからね。」

**毎回入れる。** 定型文にならないよう、その時点の事実にひもづける。

- 夜勤明け、連日の施工、猛暑・寒波 → その状況をねぎらう
- 数字で褒める → 「9月の受注9件のうち5件が渡辺さんの現場での次回予約です」
- 直前の対応 → 「昨日のご返信、早くて助かりました」

### 2. やってほしいこと（結論） ― 端的に、解説は後述する旨を添える

- **1〜3行**で終える
- 動詞で終える（「〜してください」「〜をお願いします」）
- 所要時間を書く（「1分で終わります」）
- 複数あるなら番号を振り、**3つまで**にする
- **末尾に「理由は下に書きました。お急ぎなら読まなくて大丈夫です」を必ず添える**
  これがないと、下の長文まで読まなければいけない気にさせてしまう

### 区切り ― 「以下は読まなくてもよい」と明示する

この一行があるかないかで、忙しいときの読みやすさが変わる。

```
──────────────
ここから下は、時間のあるときで大丈夫です。
```

### 3. why ― ここは厚く書く

オーナー指示（2026-09-07）。

> 「人はwhyに納得せずにはモチベーションが生まれないからね。
> 僕(経営)がこの情報はどうしても伏せた方がいい、と思うようなタスクでない限りは、
> 渡辺さんはCOOとして扱う人材だから大部分のwhyは共有すべき。」

**経営数字も共有してよい。** 伏せるのは、オーナーが明示的に伏せると言ったものだけ。

whyの書き方
- **理由は3つまで**に絞る。多いと薄まる
- **数字を出す**（受注件数、クチコミ件数、競合との差、目標と実績）
- **渡辺さん自身の貢献を数字で示す**。これが一番効く

### 4. やってほしいことの背景・補足

運用の細かい話（保存の仕方、渡すタイミング、うまくいかないときの逃げ道）はここ。

## 例（2026-09-08 アンケートQRの依頼を、この型に直したもの）

送った版は解説が先に来ていて長かった。型に沿うとこうなる。

```
渡辺さん

夜勤明けでお疲れのところ失礼します。
9月の受注9件のうち5件、10月は9件のうち8件が、渡辺さんが現場でいただいた
次回予約です。会社の売上をつくっているのは現場です。ありがとうございます。

【お願い（1分で終わります）】
本日の作業が終わったその場で、下の画像をスマホに表示して
お客様に見せてください。「1分だけご感想いただけますか」の一言だけで大丈夫です。
印刷もラミネートも不要です。

理由は下に書きました。お急ぎなら読まなくて大丈夫です。

──────────────
ここから下は、時間のあるときで大丈夫です。

【なぜ今これを】
1. お客様の声が2024年8月から止まっていて、直近1年分がゼロです
2. Googleクチコミが23件。おそうじ革命91・LightCleaning94・ダスキン61。
   評価5.0は当社が最高で、負けているのは件数だけです
3. 現場での一言がいちばん決まっているので、そこを一段効かせたい

【補足】
・カードの訴求を直しました。「12月からは1箇所あたり +3,300円 の繁忙期加算」
  ＝11月までのご予約がお得、という言い方に統一しています
・お渡しは作業完了後、その場で
・現場でうまく開かなければ、無理せずあとでこのグループに一言ください
```

**違い。** 送った版は「なぜ」から入って、依頼が下のほうにあった。
この版は**上の8行だけ読めば動ける**。

## 書くときのチェック

- [ ] 冒頭に労い・感謝・褒めがあるか
- [ ] 最初の5行だけで、やることが分かるか
- [ ] 結論の末尾に「解説は下、急ぎなら読まなくてよい」と書いたか
- [ ] 「ここから下は読まなくてよい」の区切りがあるか
- [ ] whyに数字が入っているか
- [ ] 依頼は3つ以内か
- [ ] うまくいかなかったときの逃げ道を書いたか（「無理せず、あとで一言ください」）
- [ ] 送信タイミングは適切か（**夜勤明けの就寝時間帯に送らない**。施工の30分前など）

## 送り方

```
python3 tools/line_client.py push --file 本文.txt          # テキスト
python3 tools/line_client.py image <画像の公開URL> --text "本文"   # 画像つき
```

`--dry-run` を付けると送らずに内容だけ表示する。**長文は必ず一度dry-runで見ること。**
