## 何が起きるか

```
施工開始
  ↓ 30分後（毎時のルーティン）
業務連絡グループLINEへ、この受注専用のURLが届く   ← tools/kanryo-okuru.py
  ↓ 和真さんが開く
画面1：お客様に見せる（アンケートのQR）
  ↓ お客様が回答している間に、次回のご予約をご提案
「次へ（スタッフ用）」
  ↓
画面2：作業完了フォーム（写真・終了時刻・施工内容・追加受注・クレーム…）
  ↓ 送信
毎時のルーティン                                  ← tools/kanryo-inbox.py
  ├─ 売上シートの金額・メニュー・備考を更新
  ├─ 写真を手元に落とす（SNSの素材）
  ├─ 実所要をためる（施工時間の精度を上げる資産）
  └─ クレーム・お客様のことを🔴で人に見せる
```

**アンケートの回収も、この1本で済みます。** 別途QRを出す必要はありません。

## ★受注の内容をどう渡しているか（ここが設計の肝）

お客様のお名前・メニュー・金額は、**URLの `#` のうしろ**に入れています。

```
https://oh-naibu-sms-k7q3x.netlify.app/kanryo/#eyJpIjogIi4uLiJ9
```

- **`#` のうしろはサーバへ送られません。** 社内ホストにお客様の情報が1件も残りません
- 置かないので、消し忘れも起きません
- 材料は `data/kanryo-yotei.json`（`tools/juchu-inbox.py` が作る）。**手元にだけ置きます**
- URLが無くても（直接 `/kanryo/` を開いても）使えます。その場合はお名前を手で入れます

## 決まった構成（オーナー原文・MTGシート G245）

> ▼使用時の流れ
> 施工開始時刻の30分後にマーケ部長が業務連絡グループLINEへ作業完了フォームを送信する。
> （→そのフォームのリンク先にアンケートフォームも格納する）
> →作業完了フォームの入力完了によりアンケート回収も済む導線を構築する
> ▼作業完了フォームの構成
> １．リンクを開くとトップ画面でお客様へのアンケート回答依頼画像が提示される
> １．５お客様がアンケート回答しながら施工担当者が次回予約を斡旋する
> ２．アンケート依頼画面下部に次へボタンを設置
> ３．作業完了フォーム本編
> ・施工写真添付欄（マーケ部長が即収集してSNS投稿へ反映させる）
> ・作業終了時刻（データを蓄積・集計して後から施工時間計算の正確化への資産とする。）
> ・施工内容（受注フォームの内容を自動表示して実際に施工した項目にチェックボックスチェックを入れる）
> 　表示＋追加受注欄（メニュー選択肢＋手入力欄｜追加受注がある場合は最終金額をマーケ部長が確認して
> 　売上シートへ反映させる※自動反映でもOK）
> ・クレーム有無→有の場合は内容をフリー入力
> ・アンケート回答依頼済み
> ・次回予約提案済み
> ・汚れのBeforeAfterをお客様に確認してもらったか？
> ・お客様周辺情報（犬飼ってる、小さいこともありなど）のメモ欄（マーケ部長が収集して顧客台帳へ転記する）
> ・現場で判断に迷ったこと（任意）

### どう作ったか

| 構成 | 実装 |
|---|---|
| 1 アンケート回答依頼 | 画面1。QRは https://survey.onehitter.jp/?src=kanryo を埋め込み（画像としてHTMLに同梱） |
| 1.5 回答中に次回予約を斡旋 | 画面1に留まる作り。次へを押すまでフォームは出ません |
| 2 次へボタン | 画面1の下部 |
| 施工写真 | **まとめて選べます。最大20枚**（もう一度選ぶと足されます・1枚ずつ消せます）。**選んだ瞬間にスマホの中で1600px・JPEG品質82%に縮小**。電波が悪くても送れます。20枚を超える現場は、残りをドライブへ手で上げてください（2026-09-19 オーナー指示） |
| 作業終了時刻 | 初期値は「開いた時刻」。開始からの実所要をその場で表示 |
| 施工内容 | 受注のメニューを**最初から全部チェック済み**で出し、やらなかったものを外す形 |
| 追加受注 | 売上種類に合わせた選択肢（ワンヒッター28件／本舗53件）＋数量＋手入力欄。金額は自動 |
| クレーム有無 | なし／あり。**ありを選ぶと内容が必須**になります |
| 3つの確認 | アンケート依頼済み／次回予約提案済み／Before After確認済み |
| お客様周辺情報 | 取り込み時に📗で出します。**顧客台帳への転記は人がやります** |
| 現場で迷ったこと | 取り込み時に💭で出します。仕組みで潰せないかを考える材料 |

## 売上シートを直すときの決まり

**受注フォームが作った行だけ**を直します（備考に「★受注フォームから自動で入りました」がある行）。
人が手で入れた行は触りません。**直す前の金額は必ず備考に残します。**

これは「過去の実績データを書き換えない」（CLAUDE.md）を、機械で守るための条件です。

### 写真を最大20枚にしたとき（2026-09-19）

オーナー指示（業務連絡グループLINE 18:01）で、1枚ずつの4枠から**まとめて選べる形**に変えました。

| 確かめたこと | 結果 |
|---|---|
| まとめて5枚 | 5枚入った |
| さらに3枚 | 8枚になった（置き換わらない） |
| 21枚目以降 | 20枚で止まり、「残りはドライブへ手でアップしてください」と赤で出た |
| 1枚消す | 消えて枚数が減った |
| 送信の中身 | `施工写真1`〜`施工写真20` として入った（20枚で本文222KB） |
| 縮小 | 1枚ずつ順に処理。「3/20 枚を準備しています」と進み具合が出る。20枚で3.5秒 |
| 写真0枚 | いままでどおりエラーで送れない |

`tools/kanryo-inbox.py` は `施工写真` で始まる欄を全部拾う作りのままです（20枚でも落とせることを確認。
番号の順に落ちるよう並べ替えだけ足しました）。
