# 【依頼】料金シミュレーターの割引ロジック修正

作成 2026-09-08 ／ **宛先：LP概要プレゼンのスレッド** ／ 依頼元：マーケ部長
オーナー指示（2026-09-08）にもとづく

---

## 何が起きているか

**パンフレットにあるセットメニューの割引が、一部の組み合わせで効いていません。**

オーナーが挙げた例。

> トイレと浴室＝シミュレーターで割引0だが、
> メニュー上は浴室セットが適用されて3,000円引き

再現しました。原因はこの行です。

```js
// lp/mizumawari/index.html ／ lp/nenmatsu/index.html
var order = chosen.slice().sort(function(a,b){
  return parseInt(b.dataset.single,10) - parseInt(a.dataset.single,10);
});
order.forEach(function(p, i){
  total += (i === 0) ? s : t;      // ← いちばん高い箇所を単品価格にしている
});
```

**「いちばん高い箇所を単品価格にする」のが誤りです。**

トイレ＋浴室の場合、浴室（18,480円）が高いので単品側に置かれます。
残ったトイレにはセット価格がないので、**割引が1円も出ません。**

| | 単品のまま残す箇所 | 計算 | 割引 |
|---|---|---|---|
| 現行 | 浴室（高いから） | 18,480 ＋ 10,780 | **0円** |
| 正しい | トイレ（セット価格が無いから） | **浴室セット15,180** ＋ 10,780 | **3,300円** |

## 正しいルール

出典：パンフレット（`【WEB掲載】パンフレット.pdf`）印字p10・p11、`data/prices.json`

### 1. 単品のまま残すのは「割引額がいちばん小さい1箇所」

2箇所以上を同時にご依頼いただいたとき、**1箇所だけは単品価格**、
**残りはセット価格**という考え方はそのままです。
変えるのは「どの箇所を単品側に残すか」だけです。

```
× いちばん高い箇所を単品にする
○ 割引額（単品価格 − セット価格）がいちばん小さい箇所を単品にする
```

セット価格を持たない箇所（洗濯機・トイレ）が選ばれていれば、その箇所が単品側に回り、
セット価格を持つ箇所の割引がきちんと出ます。

### 2. コンロは、キッチンと同時のときだけセット価格

パンフレットに明記されています。

> コンロクリーニング ￥9,800 ※**キッチンとセットの場合**￥5,500（印字p10）
> コンロセット ￥5,500 **原則キッチンとのセットオプション**となります（印字p11）

キッチンが選ばれていないとき、コンロは単品価格（10,780円）のままにしてください。

### 3. どの箇所にもセット価格が付かないときは、ネット申込特典 2,200円（税込）

2箇所以上を選んで、それでも割引が0円になる組み合わせがあります
（洗濯機＋トイレ、エアコン2台、コンロ＋トイレ など）。
このときだけ、**ページからのお申し込み特典として税込2,200円**を引いてください。

**1箇所だけのご注文は対象外です**（2026-09-08 オーナー決定）。
エアコン1台だけのご注文は 10,780円のままです。

## 参照実装

`lp/booking/index.html`（既存客向け予約フォーム）に、この3つのルールを実装済みです。
`tools/build-booking.py` の `kingaku()` がそのまま使えます。

```js
/* コンロのセット価格は、原則キッチンと同時のときだけ */
var kitchen = (state.qty['キッチンクリーニング'] || 0) > 0;
function setKakaku(m){
  return (m.n === 'コンロクリーニング' && !kitchen) ? m.t : m.d;
}

var tanpin = 0;
tan.forEach(function(m){ tanpin += m.t; });

var shoukei;
if (n === 1) {
  shoukei = tan[0].t;
} else {
  /* ★単品のまま残すのは「割引額がいちばん小さい1箇所」 */
  var narabi = tan.slice().sort(function(a, b){
    return (a.t - setKakaku(a)) - (b.t - setKakaku(b));
  });
  shoukei = narabi[0].t;
  for (var i = 1; i < narabi.length; i++) { shoukei += setKakaku(narabi[i]); }
}
var setBiki = tanpin - shoukei;

/* 2箇所以上で割引が0円のときだけ、ネット申込特典 */
var netto = (n >= 2 && setBiki === 0) ? 2200 : 0;
```

## 3. 予約フォームのデザインを揃えました

### なぜ揃えたのか（経緯）

オーナーから2度、見た目についてご指摘がありました。

1. **「リデザインの指示をしたのに見た目が変わっていない」**（2026-09-06）
   → 中身の組み替えしかしておらず、配色・書体・骨格を触っていなかった。
     ink／paper／rust の3色、明朝見出し、全幅バンドに作り直した
2. **「ハウスクリーニング会社として黒はどうなのか。清潔感が無い」**
   → 大手7社（本舗・革命・ベアーズ・ダスキン・カジタク・ユアマイスター・
     くらしのマーケット）のトップページを開き、computed style から実測。
     **7社中、黒を地に使っている社はゼロ。温かいクリームもゼロ。**
     地は白か寒色寄りの白で、清潔感は青が担い、CTAだけ彩度の高い暖色。
     これに合わせて **ink #0D3B5C ／ paper #F3F7F9 ／ CTA #C0300C** に変更

   → ダークテーマがOSの設定に追従していた。清潔感そのものが訴求である以上、
     端末の設定で暗転させる意味がないので、**全ページからダークテーマを外し
