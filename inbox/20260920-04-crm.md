**4年ぶん（2023〜2026）の台帳を全部当たって、実物を1名特定しました。**

| | |
|---|---|
| 行 | **9行目** |

対応は和真さんの判断待ちです（そのままにする／お詫びする）。

## 原因：`tools/build-sms-list.py` の除外が1つの列しか見ていない

```python
if keiro == '楽ラクーン':
    data.append(('除外', '楽ラクーン経由（フォロー連絡不可）', '', '')); continue
```

`keiro` は **顧客管理台帳の「主な流入経路」**です。これは**最も回数の多い経路**なので、
**楽ラクーンが1回でも、それ以外が2回以上あると別の値になります。**
大場さまは5回中1回が楽ラクーンで、残りがリピート → 「主な流入経路＝リピート」→ **除外をすり抜けました。**

同じ形の事故が9/11にもありました（送信系統の列を信じて本舗名義のお客様に自社名義で送った）。
**「集計後の1列を信じる」と落ちる、という同じ型です。**

## お願い（今日中）

**「1回でも楽ラクーン経由の施工があれば除外」に変えてください。**

判定材料は各年の月次タブ `◯月_売上/顧客` の **流入経路列**です。`derive-soushin-keitou.py` の `BOOKS` がそのまま使えます。
**⚠ 年によって列の位置が違います。ここを間違えると静かに0件になります。**

| 年 | 流入経路の列 | 氏名 | TEL |
|---|---|---|---|
| 2023 | **B列** | E列 | F列 |
| 2024・2025・2026 | **D列** | E列 | F列 |
| 2022 | **流入経路の列が存在しない**（見出しは No./日付/時刻/氏名/TEL/…） |

私は最初 2023 を D列で読んで**「0件」という誤った結果**を出しました。B列で読み直したら7名出ました。**同じ穴に落ちないでください。**

**2022年は判定不能です。**列が無いので、楽ラクーン経由だったかは**どの方法でも分かりません。**
これは「調べれば分かる」ではなく「データが存在しない」なので、**追わないと決めて、その旨をコードのコメントに残してください。**
