手順は docs/gbp-api-自動化の段取り.md の2節にあります。4点に答えます（値は書きません）。
1. OAuth クライアント：GCP プロジェクト one-hitter-sheets（番号 844550773178）の、既存の Gmail 用 OAuth クライアントを流用する形で作りました。道具（tools/gbp_client.py）は、オーナーのPCの ~/.config/one-hitter/gmail-oauth.json から client_id／client_secret を読みます。**どのクライアントIDかは、私の環境にそのファイルが無く確認できません**（同じプロジェクトの Gmail 用クライアントのはず）。「GBP投稿管理」という名前がその同意画面のアプリ名かは未確認です。
2. スコープ：business.manage の1つだけ（https://www.googleapis.com/auth/business.manage）。
3. refresh_token の取り方：tools/gbp-auth.py を、オーナーのPCで python3 tools/gbp-auth.py と実行します。ブラウザに出る同意画面で「許可」を1回押すと、refresh_token が ~/.config/one-hitter/gbp.json に保存されます。この道具は redirect に http://127.0.0.1:8765/（ループバック）を使うので、クライアントが「デスクトップ型」であるか、Web 型ならこの redirect URI を登録しておく必要があります。OAuth Playground を使う手もありますが、その場合は https://developers.google.com/oauthplayground を redirect URI に登録し、「独自の OAuth 認証情報を使う」にします。
 前に確認してほしい点（browser）：(a) GCP で My Business Account Management／Business Information／Business Profile Performance／My Business API（v4・投稿とクチコミ用）の4つが有効で、割り当てが0でないか。(b) OAuth 同意画面に business.manage を足し、case.foot.kid をテストユーザーに入れる。**状態が「テスト」だと refresh_token は7日で切れる**ので、公開にするか、週1で取り直す運用になります。
4. 置き場所：本体は Drive「ワンヒッター_認証情報（ここだけ）」でよいです。**加えて、環境のシークレットに GBP_CONF_JSON（client_id・client_secret・refresh_token）を入れてもらえると、作業環境が入れ替わっても動きます**。gbp_client.py は、この環境変数を読むように直して push しました（Meta の META_CONF_JSON と同じ形。{ } と " が外れた形でも読めます）。
取れたら cmo に一言いただければ、私が gbp_client.py check → locations → gbp-reviews.py（読むだけ）の順に確かめます。
