オーナー（2026-09-12 01:3x）：「HPブログの更新も進めていくべきだと思う」「HPのCMSはネット流入担当でも触れるのか」。
事実：あなたが 8/27 に TOP の料金表を **HTTP の POST（`_[action]=datastore`）で直接更新できた**ので、ブラウザ無しでも CMS のアーティクルは書ける。ブログも同じアーティクル（`/_sys/contents/article/561/…`）。最終更新は 2023-05（48本）で止まっている。

やること（公式サイトはあなたの持ち物なので、道具もあなたが持つ）：
1. ブログのアーティクル群（ID 561 と思われる）の**フィールド構造**を管理画面の HTML から確認（タイトル・本文 Jodit・アイキャッチ・カテゴリ・公開日時・display）。画像のアップロード先（メディア API か Jodit のアップロード）も
2. `tools/cms-blog-post.py` を作る：ログイン（CMS の ID/PW は認証情報ドキュメント第5節を Drive MCP で読み、`~/.config/one-hitter/cms.json` に置く。git に入れない）→ 画像アップロード → 記事作成。**必ず `display=0`（非公開）で作成し、プレビューURLを返す**。公開は `--publish <記事ID>` で display=1 にする別コマンド。誤爆で即公開しないための2段階
3. 入力は Markdown 1本（front matter：title / date / category / eyecatch / ogp説明）。web-inflow がこの形式で原稿を出す。変換は Markdown→HTML（h2/h3、画像、引用、出典リスト）。CSS は既存ブログの見た目に合わせる（新しいクラスを増やさない）
4. テスト：非公開で1本作成 → プレビューURLを cmo に → 問題なければ削除か非公開のまま
5. 既存の48本のうち、料金や電話番号（旧 080-1755-7275）が載っているものを一覧にして cmo に（古い価格が検索に出ている可能性）
6. できたら `docs/公式サイト-ブログ運用.md` に「原稿→査読→非公開作成→公開」の流れと戻し方を書く

注意：CMS の「ページ編集セッション」（下書き機構）は使わない（未公開セッションの件）。アーティクルの datastore だけ。ページビルダーが要る操作（プライバシーポリシー）はブラウザ担当。
