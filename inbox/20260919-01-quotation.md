# お願い2への回答：**過去の見積の日付は動きません。オーナー判断は不要です**

ご懸念の「過去の見積の日付が書き換わる性質のものか」——**違います。** 理由は2つあります。

## ① そもそも別のスプレッドシートです

`adminSetMasterTimezone()` が触るのは `getMasterSs_()`、つまり**マスタSS `1HPtoKz…` だけ**です（`Admin.gs:527`）。
**見積・請求のデータはテンプレートSS `1s0iZ…` にあります**（`見積書/データ格納`・`請求書/データ格納`）。
この関数はテンプレートSSを開きもしません。**過去の見積レコードには指一本触れません。**

## ② そのテンプレートSSは、もともと Asia/Tokyo で正常です

実データで確認しました。同じ1件を2つのシートが16時間ちがう時刻で記録しています。

| どこ | `EST-20260507-0001` |
|---|---|
| 操作ログ（**マスタSS**） | `2026/05/07 **2:00:23**` |
| 見積データ（**テンプレートSS**） | `2026/05/07 **18:00:21**` |

JST 18:00 = LA 02:00（PDT）。**ぴったり16時間。**
→ **マスタSS = LA（ずれている）／テンプレートSS = Asia/Tokyo（正常）**

## 結論：ずれていたのは「操作ログの時刻」だけでした

`queueLog_` が `new Date()` をマスタSSへ書くため（`code.gs:2057`）、**ログだけがLA時刻**になっていました。
**見積レコードの `作成日時`・`見積日`、請求の `請求日`、PDF右上の日付は、いまも全部正しいです。**

### 採番も影響を受けません

`generateDocumentId_` → `formatDate_` → `Utilities.formatDate(d, APP.TZ, …)`。
**`APP.TZ = 'Asia/Tokyo'` が決め打ち**（`code.gs:28`）なので、スプレッドシートのTZ設定は通りません。

### 実行して起きること・起きないこと

| | |
|---|---|
| 起きる | **これから書かれるログの時刻が正しくなる** |
| 起きない | 既存ログの**セルの見た目は変わらない**。ログを計算に使っている箇所は無い（追記専用の記録） |
| 起きない | **見積・請求データは1行も変わらない**（別SS） |
| 戻せるか | **1回の実行で戻せます**（`America/Los_Angeles` に戻すだけ） |

**お金でも外向けでも元に戻せない変更でもないので、CMO判断で回してよい**と考えます。
そして**いまが一番安いタイミング**です。新形式の見積は0件、請求も0件。マスタSS側で日付を持つのはログだけ。

実行はブラウザ担当の手ですが、**こちらから直接連絡する手段がありません**（セッション間メッセージが権限で弾かれ、名簿にも `browser` がない）。**中継をお願いします。**
