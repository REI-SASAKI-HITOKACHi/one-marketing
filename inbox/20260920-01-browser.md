# 🚨 4. いちばん大事：**設計の3つが1つも登録されていません**

あなたの実測どおり、キーイベントは `form_complete` `purchase` `teltap` の**3つだけ**でした。

**`generate_lead` `phone_click` `line_click` が入っていません。**

> **広告のコンバージョンは落ちていません。**
> Google広告へはLPから直接撃っており（`AW-18450975194`）、**GA4のキーイベントを経由しません。**
> **壊れているのはGA4のレポートだけ**です。ただし週次の数字が読めません。

## 設定してもらえますか（画面から。5分）

**[管理] → [データの表示] → [イベント]** で、次の3つの**星をオンに**してください。

| イベント名 | 何か |
|---|---|
| `generate_lead` | **申込**（LPのサンクスページ・予約フォームの完了画面） |
| `phone_click` | 電話タップ |
| `line_click` | LINEタップ |

**一覧に出ていなければ、まだそのイベントが届いていないということです。**
その場合は「**イベントを作成**」ではなく、**届くのを待ってから**星を付けてください
（LPは配信済みなので、クリックが発生すれば出てきます）。

### ⛔ 順番を守ってください

```
1. purchase の90日0件を確認   ← 消す前に
2. 設計の3つを登録             ← ★ここが本丸
3. purchase を外す             ← 2のあと
4. form_complete と teltap は そのまま（消さない）
```

**2を先にやってください。** 先に `purchase` を外すと、その間キーイベントが実質2つ（公式サイトぶんだけ）になります。

### ⛔ 星を付けてはいけないもの

| | 理由 |
|---|---|
| `form_submit` `booking_submit` | **送信ボタンを押した時点。`generate_lead` と二重に数えます** |
| `survey_complete` | **アンケートの回答は広告の成果ではありません。** 入札が歪みます |
| `click` | **公式サイトの電話リンクは1回のタップで `click` と `teltap` の2つを撃ちます。** 両方キーイベントにすると1タップが2件になります |
| `refer_share` | アンケートの「友だちに紹介文を送る」。既存のお客様なので成果ではありません |

**いまはどれも登録されていないので、このままで正しいです。**

# 5. アンケートの欠損（9/05〜9/19）… **こちらが最優先です**

**Data API が有効化済みとのこと、助かります。**

**アンケートの回答が2週間1件も保存されていなかった件**（LP担当が発見）で、
**失った件数を出す依頼がCMOから来ています。** 打ち手がそれで変わります
（1〜2件なら和真さんが現場を覚えている可能性があり、もう一度お願いできる。10件以上なら諦める）。

```
python3 tools/ga4-event-shirabe.py --event survey_complete --start 2026-09-05 --end 2026-09-19 --daily
python3 tools/ga4-event-shirabe.py --event survey_start    --start 2026-09-05 --end 2026-09-19 --daily
python3 tools/ga4-event-shirabe.py --event survey_complete --days 90 --daily
```

**3つ目は「壊れる前の水準」を見るためです。** 「2週間で本来何件あったはずか」が推測でなく出ます。
**ホスト2つ（`lp.onehitter.jp/survey/` と `survey.onehitter.jp`）は自動で合算され、
「合計 N 件」が先頭に出ます。** そのまま貼れます。

**GA4の読み取りはCMOが持つことになっています**（9/19 決定）。
**そちらと重複しないよう、誰が走らせるかだけCMOと合わせてください。**
