**入金の確認に2〜4週間かかります。** 週1だと**毎週ほとんどの行が「まだ入金前」で弾かれ、
同じ行を何度も見ることになります。**

> **ただし90日を空けてはいけません。**
> **クリックから90日を過ぎた成約は、Google広告が受け取りません。**
> **月1なら、いちばん遅い行でも最大60日で戻せます。2か月飛ばすと取りこぼします。**
> 道具が**90日超の行を注文IDと金額つきで警告**します。**出たら運用が滞っている合図です。**

### なぜ施工日か（入金日ではなく）

**入金日だと、支払い方法の違いがそのまま日付の差になります。**
現金は当日、振込は数日後、カードはもっと後。**広告の良し悪しと関係のない差です。**

### ⛔ いちばん大事：**「申込」と同じコンバージョンアクションに入れない**

**同じ申込が2回数えられます。** サンクスページで1回、受注が決まってもう1回。
**CPAが実際の半分に見えて、入札が暴走します。**

**「受注（オフライン）」を新設し、最初はサブアクションにしてください。**
件数が少ないうちに主にすると、**自動入札が数件の受注に引きずられます。**
**30件くらい貯まってから、主CVを「申込」から切り替える**のが順当です。

# 🐛 `form_submit 4` / `generate_lead 2` の切り分け

## まず：**9/15 のテストで説明がつきます**

**9/15 はレントラックスのテスト申込をした日です。**

| | |
|---|---|
| 11:14 | PC でテスト申込（`OH-20260915-mizumawari-MY83`） |
| 11:15〜11:16 | スマホでテスト申込（`OH-20260915-mizumawari-SCH4`） |

**成果2件・Netlify Forms の受信2件・`generate_lead` 2件。ここは全部そろっています。**

**残る `form_submit` の2件が、二度押しです。**

**`form_submit` は送信ボタンを押した瞬間、`generate_lead` はサンクスページが開いた瞬間です。**
**二度押しすると `form_submit` は2回出ますが、ブラウザが実際に進むのは1回だけ**なので、
**サンクスページも Netlify の受信も1件のまま**です。

```
PC   ：押す・押す → form_submit ×2 → 送信1件 → generate_lead 1
スマホ：押す・押す → form_submit ×2 → 送信1件 → generate_lead 1
────────────────────────────────────────
合計         form_submit 4 ／ generate_lead 2 ／ Netlify 2
```

**数字がぴたりと合います。送信が落ちたのではありません。**

> **確かめ方**：GA4 の `client_id` 別に並べると、**同じ人が数秒以内に2回**押しているはずです。
> **別々の人が1回ずつなら、二度押しではありません。** そのときは改めて調べます。

## ⚠️ ただし、そこで**本物の不具合**が見つかりました。直しました

**注文IDが、送信を押すたびに作り直されていました。**

```
1回目を押す → ID1 を作る → 隠し欄=ID1、sessionStorage=ID1 →【送信が出ていく】
2回目を押す → ID2 を作る → 隠し欄=ID2、sessionStorage=ID2 ← 上書き
```

| | 残るID |
|---|---|
| Netlify Forms の受信内容 | **ID1**（1回目の送信が持っていったもの） |
| サンクスページが読む sessionStorage | **ID2** |

**サンクスページのアフィリエイトタグは sessionStorage を読みます。**
**つまり、当社の受信記録に存在しないIDを、レントラックスへ送ることになります。**

**影響は2つです。**

1. **アフィリエイトの成果の備考が、当社の記録と一致しなくなる**
   → **承認・却下の判断ができません**（9/15 は一致したので、このときは二度押しの順序で助かった形です）
2. **オフラインインポートの突き合わせ鍵（`order_id`）が合わなくなる**
   → **いま作っている運用が、そこで壊れます**

**1ページにつき1つだけ作るように直しました。**
**テストに「3回押してもIDが変わらない」「隠し欄と sessionStorage が同じID」を足しました。**

```
PASS 二度押ししても注文IDが変わらない
PASS 隠し欄と sessionStorage が同じID
```

> **本番への反映はLP担当の配信待ちです。**
