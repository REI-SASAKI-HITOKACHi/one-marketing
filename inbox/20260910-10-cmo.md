## ② 予約フォームは「予約数」は測れるが「反応率」が測れない

SMS配信（9/10開始・473名）の効果測定について調べました。

**測れているもの（良い設計です）**

`https://one-hitter-booking.netlify.app/?src=sms` の `src` は、送信時に
**「流入元」という欄でNetlify Formsに記録**されています。概算金額・希望日時も一緒に入ります。
つまり**「SMS経由で何件予約が入ったか」は分かります。**

**測れていないもの**

| | 状態 |
|---|---|
| 何人がリンクを開いたか | **分からない**（GA4も計測タグも入っていません） |
| どの画面で離脱したか | 分からない |
| `cid`（誰宛てのSMSか） | **記録されていません**（`src` だけ拾う作りです） |

**反応率 ＝ 予約数 ÷ 開いた人数**。分母が無いので、いま出せるのは予約の実数だけです。
473名に送って40件送信済みという段階なら、**残りを送る前に分母を取れるようにしたほうが得です。**
「開いたけど予約しなかった人が何人いるか」が、次の文面を直す材料になります。

## こちらでできること（指示をください）

`tools/inject-tracking.py` という、**完結したHTML1枚に計測を差し込む道具**を作ってあります。
予約フォームにも同じ仕組みが使えます（アンケートで実証済み）。

```
python3 tools/inject-tracking.py <予約フォームのHTML> --kind booking --id booking
```

ただし**予約フォームはCMOの持ち物**なので、勝手に触りません。次のどれにしますか。

| | やり方 | 手間 |
|---|---|---|
| A（推奨） | ソースの場所を教えてもらい、**差し込む変更だけ作って渡す**。配信はそちら | こちら30分 |
| B | 手順だけ渡して、そちらで実行 | こちら10分・そちら10分 |
| C | GA4の測定IDが来るまで保留 | 0 |

**AでもBでも、GA4の測定IDが無いとタグは何も送信しません。**
なので、いずれにせよ別途出した依頼（`20260910-08-cmo`）の①が先に要ります。

`cid` を拾うかどうかは、**SMSのリンクに `cid` を付けているかどうか次第**です。
付けているなら、記録するよう直す価値があります（誰が予約したかを台帳と突き合わせられます）。
付けていないなら、そのままで構いません。**どちらか教えてください。**
