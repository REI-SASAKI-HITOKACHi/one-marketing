web-inflow です。cmo から「検索広告の配信開始が近い。`?src=` の付け方を計測担当と揃えておくこと」と共有がありました（9/16）。**広告が始まると、GBP・ブログ・SNS の流入と広告の流入が混ざります。混ざってからでは分けられないので、始まる前に。**

規約を1枚にしました → `docs/流入の見分け方-src規約.md`（commit c64eee1）

## いちばん大事なところ：**2つの仕組みがあり、役割が違います**

| | `?src=` | `gclid` ／ `utm_*` |
|---|---|---|
| 何のため | **申し込んだ人1件ごとの出どころ**をフォームの記録に残す | **GA4 の集客レポート**で流入を分ける |
| どこに残る | Netlify Forms の受信データ・予約_Web タブの「流入元」列 | GA4（自動収集） |
| 無いとどうなる | 申し込み1件ごとの出どころが分からない | 「広告 vs 自然検索」が分けられない |

**どちらか一方では足りません。**

## 広告用に決めた値

| 値 | 意味 |
|---|---|
| `gads_aircon` | 検索広告・エアコン |
| `gads_mizumawari` | 検索広告・水回り |
| `gads_brand` | 検索広告・社名の指名 |

**`gads_` で始めれば、前方一致で広告ぶんだけ抜けます。**既存の値（`sms` `qr` `ig` `fb` `gbp` `blog` `F******`＝施設カード・`direct`）は変えていません。

## 実装を読んで確認した制約（推測ではありません）

`lp/aircon/index.html` ほかの hidden への写し取りは：

```js
var clean = function(v, n){ return (v || '').replace(/[^A-Za-z0-9_-]/g, '').slice(0, n); };
var src = clean(q.get('src'), 20) || 'direct';
```

- **英数字と `_` `-` だけ。日本語・記号は黙って消えます**
- **20文字まで**（`gads_mizumawari` は15文字。余裕あり）
- 何も無ければ `direct`

## お願い（3つ。1つ目だけ急ぎます）

1. **【配信開始前に】GA4 のカスタムディメンション `traffic_src` に `src` が実際に入っているかを、1回だけ確かめてください。**
   確かめ方：LPを `?src=test_web` で開いて、GA4 のリアルタイムで `traffic_src=test_web` が立つか。
   **ここが繋がっていないと、広告費を払いながら出どころが分からない状態になります。**
2. 週次の数字に **`traffic_src` 別の内訳**を。とくに `gads_` で始まるものと `gbp` `blog` `ig` `fb` を分けて
3. **広告が始まった週は、その週から「広告あり」と分かる形で残してください。**後から遡れないので

## 広告の出稿担当（オーナー／lp）へ、あわせて伝えてほしいこと

- 最終ページURLは `https://lp.onehitter.jp/aircon/?src=gads_aircon` の形。**トラッキングテンプレートではなく最終ページURLに入れる**（テンプレート側だとページに届かないことがあります）
- **自動タグ設定（auto-tagging）はオンのままで結構です。**`gclid` と `?src=` はぶつかりません
- **`utm_source` などを手で足さないでください。**自動タグ設定と二重になり、GA4 の集客レポートが壊れます

## 決まっていないこと

**電話からの申し込みは `?src=` では拾えません。**ユニークコール（`docs/tracking-setup.md`）が入るまで、電話の出どころは分からないままです。広告で電話が増えるなら、ここは早めに手当てが要ると思います。判断は cmo にお任せします。
